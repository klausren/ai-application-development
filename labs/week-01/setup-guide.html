1Install Miniconda

First, find out which chip you have — this decides which installer to download:

# macOS / Linux: run in Terminal
uname -m
#   arm64 / aarch64  ->  ARM build
#   x86_64           ->  Intel build

# Windows: Settings -> System -> About -> "Processor",
# or run in PowerShell:
echo $env:PROCESSOR_ARCHITECTURE
#   ARM64 -> ARM build ;  AMD64 -> Intel build

Then download the Python 3.11 Miniconda installer for your OS and chip from anaconda.com/download (pick Miniconda, the small one, ~80 MB — not the full Anaconda).

WINDOWS

  1. Run the .exe. Accept defaults, and check "Add Miniconda3 to my PATH" if offered.
  2. From now on, use Anaconda Prompt (search it in the Start menu) — not the plain cmd or PowerShell.
  3. If PowerShell refuses to run conda: open Anaconda Prompt and run conda init powershell, then in PowerShell (as your own user, no admin needed): 
    Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
    Type Y and press Enter. Close and reopen PowerShell.

MACOS

  1. Run the .pkg that matches your chip: arm64 for M1/M2/M3/M4/M5, x86_64 for Intel.
  2. Open Terminal and run conda init zsh, then close and reopen Terminal.
🍎 Apple Silicon trap: installing the x86_64 build on an M-series Mac "works" but runs through Rosetta — torch will be slow, and some packages will not install at all. If uname -m says arm64, you need the arm64 installer. Check with python -c "import platform; print(platform.machine())" — it must print arm64, not x86_64.

LINUX

bash Miniconda3-latest-Linux-x86_64.sh   # or aarch64.sh on ARM
conda init bash
# close and reopen your terminal

Verify — in a new terminal window:

conda --version
# expect: conda 24.x.x or newer
📌 One extra step that everybody now needs (added 2026-09): recent conda versions refuse to install anything until you accept Anaconda's commercial Terms of Service for the built-in defaults channel. The clean way out is to use conda-forge only — it is community-run, free for everyone, and needs no licence: 
conda config --add channels conda-forge
conda config --set channel_priority strict
Adding the channel to .condarc alone is not enough — the fallback to defaults is hard-wired. Every conda create in this course must therefore carry the override flag, as shown in Section 2.

2Create the course environment

Run these in Anaconda Prompt (Windows) or Terminal (macOS/Linux), one block at a time:

# 1. create an isolated environment named "ai-app"
conda create -n ai-app python=3.11 -c conda-forge --override-channels -y

# 2. activate it — DO THIS EVERY SINGLE LAB SESSION
conda activate ai-app

# 3. confirm you are inside it (the prompt should start with "(ai-app)")
python -c "import sys; print(sys.executable)"
#   the path must contain ".../envs/ai-app/..."

# 4. install the Week 1 toolkit from the provided file
pip install -r requirements.txt

Everything is pinned in requirements.txt (shipped in this folder), so you do not have to type package names. If you prefer installing by hand:

pip install numpy pandas matplotlib seaborn scikit-learn torch jupyterlab
🐢 Slow or timing out? Use a mirror. In China this is often 10–50× faster: 
pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
Other mirrors: Aliyun https://mirrors.aliyun.com/pypi/simple/, Tencent https://mirrors.cloud.tencent.com/pypi/simple.
💾 Low disk space, or torch download keeps failing? Install the CPU-only build (~200 MB instead of 2+ GB). It is enough for every lab in this course: 
pip install torch --index-url https://download.pytorch.org/whl/cpu

3Set up VS Code

  1. Install VS Code from code.visualstudio.com.
  2. Open it → Extensions (Ctrl/Cmd + Shift + X) → install Python and Jupyter (both by Microsoft). Recommended extra: GitLens.
  3. Open your lab folder: File → Open Folder → select the labs/week-01 folder you cloned.
  4. Open starter-notebook.ipynb. If asked "Do you trust the authors of this folder?" → Yes.
  5. The critical step: click the kernel selector in the top-right corner → Select Kernel → Python Environments → ai-app (Python 3.11).
🔥 The #1 Week-1 mistake: the wrong kernel. A ModuleNotFoundError almost never means the package is missing — it means the notebook is running a different Python. Look at the top-right corner before you reinstall anything. Reinstalling into the wrong environment fixes nothing and wastes 20 minutes.
🪟 Windows only: if typing python opens the Microsoft Store, disable it — Settings → Apps → Advanced app settings → App execution aliases → turn off both python.exe and python3.exe. Always use Anaconda Prompt.

4Git & GitHub

  1. Create a GitHub account using a professional username — it ends up on your CV: github.com/signup
  2. Install Git: git-scm.com/downloads (macOS: xcode-select --install also works)
  3. Verify: git --version

Tell Git who you are (required — do this once)

Every commit is signed with a name and email. Skip this and your first commit fails with *** Please tell me who you are:

git config --global user.name  "Your Name"
git config --global user.email "you@university.edu"   # use the SAME email as your GitHub account
git config --global init.defaultBranch main

# confirm:
git config --global --list
🔑 Using the same email as your GitHub account is what makes your commits show up with your avatar and count toward your profile — worth the 30 seconds.

Set up authentication (required to push)

GitHub no longer accepts your account password in the terminal. Two options — pick one:

  • Easiest: install GitHub Desktop and sign in. It handles credentials for you.
  • Or create a Personal Access Token: GitHub → Settings → Developer settings → Personal access tokens → Tokens (classic) → Generate new token → tick repo → copy it once (you will not see it again). Paste it as the password when Git asks.

Windows users should also run this once to avoid "filename too long" errors:

git config --global core.longpaths true

New to Git entirely? Free reading, chapters 1–3 only: Pro Git (free e-book). The push commands themselves are in the lab notebook.

5Verify everything (do not skip)

Inside your activated ai-app environment, from the labs/week-01 folder:

python env-check.py

You should see a wall of [ OK ] lines and finish with:

ALL CHECKS PASSED - see you in the lab!
⚠️ The filename uses a hyphen: env-check.py. Older drafts of this guide said env_check.py (underscore) — if you get can't open file 'env_check.py', you typed the old name.
✅ Any [FAIL] line means: check the FAQ first, then ask. The script also trains a tiny model as a smoke test, so a pass means your whole stack genuinely works.

6Two-minute daily routine

Every lab session, from now on:

conda activate ai-app        # 1. activate — nothing works without this
cd path/to/course/labs/week-XX
jupyter lab                  # or open the .ipynb in VS Code

And in VS Code: glance at the top-right corner to confirm the kernel says ai-app.

7Fallback — Google Colab (zero install)

No laptop, or the install is broken and the lab is in an hour? Colab runs notebooks in your browser with a free GPU:

  1. Go to colab.research.google.com (needs a Google account)
  2. File → Upload notebook → choose starter-notebook.ipynb
  3. Runtime → Change runtime type → T4 GPU → Save
  4. torch and scikit-learn are pre-installed; everything except the Git parts works out of the box
⚠️ Colab is a backup, not the main workflow. Free tier has daily limits, sessions disconnect after ~90 minutes idle, and files vanish when the VM is recycled — always save your work to GitHub before closing the tab. Later labs (Week 13+: FastAPI servers, Docker) require a real local setup.

8FAQ — common errors & fixes

SymptomFix
conda: command not found Windows: use Anaconda Prompt, not cmd. macOS: conda init zsh then reopen Terminal. Or reinstall with "Add to PATH" ticked.
can't open file 'env_check.py' Filename is env-check.py (hyphen). Or you are in the wrong folder — cd into labs/week-01 first.
ModuleNotFoundError: No module named 'torch' 99% a wrong kernel or a forgotten conda activate ai-app — check the VS Code top-right and your prompt prefix before reinstalling.
pip install very slow / times out Add a mirror: -i https://pypi.tuna.tsinghua.edu.cn/simple. In China this is dramatically faster.
torch download is 2 GB / keeps failing CPU-only build (~200 MB): pip install torch --index-url https://download.pytorch.org/whl/cpu
CondaToSNonInteractiveError — Terms of Service not accepted conda fell back to Anaconda's commercial defaults channel. Re-run with -c conda-forge --override-channels (see Section 2), or run conda tos accept --override-channels --channel https://repo.anaconda.com/pkgs/main if you accept Anaconda's commercial terms.
CondaHTTPError / SSL errors during conda create Usually a campus proxy or VPN. Try a phone hotspot, or configure the Tsinghua conda mirror and retry.
macOS: torch is installed but very slow / no MPS You likely installed the x86_64 Miniconda on an M-series Mac. Check python -c "import platform; print(platform.machine())"; if it prints x86_64, reinstall with the arm64 build.
PowerShell: "running scripts is disabled" Run conda init powershell, then Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser, then reopen. Or just use Anaconda Prompt.
Windows: typing python opens the Store Turn off App execution aliases for python.exe / python3.exe, and use Anaconda Prompt.
git push rejects the password GitHub no longer accepts account passwords. Use a Personal Access Token as the password, or install GitHub Desktop.
*** Please tell me who you are Set your identity: git config --global user.name "..." and git config --global user.email "..."
Windows: Filename too long git config --global core.longpaths true, then clone again.
Notebook errors that make no sense You ran cells out of order. Kernel → Restart & Run All. This is also exactly how submissions are graded, so test it before submitting.
Colab: cannot connect / no GPU Region restriction or quota. Use the local setup, or retry off-peak.
📌 Still stuck? Post in the class group with all three of: (1) your OS and chip, (2) the exact command you ran, (3) the full error — a screenshot of the whole terminal, not just the last line. "It doesn't work" gets a slow answer; a complete bug report gets a fast one. Writing good bug reports is a professional skill you will use for the rest of your career.

9Pre-lab checklist — finish before class

  • conda --version prints a version number
  • conda activate ai-app works and my prompt starts with (ai-app)
  • pip install -r requirements.txt completed with no red errors
  • python env-check.py prints ALL CHECKS PASSED
  • VS Code opens starter-notebook.ipynb and the top-right kernel says ai-app
  • git --version works, and git config --global user.name returns my name
  • I can log in to GitHub in a browser and I have chosen my push method (Desktop or token)
  • I ran the notebook top-to-bottom once (Restart & Run All) and it finished without errors

Bring your laptop charged, with the charger. Bring the one error message you could not solve — that is what the lab session is for.

10中文摘要 · 安装流程速查

面向中文使用者与助教的精简版，详细英文说明见上文各节。

步骤操作
① 装 Miniconda先 uname -m 确认芯片（arm64 装 ARM 版，x86_64 装 Intel 版），再到 anaconda.com/download 下载 Python 3.11 的 Miniconda（约 80MB，不要装完整版 Anaconda）。Windows 全程用 Anaconda Prompt，不要用 cmd。
② 建环境conda create -n ai-app python=3.11 -c conda-forge --override-channels -y（必须带 override 参数，否则会撞 Anaconda 商业条款报错）→ conda activate ai-app（每次上机都要激活）→ pip install -r requirements.txt
③ 提速（国内必看）pip 加镜像：-i https://pypi.tuna.tsinghua.edu.cn/simple；torch 太大就装 CPU 版：--index-url https://download.pytorch.org/whl/cpu
④ 装 VS Code装 Python + Jupyter 两个扩展；打开 notebook 后务必在右上角把 kernel 切成 ai-app —— 90% 的报错都是这里选错
⑤ 配 Gitgit config --global user.name "你的名字"、user.email "邮箱"（与 GitHub 账号一致）。推送不用密码，改用 Personal Access Token 或装 GitHub Desktop
⑥ 自检python env-check.py（连字符，不是下划线）→ 全部 [ OK ] 并输出 ALL CHECKS PASSED 才算通过
⑦ 兜底方案装不上就用 Google Colab 上传 notebook，选 T4 GPU；但 Colab 只是备份，第 13 周起必须本地环境
🍎 Apple Silicon 重点提醒：M 系列 Mac 装错 x86_64 版本会走 Rosetta，torch 变慢且部分包装不上。用 python -c "import platform; print(platform.machine())" 验证，必须是 arm64。
