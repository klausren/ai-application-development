序列模型与文本数据处理

第 7 章选了一个架构，并算清了它的代价。这一章讲的是任何文本模型底下那套管线，以及藏在管手里的一个 bug——它几乎从不声张。任务小到可以拿在手里：给一段英文段落，判断它出自本课程的第几周（6 分类）。语料是本课程自有的第 1–6 周材料，748 段，在 262 处清掉了周次标识，使任务不是一眼可解，全程零下载、零第三方许可。本周的主线不是“这个 LSTM 得分高”——它并不高。主线是：一行决定 (B, T, 96) 张量如何压成 (B, 96) 向量的代码，把结果从 0.2407 拉到 0.5027，差距 0.2620，而其余一切保持不变。沿途本章量化了掩码的价值（+11.0 个点），说明最差那一臂的宏 F1（0.0711）为何低于 1/6 的随机基线，并得出本周最诚实的结论：当训练段只有 523 个时，真正的瓶颈是数据，于是第 6 周有效的正则化，在这里反而把成绩从 0.5027 拉低到 0.4672。同一种手段，相反的答案，因为瓶颈换了。

8.1 从文本到张量：完整链路

nn.Embedding 是一张以整数为下标的查表。循环层在第 t 步消费一个整数，并从这张表里读出一行。两者都放不下 Python 字符串，也都没有“词”这个概念。正是这一条事实，决定了任何文本任务——无论上面叠的模型多精巧——都要先走一遍同样的四步转换，也决定了四步里任何一步出错，都要等结果出来才发现。

8.1.1 为什么模型只认整数

两层定义了这份契约。nn.Embedding(V, D) 存一个 (V, D) 形状的矩阵，给定一个整数下标张量，返回对应的行。nn.LSTM(input_size, hidden_size) 接收 (B, T, input_size) 形状的浮点张量，在 T 轴上逐步推进。所以整数不是分词器的一个细节，它是索引到一张可学习表的钥匙，而一个“词”的含义，完全在训练最终写进那一行的数值里。改变从 token 到整数的映射，就改变了哪一行学到哪个词。这就是为什么词表必须在训练开始前建好并冻结，也是为什么“用错了数据建词表”不是无关痛痒的小错。

8.1.2 四步链路，以及每一步最典型的错误

分词（tokenisation）

把一个字符串切成 token 列表。英文：小写后用正则切分；中文：这一步会让一个朴素实现悄悄毁掉输入（见 8.2 节）。典型错误：对中文按空白切分，结果是每句一个 token，得到一个永不迁移的词表。

词表（vocabulary）

给每个 token 分配稳定的整数 id，保留 0 给填充、1 给未知词。典型错误：在全量语料上统计词频，而不是只在训练集上——这就是数据泄漏，报出来的 OOV 率随之变成一句空话（见 8.3 节）。

编码（encoding）

把每个 token 换成它的 id，没见过的映射到 <unk>=1。典型错误：忘了未知词分支，于是一个词表外的词让整批崩掉——或者更糟，让一个空文档产生一个空张量。

填充与掩码（padding & masking）

给每个文档追加 <pad>=0，让一批长度一致，同时把真实长度带上，好让模型忽略填充。典型错误：把填充当成内容来读。这正是本章后文的那个 bug（见 8.4、8.5 节）。

8.1.3 分词与建词表，写成代码

下面两个函数就是英文那半条管线的全部。它们被写成让真正要紧的那个决定——词表到底在哪些文档上统计——是一个看得见的参数，而不是一个埋在默认值里的隐患。

import re
import torch

# token 以字母开头，后续是字母、撇号或连字符，于是 "don't" 与
# "state-of-the-art" 各是一个 token。
WORD = re.compile(r"[a-z][a-z'-]*")


def tokenise(text):
    """小写，然后只保留以字母开头的 token。"""
    return WORD.findall(text.lower())


def build_vocab(train_docs, min_freq=2, max_vocab=6000):
    """只在训练集上统计 token。

    在全量语料上统计就是数据泄漏：测试集的稀有词会提前出现在词表里，报告里
    引用的 OOV 率被低估，而准确率是在一个比部署时更简单的任务上测出来的。
    """
    freq = {}
    for doc in train_docs:
        for t in tokenise(doc):
            freq[t] = freq.get(t, 0) + 1
    kept = [t for t, c in freq.items() if c >= min_freq]   # 丢掉低频词
    kept.sort(key=lambda t: (-freq[t], t))          # 高频在前，同频按字母序
    kept = kept[:max_vocab - 2]                          # 给 0 和 1 留位
    return {t: i + 2 for i, t in enumerate(kept)}          # <pad>=0, <unk>=1


def encode(doc, vocab, max_len):
    ids = [vocab.get(t, 1) for t in tokenise(doc)]   # 未见词 -> <unk>=1
    ids = ids[:max_len]                                 # 超长文档截断
    return ids or [1]                                  # 绝不返回空列表
泄漏只是一个词的改动，所以它反复发生 把 train_docs 换成 all_docs，代码照样跑，模型照样训，而且准确率往往更高。没有崩溃，没有任何警告。词表只是提前被告知了一批它要到测试时才会遇到的词，于是你测到的 OOV 率低于你实际会遇到的 OOV 率。本章会在 8.9 节带着一个实测数字回到这个陷阱，因为那个“修复”看起来像一次退步。

8.1.4 填充与掩码，写成代码

填充让一批变成长方形，而长度向量才是阻止填充被当成内容的那个东西。掩码均值是本章最优那一臂用的归约，它的正确性完全落在两行上：掩码在哪一步进入求和，除数选的是谁。

def pad_batch(docs, vocab, max_len):
    """右侧补 <pad>=0，返回 (ids, lengths)。

    `lengths` 不是装饰品。它是让模型分辨真实 token 与填充 token 的唯一依据，
    也是 pack_padded_sequence 需要的输入。
    """
    enc = [encode(d, vocab, max_len) for d in docs]
    lengths = torch.tensor([len(e) for e in enc])
    T = int(lengths.max())            # 这一批的宽度，不是全局的 max_len
    x = torch.zeros(len(enc), T, dtype=torch.long)
    for i, e in enumerate(enc):
        x[i, :len(e)] = torch.tensor(e)
    return x, lengths


def masked_mean(out, x):
    """只在真实时间步上求均值。

    out: (B, T, H) 隐状态   x: (B, T) token id，填充处为 0。
    掩码必须在求和之前乘进去，除数必须是真实步数而不是 T。两半都要对；只对一半就是错的。
    """
    mask = (x != 0).unsqueeze(-1).float()                # (B, T, 1)，1 = 真实 token
    return (out * mask).sum(1) / mask.sum(1).clamp(min=1)     # (B, H)
冻结的协议，精确复述 本章后面出现的所有数字都来自同一套固定配方，这样数字的变化就只能来自被检验的那个改动。

  • 语料。本仓库自有的第 1–6 周材料——lesson-plans/week-XX/lecture-en.html、lab-en.html、textbook/chapter-XX/en.html、labs/week-XX/lab-handout.md。748 段英文段落、6 类，许可 CC BY-NC-SA 4.0，由 scripts/build_text_corpus.py 构建。整个运行完全离线、不下载任何东西：这是刻意设计，它排除了对第三方数据及其许可的依赖。
  • 反泄漏清洗。所有字面的周次、实验、单元标识（Week 3、W3、CU(3)、Lab 3、日期）都替换为 <WEEK>、<UNIT>、<LAB>、<DATE>——共替换 262 处。没有这一步，标签就明摆在文本里，一切准确率都失去意义。替换次数被计入报告，使清洗本身可被审计，而不是靠信任。
  • 划分。70 / 15 / 15，按周分层，random_state = seed；种子 42 即 523 / 112 / 113。

  • 模型。Embedding(64, padding_idx=0) → LSTM(96, batch_first=True) → Linear(6)。
  • 优化。Adam(lr = 1e-3)，批 64，30 轮，max_len = 96。
  • 重复。五个种子（42、43、44、45、46）；每个数字都是五种子的均值 ± 1 个标准差。
关键术语
  • token——模型看到的单位：英文是像词一样的字符串，中文是一个词片段或一个字。
  • 词表（vocabulary）——从 token 到整数 id 的冻结映射，其中 0 留给填充、1 留给未知词。
  • 编码（encoding）——把 token 列表变成 id 列表，所有未见 token 换成 <unk>。
  • 填充（padding）——追加 <pad>，让一批中的每个文档等长。
  • 数据泄漏（data leakage）——测试集的信息进入了模型或预处理；这里指用超过训练集的数据建词表。
  • 文本到张量链路（text-to-tensor pipeline）——从原始字符串到“填充后的整数张量 + 长度”的四步。

8.2 分词：英文，以及中文的陷阱

分词看起来是最没意思的一步，却是唯一能错到 39 倍的一步。英文那套配方毫无争议；中文那套，则是一个从未处理过“不用空格分界的语言”的学生最容易踩进去的地方——他会写出一条看起来能跑、却得到一个永不迁移的词表的管线。

8.2.1 英文：先小写，再一条正则

本章全程使用的规则是：把文本小写，然后抽取每一段以字母开头、后续为字母、撇号或连字符的串。模式 [a-z][a-z'-]* 有三个后果值得明说，因为每一个都是一个选择。

  • 大小写是被有意丢掉的。LSTM 与 lstm 成为同一个 token。词表变小，模型不必为同一个词学两行——代价是丢掉了“大写词常常是一个句子的开头或一个专名”这条线索。
  • 缩写与连字符词保持完整。don't 是一个 token，不是两个；state-of-the-art 是一个 token，不是四个。对一个小语料来说这通常正是你要的，因为拆开只会用几乎不带信号的碎片把词表撑大。
  • 数字与标点会消失。一段含 17,226 的文本，对它一个 token 也不贡献，因为那里没有任何一段以字母开头。如果你真正在意的信号是数字，那这条正则就是错的分词器，你必须明说。

在这份语料上，配方的结果是稳定的：全量 748 段的词表有 3142 个词型，段落长度的中位数是 35 个词 token（p25 为 26，p75 为 50，p95 为 87，最大 285）。一个不大的词表，配上不长的段落——这两个数字正是让任务因 8.10 节所述原因而变难的关键。

8.2.2 中文：按空白分词就是错的

中文书写时词与词之间不加空格，所以英文那套配方没有对应物。一个诱人的捷径是：照样按空白切。这条捷径行不通，而在这里它是被量出来的，不是被断言的。在本仓库自有的中文教材文本上跑两种方案（750 段，切 375 段建词表、375 段做测试）：

把两行合起来读，失败是彻底的。按空白切分时，测试集对 375 个片段只贡献了 375 个 token——每段一个“词”，因为一整段没有空格的中文就是一个字符串。OOV 率是 0.9973，这不是“高”的意思，而是整段只被识别成一个 <unk>。词表几乎全是单例（0.9946），因为没有任何两个片段恰好相同，什么也共享不了，什么也学不到。相形之下，字符级从同样的片段里产出 14,860 个测试 token，OOV 率 0.0254，单例占比 0.2170。

OOV 率从 0.9973 降到 0.0254——差了 39 倍。这就是那个错误的量级，而避开它只需要一行代码。

对“没有空格的语言”的工程规则 先用真正的分词器——常见的是 jieba——它把句子切成词一级的单位。如果拿不到分词器，就退到字符级：它粗糙但正确，每个片段变成一串字符，OOV 低，模型仍能从字符模式里学。你绝不能做的，是退回按空白切分——那是唯一保证“每句一个长度为一的词表”的选项。 
# 正确：用分词器，拿不到就退到字符级。绝不按空白切。
def tokenise_zh(s, use_jieba=True):
    if use_jieba:
        try:
            import jieba
            return [t for t in jieba.lcut(s) if t.strip()]
        except ImportError:
            pass
    return list(s)          # 字符级：粗糙，但 OOV = 0.0254，不是 0.9973
    # return s.split()    # <- bug：每句一个 token，OOV = 0.9973
关键术语
  • 分词（tokenisation）——把字符串切成词表将持有的单位。
  • 词切分（word segmentation）——在不用空格标记边界的语言里恢复词边界；这是中文需要、英文不需要的一步。
  • 字符级分词（character-level tokenisation）——每个字符一个 token；拿不到分词器时的正确兜底。
  • OOV 率——测试 token 中不在训练词表里的比例；这里是 0.9973 对 0.0254。
  • 单例（singleton）——在训练词表中恰好出现一次的 token；单例占比高说明词表不可复用。

8.3 词表与编码

词表是分词器与嵌入表之间的一份契约，它在训练开始前就被冻结。本章用三个参数定义它，每一个都有可以辩护的理由。

8.3.1 三个设置，以及为什么这样设

设置取值理由
最小词频min_freq = 2训练里只出现一次的词学不到东西，它只会变成一行几乎不更新的参数。丢掉它能让 <unk> 保持有意义，也缩小了表。
词表上限6000嵌入表的一个上界。这份语料远够不到它，但一旦语料变大，这个上限能约束参数量与内存。

词表只在训练文档上统计，且统计与 id 分配在同一步完成，所以词频与 id 不可能对不上。种子 42 的结果是 1617 个条目；五个种子平均，模型实际看到 1592。若把每段都算进来，全语料有 3142 个词型——而第二个数字正是模型不该被给到的。

8.3.2 只从训练集统计

两个词表，两个故事。诚实的那个只在 523 个训练段上统计 token，于是模型在测试时第一次遇到的词是真的未知、也真的映射到 <unk>。泄漏的那个在全部 748 段上统计，这意味着测试集的稀有词早已带着 id 坐在表里，模型被考的是一道被悄悄放水的题。

为什么这是文本建模里最常见的泄漏 “把数组切开”是容易记住的；“把预处理也切开”不是。token 已经躺在一个列表里了，统计它只是一个两行的循环，看上去不明确属于切分的哪一边。纪律与第 3 章、第 6 章相同：任何被“拟合”的东西——一个 scaler、一个 imputer、一张词表——都在训练切分上拟合，测试切分只被 transform，永远不被 fit。词表就是被拟合的东西。8.9 节会量出忘掉这一点的后果。

8.3.3 padding_idx=0：一份永远送不到的梯度

给 nn.Embedding 传 padding_idx=0，不只是记录了哪一行是填充。在每一次反向传播中，PyTorch 都会把这一行的梯度贡献置零，于是 <pad> 的嵌入向量永远收不到更新。它从零出发，一路保持为零。这一点重要，是因为忽略掩码的池化仍会把真实隐状态乘上一个零向量；那一行不动并不能救你，但它至少意味着填充行不会带着被学出来的信号去别处误导优化器。

emb = nn.Embedding(1617, 64, padding_idx=0)

ids = torch.tensor([[5, 6, 7, 0, 0]])
out = emb(ids)                       # (1, 5, 64)；第 3、4 行来自第 0 行
out.sum().backward()                  # 用一个非零损失逼出梯度
print(emb.weight.grad[0].abs().sum())     # tensor(0.)——填充行永不学习
关键术语
  • 词表大小（vocabulary size）——含两个保留 id 在内的不同 id 数；种子 42 为 1617，平均 1592。
  • <pad> / <unk>——两个保留 id：0 用于填充，1 用于一切词表外 token。
  • padding_idx——告诉嵌入层哪一行是填充，其梯度在每一步都被强制置零。
  • 冻结词表（frozen vocabulary）——从训练切分建一次，训练与评估期间不再更新。

8.4 填充与掩码

LSTM 在一个固定的 T 轴上推进，但文档长度不一。填充是这场调和——而掩码，才是阻止这场调和污染答案的东西。本节是本章的核心，因为后文每一次失败，都是同一个掩码失败换了一顶帽子。

8.4.1 变长到定长

一批 64 个文档，数组必须是长方形的：形状 (64, T)。T 要么是这一批里最长的文档，要么是全局上限 max_len = 96，取较小者。每个更短的文档都在右侧填上 <pad>=0。长度向量记录每一行的真实长度，而那是这条信息唯一存活的地方。

填充的规模不小。在种子 42 的测试集上，95.58% 的文档短于 max_len = 96。换句话说，几乎每一批里几乎每一个文档都带着一条填充尾巴，任何读尾巴的代码，几乎在每个样本上都读到了填充。正是这一个百分比，决定了 8.5 节那个 bug 的杀伤力有多大。

8.4.2 掩码，以及正确的掩码均值

掩码是一个张量，在真实 token 处为 1，在填充处为 0。直接由 id 本身构造，(x != 0) 已经正好是这个——不需要额外的记账，因为 <pad> 就是 id 0。接着把掩码的形状调整到能与隐状态广播相乘，在归约之前施用。

out, _ = rnn(emb(x))                    # out: (B, T, H)

mask = (x != 0).unsqueeze(-1).float()     # (B, T, 1) -> 在 H 上广播

# 正确：在真实位置求和，除以真实位置的个数
z = (out * mask).sum(1) / mask.sum(1).clamp(min=1)      # (B, H)

# 安静的 bug：除以 T，于是每个填充位置都把均值往 0 拖
z_wrong = out.mean(1)                      # (B, H)——把填充也平均进去了

两行都能跑，都返回正确的形状，都不给任何警告。差别只在除数和掩码，而它们的效果在 8.8 节被量了出来：正确的掩码均值 0.5027，未掩码均值 0.3929，差 0.1098——约 11.0 个点——只因为少乘了一个掩码。

掩码必须在求和前进入，除数必须与之匹配 有两种写法会出错，而它们不是同一个错误。如果在求均值之后再掩码（out.mean(1) * something），填充位置早已贡献过了。如果掩码进了求和、却仍除以 T，那么每个短文档都被它真实 token 的占比缩小了：一个 35 词的文档被除以 96，它的向量被悄悄缩到大约三分之一。掩码必须进入求和，除数必须是掩码自己的计数。
关键术语
  • 填充（padding）——追加 <pad> 使一批成为长方形；95.58% 的测试文档短于上限。
  • 掩码（mask）——标记真实位置的 0/1 张量；这里是 (x != 0)，无需单独记账。
  • 掩码均值（masked mean）——只在真实位置上求和、除以它们的个数，(h * mask).sum(1) / mask.sum(1)。
  • 变长序列（variable-length sequence）——真实长度与批宽不等的文档；填充正是为了解决它。

8.5 out[:, -1, :] 这个 bug 的完整解剖

这是本周围绕的 bug，值得完整解剖一次，因为它具备一个能上线的 bug 的全部特征：它只有一行，写法很地道，运行不报错，输出形状正确，而它的伤害恰恰集中在没人会去检查的那批样本上。

8.5.1 错的那一行，和对的那一行

LSTM 之后，out 的形状是 (B, T, H)。意图是“模型对文档的读法”——每个样本一个长度为 H 的向量。错的那一行取的是最后一列：

# ---- 错的：out[:, -1, :] --------------------------------------------------
# 第 T-1 列，是 LSTM 消费完“最后一个位置”之后的状态。对短于批宽的文档，
# 那些位置就是 <pad>=0。所以这里读到的向量，是读完填充之后的隐状态——不是
# 这份文档的。95.58% 的测试文档短于 max_len = 96，于是几乎每个样本都读错了地方。
out, _ = rnn(emb(x))
z_bad = out[:, -1, :]                     # (B, H)——最后一列

# ---- 对的：打包，然后取“最后一个真实”隐状态 ------------------------------
# pack_padded_sequence 丢掉每一个填充时间步，于是 LSTM 在每个文档的真实长度处
# 停下。它要求批按长度降序，或者 enforce_sorted=False——后者在内部排序，回程
# 再恢复原顺序。此时 h[-1] 就是顶层每个样本在各自最后一个真实 token 处的隐状态。
packed = nn.utils.rnn.pack_padded_sequence(
    emb(x), lengths, batch_first=True, enforce_sorted=False)
_, (h, _) = rnn(packed)
z_ok = h[-1]                                # (B, H)——最后一个真实 token

一批里只有一份文档会被错的那一行读对：最长的那份，因为它的最后一个位置恰好是真实 token。其余每一份，都在一个仅仅因为填充才存在的位置上被读取。文档越短，隔在它的真实末尾与模型实际读取的位置之间的填充就越多。

import torch, torch.nn as nn

torch.manual_seed(0)
B, T, H, V = 4, 8, 96, 100
emb = nn.Embedding(V, H, padding_idx=0)
rnn = nn.LSTM(H, H, batch_first=True)

x = torch.tensor([[5, 6, 7, 0, 0, 0, 0, 0],     # 长度 3
                  [8, 9, 1, 2, 3, 4, 5, 0],     # 长度 7
                  [1, 2, 3, 0, 0, 0, 0, 0],     # 长度 3
                  [7, 8, 9, 10, 11, 12, 13, 14]])  # 长度 8（满）
lengths = (x != 0).sum(1)                        # tensor([3, 7, 3, 8])

e = emb(x)
out, _ = rnn(e)

z_bad = out[:, -1, :]                              # 读到填充
packed = nn.utils.rnn.pack_padded_sequence(
    e, lengths, batch_first=True, enforce_sorted=False)
_, (h, _) = rnn(packed)
z_ok = h[-1]                                    # 读到最后一个真实 token

print(torch.allclose(z_bad[3], z_ok[3]))              # True——第 3 行是满长
print(torch.allclose(z_bad[0], z_ok[0]))              # False——第 0 行有填充

机制一句话，以及这个错误的通用形状 out[:, -1, :] 假定填充张量里的最后一个位置就是文档的最后一个位置；pack_padded_sequence 加 h[-1]（或掩码均值）用真实长度，在文档结束处停下。这个错误的通用形状是在变长轴上的固定归约：只要一个张量带有填充轴，任何把每个位置都当成真实的操作——取最后一位、不带掩码的均值、不带掩码的最大值——都是错的，唯一的差别只是代价有多大。
关键术语
  • pack_padded_sequence——PyTorch 的辅助函数，丢掉填充时间步，让循环层在每个文档的真实长度处停下。
  • enforce_sorted——为 False 时，打包会在内部按长度排序并在回程恢复原顺序；为 True 时你必须预先排好。
  • 最后一个真实隐状态（last real hidden state）——最终一个非填充 token 之后的状态；最后一步读取的正确目标。
  • 池化（pooling）——把隐状态序列归约成每个文档一个向量的操作。
  • 变长轴上的固定归约——这个 bug 的模式；把填充当内容读，不报错，藏在短样本里。

8.6 RNN 与梯度消失

循环层继承了每个深层网络都有的问题，但形态更糟、也更具体。递归是序列模型“看得远”的来源，也是它梯度死掉的地方。

8.6.1 递推式

一个朴素的循环层维护一个长度为 H 的隐状态，每个 token 更新一次：

ht = tanh(W xt + U ht-1 + b)

其中 xt 是第 t 步 token 的嵌入，W、U、b 在每一步之间共享。共享不是一种优化，它就是定义本身。它让同一个层能同时接受一份 20 词的文档和一份 285 词的文档，也让整个东西能靠一套参数训练。

import torch

H, T = 96, 5
W = torch.randn(H, H) * 0.1
U = torch.randn(H, H) * 0.1
b = torch.zeros(H)

h = torch.zeros(H)                          # 初始状态
xs = torch.randn(T, H)                      # 每步一个嵌入
for t in range(T):
    h = torch.tanh(xs[t] @ W.T + h @ U.T + b)   # 把递推式写开

训练一个循环网络就是普通的沿时间反向传播：最后一步的损失要对每一个更早的步求导，于是到达第 k 步的梯度，是每一步一个雅可比矩阵的连乘。麻烦就在这个连乘里。

8.6.2 梯度为什么消失，或者爆炸

对递推式求导，转移因子就出现了：

dht / dht-1 = diag(1 - tanh2(...)) U

于是，对过去第 k 步的梯度，被大约 T 个这样的因子连乘。这条链上会发生两件事。

  • 消失。tanh 的导数最大为 1，通常远小于 1，而 U 的元素在初始化后也很小。许多小于 1 的数连乘会指数级缩小：等梯度回溯跨过 50 步，它已经小到与零无法区分，塑造序列前段的那些参数就不再学习。
  • 爆炸。如果 U 的元素恰好很大，连乘就会放大，梯度溢出。典型症状是损失跳成 nan；典型对策是梯度裁剪，在优化器步之前把梯度的范数截住。

在这份语料上，这个问题存在，但不是那个真正的瓶颈：段落长度中位数是 35，上限是 96，短到梯度消失更像是噪声，而不是成绩低的原因。成绩低的真正原因，是 8.9 节量出来的那件事——数据太少——两者要分清楚，因为它们对应的修法不同。

关键术语
  • 隐状态（hidden state）——循环层跨步携带的向量，长度为 H。
  • 权值共享（shared weights）——每一步都用同一个 W 与 U，这是变长输入得以成立的原因。
  • 沿时间反向传播（BPTT）——在展开的递归上做反向传播。
  • 梯度消失（vanishing gradient）——梯度在很多步上指数衰减，导致前段停止学习。
  • 梯度爆炸（exploding gradient）——相反的情形；梯度溢出，通常靠裁剪其范数解决。

8.7 LSTM 与 GRU：门控，以及它并没有解决的问题

长短期记忆（LSTM）单元被发明出来，是为了给梯度一条不必再穿过一长串 tanh 导数的通路。它靠门控做到这一点，而把门一个一个地看作对某个具体问题的回答，是最好理解的。

8.7.1 三个门，三个问题

门它回答的问题它控制什么
遗忘门 ft旧记忆里有多少该活下来？缩放上一时刻的细胞状态 Ct-1；接近 0 抹除，接近 1 保留。
输入门 it新候选里有多少该被写进去？缩放候选更新；决定这个 token 里有什么值得记住。
输出门 ot此刻该暴露多少记忆？缩放细胞状态到隐状态 ht 的通路。

对梯度真正要紧的机制是细胞状态 Ct，其更新为 Ct = ft * Ct-1 + it * candidate。在细胞状态这条通路上，转移是乘以遗忘门，而不是乘以一个权重矩阵再乘一个 tanh 导数。当遗忘门接近 1 时，这条通路接近恒等，梯度可以跨很多步流动而不像原来那样迅速缩小。这就是“LSTM 解决梯度消失”的真正含义——不是说问题没了，而是说现在有了一条让问题轻得多的路径。

8.7.2 代价：它仍然是顺序计算的

门控买来了一条更好的梯度通路，在正确性上没有代价，但它改变不了一个结构性事实：递归仍然是一个循环。第 t 步需要 ht-1，所以一份文档的 T 个步无论有多少核都不能并行。GRU 是同一思想的更廉价的变体——它把遗忘门与输入门合并成一个更新门、去掉了独立的细胞状态，两个门代替三个——而它同样顺序。

通往模块三的桥 正是这个顺序依赖，让这个领域继续往前走。注意力机制，以及由它搭起的 Transformer，一次性从所有其他位置算出每个位置的表示，完全没有递归——于是整条序列可并行，沿链的梯度消失问题也随之消失。第 10 章会直接讲它，而它会把本周的 LSTM 当对照：同一个任务、同一份数据，对“一个位置怎样看到其他位置”给出不同的答案。请记住本周的数字，因为它们是 Transformer 必须超过的基线。
关键术语
  • 门（gate）——一个输出在 0 到 1 之间的 sigmoid 层，用来缩放某个信号；门是单元决定保留什么的方式。
  • 遗忘门（forget gate）——缩放上一时刻的细胞状态；接近 0 忘记，接近 1 保留。
  • 输入门（input gate）——缩放写入细胞状态的新候选。
  • 输出门（output gate）——缩放细胞状态到隐状态的输出。
  • 细胞状态（cell state）——LSTM 的长期记忆通路；因为它的转移是乘以遗忘门，它为梯度提供了更轻松的一条路。
  • GRU——LSTM 的双门简化版；更廉价，也同样顺序。

8.8.2 诚实的基线：最差那一臂低于随机

6 个大致均衡的类，随机猜测在准确率上达到 1/6 ≈ 0.1667。这是每一臂在“做了任何事”之前必须先超过的数。last_step 的准确率是 0.2407，过了 0.1667——但它的宏 F1 是 0.0711，低于随机基线。原因在 8.10 节的混淆矩阵一摆出来就清楚了：错的那一臂几乎总是预测最大的类，于是它单靠先验就收到准确率，却几乎找不到任何小类的样本。宏 F1 对每个类等权，一眼看穿它。

0.5027 是真实成绩，不是好成绩 它是随机基线的三倍，而每个种子 113 篇测试文档的样本量小到 ±0.0449 的离散度不容忽视。本章任何一句话都不该读成“这个 LSTM 文本分类做得好”。正确的说法是：在这份语料、这些数据量下，最优配置到 0.5027，而配置之间的差距，比任何一个配置的绝对水平都大。本章讲的是那个差距，因为差距才是你控制得了的东西。

关键术语
  • 方案（arm）——被检验的一种配置，其余所有因素保持不变。
  • 池化（pooling）——从隐状态序列到单个向量的归约；这里是唯一变化的量。
  • 随机基线（random baseline）——瞎猜的得分；6 分类下约为 1/6 ≈ 0.1667。
  • 宏 F1（macro F1）——各类 F1 的等权均值；它是能把“靠类别先验”的臂照出来的指标。
  • 种子重复（seed replication）——在多个随机种子上重复同一方案，使离散度而不是单次运行成为测量结果。

8.9 过拟合、正则化，与认错的瓶颈

每一臂都在过拟合。有意思的问题不是“它是否过拟合”——523 个训练段，模型在上面到了 0.9885，当然过拟合——而是这是哪一种过拟合，因此什么能修它。本节用两次实测回答这个问题，并得出本周最重要的诚实结论。

8.9.2 加上第 6 周的正则化，反而更差

第 6 章教过两种在那里有效的正则化：对隐表示做 Dropout，对优化器加权重衰减。把两者都加到最优那一臂上——mean_masked 配 Dropout 0.3 与权重衰减 1e-3——就是对瓶颈假设的一次受控检验：

臂测试准确率宏 F1
mean_masked0.5027 ± 0.04490.4774 ± 0.0482

成绩从 0.5027 掉到 0.4672——下降 0.0355，约 3.6 个百分点——宏 F1 下降 0.0341，约 3.4 个点。比下降更糟的是离散度的变化：种子间标准差从 ±0.0449 扩大到 ±0.0595，于是正则化那一臂既更低、也更不稳。在这个任务上，两个“帮数据充足、容量过剩的模型”的工具起到了反作用：它们拿掉了模型仍然需要的容量。

结论，直说 本周绑住结果的约束是数据，不是容量。训练段只有 523 个。0.5689 的训练-验证差距看着像过拟合，但它是发生在一个容量并非限制因素的模型上的过拟合——所以去约束那个容量（Dropout、权重衰减）只会把它仅有的那点信号也拿掉。能撬动这个数字的杠杆是更多段落，或者一个不同的任务定义；正则化不是这里的杠杆。
同一个手段，两个相反的答案 在第 6 周，同样的两种正则化提高了成绩：那里数据充足、模型偏大，容量是瓶颈，约束它有帮助。在这里数据稀缺、容量不是瓶颈，于是完全相同的手段造成伤害。这不是工具自相矛盾，而是一个提醒：一项技术不是一条规则，它是对一个被诊断出来的瓶颈的回应。流程永远一样：先量出哪条约束在绑着结果，再选工具。把上次奏效的工具直接套用、不做测量，正是一个能用的模型在工程师自以为改进了它的同时变坏的原因。

8.9.3 在全量数据上建词表带来的“假提升”

另一个诱人的“修复”是：在全部 748 段而不是 523 个训练段上统计 token，从而把词表撑大。它把词表从 1592（五种子的均值）推向全语料的 3142，而且通常会把成绩抬高。它同时是泄漏，而那个抬升是假的：词表里现在装着测试集的稀有词，于是报告量到的 OOV 率低于模型在真正新文本上会遇到的 OOV 率。测出来的抬升正是因为任务被改简单了，任何诚实的报告都不能把它当作改进来引用。练习 2 会让你亲手跑一遍，看清这个假增益的形状。

关键术语
  • 过拟合（overfitting）——模型在训练集上远好于未见数据；这里训练-验证差距是 0.5689。
  • Dropout——训练时随机置零隐单元，以降低有效容量。
  • 权重衰减（weight decay）——对权重的 L2 惩罚，把它们往零收缩。
  • 瓶颈（binding constraint）——真正限制成绩的因素；这里是 523 个训练段，不是模型的大小。
  • 假提升（false improvement）——来自泄漏测试信息、而非来自更好模型的增益。

非对角几乎是平的。每个非对角格子都在 4 到 22 之间。没有任何一对周次比别的更容易被混淆——没有这个任务里的“8 与 1”。对角线上唯一突出的是 W6 的 93，而那不是模型擅长第 6 周，是第 6 周本来就是最大的类（140 篇测试样本，对第 1 周的 80 篇）。

召回随类别大小总体上升（Spearman ρ = 0.77）。召回应为：W1 0.1750、W2 0.1867、W3 0.4235、W4 0.4778、W5 0.4211、W6 0.6643。序列里有两处小逆序（W2 略高于 W1、W5 略低于 W4），但趋势一目了然：类越大，模型找得越好。W6 的召回是 W1 的 3.80 倍。一个把大类找得好、把小类找得差的模型，学的不是内容——它学的是先验，更频繁地预测那个常见的周。这正是“非对角是平的”背后的直接证据：既然没有任何一对周次比别的更可分，那么按频率预测，就是模型找到的最好策略。

8.10.2 准确率与宏 F1 的分裂：那个阻止坏模型上线的信号

对 last_step 臂，两个指标分歧很大：

last_step0.2407 ± 0.00400.0711 ± 0.00951/6 ≈ 0.1667

准确率 0.2407；宏 F1 0.0711。差距 0.1696——约 17 个点——而且方向要紧：准确率高于随机基线，而宏 F1 低于它。一份只报准确率的报告，会把一个看起来比抛硬币好的模型描述出来，并把它送进生产。宏 F1 对每个类等权，照出一个“学会了说最大那个类、别的几乎什么都不会”的模型。指标不是形式；它是“一个能用的模型”与“一个自信的模型”之间的差别。

指标由“错要付什么代价”决定 当类别不均衡、而漏掉一个小类的代价与漏掉一个大类一样高时，准确率是错的工具，宏 F1 才对。当代价确实与类大小成比例时，准确率是站得住的。这个选择是对“一次错误值多少”的陈述——所以它属于那些承担后果的人，而不属于一个默认值。这是本周的思政落点：选指标，就是在选你愿意接受谁的错。

8.10.3 十四篇错分，当成文本读

种子 42 的 packed 臂在 113 篇测试段里错 14 篇。当成文本、而不是当成格子来读，它们分三类，而三类都不是模型的失败。

短句，词表能借力的地方最少（20 词）——真 W4，判 W3

"Hidden layers transform the features first; the output layer decides afterwards. The same data becomes separable in the new space." 20 词是语料允许的最小长度，而它讲的是通用概念，没有多少 token 能把它锚定到某一周。

通用工程句，哪一周都成立（26 词）——真 W1，判 W2

"Hyper-parameters, data paths, batch size and split ratios live in a file or a single dictionary - not scattered through the code and not in your memory." 这句话在第 1 周是好建议，第 6 周也是；它完全不带周次特定的词汇，所以任何分类器都无法靠内容给它定位。

术语跨周复用（22 词）——真 W6，判 W4

"Explain how a training set of 80 samples against 17,226 parameters produces overfitting on purpose, and why that is the point of the lab." 这一段里出现 17,226，而这个数字在第 4 周的材料里也出现过；模型拿到了那个词，但那个词并不专属于某一周。

这三篇里没有一篇是“模型看错了” 三种情况下，模型的预测都能从段落里的词得到辩护：这些句子本身就属于不止一周。对一段复用了另一周词汇的段落，“它出自哪一周”本来就没有唯一答案——标签是这段文字被归档在哪里的属性，不是它说了什么的属性。那不是靠更大的模型能修好的失败；那是任务定义的边界。诚实的回应是在报告里点明它，并考虑该不该重新定义任务（预测主题、接受多标签），而不是该不该重训模型。
关键术语
  • 混淆矩阵（confusion matrix）——行是真类、列是预测类；对角线统计判对，每个非对角格子是一次具体的混淆。
  • 召回率（recall）——某一类真实样本中被找出的比例；这里从 W1 的 0.1750 到 W6 的 0.6643。
  • 类别先验（class prior）——某一类的基础比例；一个预测最大类的模型就是在利用它。
  • 准确率 / 宏 F1 分裂——准确率高于基线而宏 F1 低于基线；这是模型只预测先验的信号。
  • 错分分析（error analysis）——把错分样本当文本读，找出聚合数字藏起来的东西。

8.11 本章小结与练习

六条要点
  1. 文本模型永远看不到字符串。四步把文本变成张量——分词、建词表、编码、填充与掩码——而词表只从训练切分构建。别的做法都是泄漏，8.9 节说明了为什么由此得到的增益是假的。
  2. 分词不是化妆。在中文文本上，按空白切分得到 OOV 率 0.9973——每句一个 token，等于每段一个 <unk>——而字符级是 0.0254，差 39 倍。先分词，退到字符级，绝不退到空白。
  3. 填充是张量的大部分：95.58% 的测试文档短于 max_len = 96。掩码必须在归约前进入求和，除数必须是掩码自己的计数；掩码均值比未掩码均值值约 11.0 个点。
  4. out[:, -1, :] 在每个短文档上都读填充。它的签名是伤害紧跟文档长度——20–29 词上 0.1579，短于 max_len 为 0.2315，而达到或超过则为 0.4000——而正确那一臂是平的。修正归约能把成绩移动 26.2 个点，而且任何 max_len 设置都替代不了它。
  5. 正则化是对瓶颈的回应，不是规则。本周瓶颈是 523 个训练段：Dropout 与权重衰减把成绩从 0.5027 拉到 0.4672，并把离散度从 ±0.0449 扩大到 ±0.0595。在第 6 周同样的工具帮助很大，因为那里的瓶颈是容量。先诊断。
  6. 报告与“错的代价”匹配的那个指标。last_step 臂准确率 0.2407、宏 F1 0.0711——一个高于随机、一个低于随机。而那 14 篇错分不是模型错误：那些段落属于不止一周，任务对它们本就没有唯一答案。
