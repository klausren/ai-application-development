第 07 章 · 模块 2 · 第 7 周

卷积神经网络与计算机视觉应用

第 5 周搭起了训练循环，第 6 周教会你不轻信单个数字。这一章面对的是另一种决定：不是选哪个优化器，而是选哪个架构，以及这个架构要付出什么代价。本周的主线刻意不是「卷积更准」——在这份数据上，实测不支持这个说法。它讲的是一个更窄、也更有用的结论：两层卷积用 1898 个参数拿到 0.9808，而全连接网用 17226 个参数拿到 0.9785，这 0.0023 的差距还不到一个标准差。于是我们把整章花在让它成立的算术上——滑动点积、与真实张量逐项核对的输出尺寸公式、感受野递推 3 → 4 → 8 → 10——然后花在两个「诚实答案并不方便」的地方：池化方式是一个值 4.1 个点的设计选择；数据增强买到 29 个点的鲁棒性，付出 3 个点的干净精度。章末是覆盖 1350 个测试预测的混淆矩阵、峰值内存随批大小的实测扫描，以及四种梯度累积权重写法中哪些能真正复现大 batch。

7.1 从全连接到卷积

最自然的第一反应，正是第 5 周已经用过的：把图像铺平成向量，喂给多层感知机。在 8×8 的数字图上，这个向量只有 64 维，想法完全可行。但换到照片上就不行了，原因不在哲学，而在算术——所以它可以被数出来。

7.1.1 为什么图像不能直接铺平

像素被排成一行的那一刻，三件互不相同的事同时出问题，而每一件都能在本周的实验里找到对应的数字。

参数量会爆炸

一个把 64 维输入映射到 128 维输出的全连接层，光权重就有 64 × 128 + 128 = 8320 个。本周用作对照的整个网络共有 17226 个参数。把输入换成真实照片——224 × 224 × 3 是 150528 个输入——一个同样宽的隐藏层在第一个 ReLU 之前就需要一千九百多万个权重。增长是图像边长的二次函数，而驱动它的是输入的维度，不是类别数。

铺平会破坏空间结构

8×8 的网格一旦变成 64 维向量，原本相邻的两个像素，和隔着整张图的两个像素，就变成同一类东西：两个下标。全连接层的权重矩阵里没有任何东西知道下标 8 和下标 9 在同一行上相邻，也不知道下标 0 离它们整整隔了一行。图像中真正承载信息的空间结构，在学习开始之前就被丢掉了。

平移被当成全新对象

全连接网必须为每一个位置把每个模式重新学一遍。这不是理论抱怨，它是被实测出来的：把测试图平移一列，全连接网从零平移的 0.9785 掉到 0.5089，而卷积只掉到 0.6481。同一个数字，移动一个像素，对一个无法跨位置共享权重的网络来说就是半个新问题。

7.1.2 局部连接与权值共享

卷积层用两条结构性假设回应了全部三个问题。局部连接（local connectivity）说：一个输出值只由输入的一小块算出——一个 3×3 的窗口，而不是整张图——于是每个输出对应的权重数不随图像尺寸增长。权值共享（weight sharing）说：同一个小核被应用在每一个位置上，于是总权重数只取决于核的大小和通道数，与图像有多宽无关。

正是这两个决定，把「为每个位置分别学一个检测器」变成了「学一个检测器、然后滑动它」。代价是一条假设：有用的模式是局部的，而且这个模式出现在哪里都有用。当这条假设成立——手写数字的笔画就是如此——节省是巨大的。当它不成立，卷积可能比全连接还差，而这是一笔真实的代价，不是脚注。

7.1.3 参数量对账：从 17226 到 1898

官方教学实施建议明确要求用「参数量对比」来讲清卷积的权值共享，因为它是最直观的一种方式。下面两个架构用的是完全相同的数据、完全相同的切分和优化器。

层形状参数量累计
全连接 64 → 12864 → 12883208320
全连接 128 → 64128 → 64825616576
全连接 64 → 1064 → 1065017226
卷积 1 → 8，3×3（k*k*C_in*C_out + C_out）8×8×83*3*1*8 + 8 = 8080
卷积 8 → 16，3×316×4×43*3*8*16 + 16 = 11681248
全连接 64 → 1064 → 1064*10 + 10 = 6501898

两层卷积合计 1248 个权重，线性头 650 个；全连接对照网则持有 17226 个。卷积的参数量少了 9.07 倍；而——这才是整周的关键——两者的测试准确率分别是 0.9785 与 0.9808，差距 0.0023，小于一个标准差（0.0084）。所以诚实的写法是「未观察到显著差异」，而不是「卷积更好」。

冻结的协议，精确复述 本章后面出现的所有数字都来自同一套固定配方，这样数字的变化就只能来自被检验的那个改动。
  • 数据。sklearn.datasets.load_digits——8×8 灰度手写数字，10 类，共 1797 张，随 scikit-learn 自带。整个实验完全离线，不下载任何东西，这是刻意设计：它排除了对第三方数据源及其许可的依赖。像素缩放到 0–1。
  • 划分。70 / 15 / 15，分层，random_state = seed，留下 n_train = 1258，验证集与测试集各约 270 张。
  • 优化。Adam(lr = 1e-3)，批大小 64，120 轮，不用权重衰减。
  • 重复。五个随机种子（42、43、44、45、46）；每个数字都是五种子的均值 ± 1 个标准差，绝不用单次运行。
import torch, torch.nn as nn
from sklearn.datasets import load_digits
from sklearn.model_selection import train_test_split


def load_split(seed=42):
    """1797 张数字图，8x8，缩放到 [0, 1]；分层 70 / 15 / 15。"""
    X, y = load_digits(return_X_y=True)          # 8x8 像素，10 类
    X = (X / 16.0).astype("float32")              # 像素范围 0..16 -> 0..1
    Xtr, Xrest, ytr, yrest = train_test_split(
        X, y, test_size=0.30, stratify=y, random_state=seed)
    Xva, Xte, yva, yte = train_test_split(
        Xrest, yrest, test_size=0.50, stratify=yrest, random_state=seed)
    t = lambda a: torch.tensor(a)
    return (t(Xtr), t(ytr), t(Xva), t(yva), t(Xte), t(yte))


class MLP(nn.Module):
    """铺平 64 -> 128 -> 64 -> 10  =  17226 个参数。"""
    def __init__(self):
        super().__init__()
        self.net = nn.Sequential(nn.Linear(64, 128), nn.ReLU(),
                                 nn.Linear(128, 64), nn.ReLU(),
                                 nn.Linear(64, 10))

    def forward(self, x):
        return self.net(x.view(x.shape[0], -1))


class CNN(nn.Module):
    """conv(1->8,3,pad1) ReLU maxpool2 -> conv(8->16,3,pad1) ReLU maxpool2 -> FC 10
    = 1898 个参数。`pool` 是构造参数，让平均池化那一臂共用这段代码。"""
    def __init__(self, pool=nn.MaxPool2d, in_size=8):
        super().__init__()
        self.in_size = in_size
        self.body = nn.Sequential(
            nn.Conv2d(1, 8, 3, padding=1), nn.ReLU(), pool(2, stride=2),
            nn.Conv2d(8, 16, 3, padding=1), nn.ReLU(), pool(2, stride=2))
        self.head = nn.Linear(16 * 2 * 2, 10)      # 铺平 64 -> 10

    def forward(self, x):
        x = self.body(x.view(-1, 1, self.in_size, self.in_size))
        return self.head(x.view(x.shape[0], -1))


for m in (MLP(), CNN()):
    print(sum(p.numel() for p in m.parameters()))   # 17226，然后是 1898
关键术语
  • 卷积（convolution）——每个输出由输入的局部小块算出，并在所有位置复用同一个核的层。
  • 特征图（feature map）——卷积产生的二维数组；每个输出通道对应一张。
  • 局部连接（local connectivity）——每个输出只依赖输入的一个小邻域。
  • 权值共享（weight sharing）——同一组核权重在每个空间位置被复用，这正是参数量与图像宽度无关的原因。
  • 平移等变性（translation equivariance）——输入平移，特征图跟着平移同样的距离；全连接层必须在每个位置从头学出这个性质。这里的词是等变（equivariance）而不是不变（invariance），因为响应是随输入一起移动的。

7.2 卷积运算

卷积里的全部算术就是一句话：取一块、与核逐元素相乘、求和。其余的一切——步长、填充、通道、分组——都是围绕这句话的记账。亲手把这句话写一次，术语才会变得具体。

7.2.1 一次滑动点积

下面的手写版本不是你要交付的代码，而是让特征图、步长、填充这三个词有具体含义的代码。它与 nn.Conv2d 的一致性用断言来核对，所以「手写实现与 PyTorch 一致」是程序验证过的事实，而不是教材里的一句声称。

import torch, torch.nn as nn
import torch.nn.functional as F


def conv2d_naive(img, kernel, stride=1, pad=0):
    """img: (H, W)   kernel: (kh, kw)  ->  一次滑动点积。"""
    H, W = img.shape
    kh, kw = kernel.shape
    if pad:
        img = F.pad(img, (pad,) * 4)
        H, W = H + 2 * pad, W + 2 * pad
    oh = (H - kh) // stride + 1
    ow = (W - kw) // stride + 1
    out = torch.zeros(oh, ow)
    for i in range(oh):
        for j in range(ow):
            patch = img[i * stride:i * stride + kh,
                        j * stride:j * stride + kw]
            out[i, j] = (patch * kernel).sum()
    return out


torch.manual_seed(0)
img, kernel = torch.randn(8, 8), torch.randn(3, 3)
mine = conv2d_naive(img, kernel, stride=1, pad=1)

conv = nn.Conv2d(1, 1, 3, stride=1, padding=1, bias=False)
conv.weight.data = kernel.view(1, 1, 3, 3)
ref = conv(img.view(1, 1, 8, 8))[0, 0]

assert mine.shape == ref.shape == (8, 8)          # padding=1 保持尺寸不变
assert torch.allclose(mine, ref, atol=1e-5)
print("hand-written == nn.Conv2d")

7.2.2 多输入通道、多卷积核、多输出通道

真正的层不是「一个核滑过一张图」。当输入有 C_in 个通道、需要 C_out 个核时，每个输出通道由它自己的核产生，而这个核跨越全部输入通道。因此该层的参数量是 k * k * C_in * C_out + C_out，第一项是权重，第二项是偏置。

# 3 个输入通道，16 个 3x3 卷积核，padding 1 -> 16 个输出通道
conv = nn.Conv2d(in_channels=3, out_channels=16, kernel_size=3, padding=1)
x = torch.randn(4, 3, 8, 8)                       # 一批 4 张图
y = conv(x)
print(y.shape)                                     # torch.Size([4, 16, 8, 8])
print(sum(p.numel() for p in conv.parameters()))    # 3*3*3*16 + 16 = 448

这正是 7.1.3 节里那个 80 和 1168 的来历：conv1 = 3*3*1*8 + 8 = 80，conv2 = 3*3*8*16 + 16 = 1168。

7.2.3 输出通道意味着什么

每个输出通道都是一个学到的特征检测器，被应用在整张图上，而它的特征图告诉你这个检测器在哪里响应强烈。8 个输出通道就有 8 张 8×8 的特征图；16 个就有 16 张。所以通道数是这一层被允许去寻找的模式种数，它与图像尺寸无关——无论输入是 8×8 还是 1024×1024，用的都是同一个 3×3 核。

关键术语
  • 卷积核 / 滤波器（kernel / filter）——被滑动过输入的小权重张量；一个核产生一个输出通道。
  • 滑动点积（sliding dot product）——运算本身：把小块与核逐元素相乘，再求和成一个数。
  • 输入 / 输出通道（input / output channel）——输入体的深度，以及卷积核的个数，后者成为输出的深度。
  • 偏置（bias）——每个输出通道一个学到的标量，加到该通道特征图的每一个位置上。

7.3 步长、填充与输出尺寸公式

形状错误是深度学习里最常见的报错，也是最容易消除的，因为它们纯粹是算术。一个公式同时覆盖卷积、池化和带步长的卷积：

out = (in + 2p − k) / s + 1

其中 in 是输入的边长，k 是核大小，s 是步长（stride），p 是每一侧的填充（padding），除法取整数部分。下面四种常用取值几乎覆盖了你将要写的一切：

ksp8×8 输入的输出什么时候用
3118尺寸不变的卷积；每个 CNN 的主力配置。
3106valid 卷积；每次缩小 k − 1。
2204池化：特征图减半，感受野的 jump 翻倍。
3214带步长的卷积：一个可学习的下采样。

7.3.1 公式与真实张量逐项核对

脚本不会去「估算」这些形状；它把公式算出来，再与真实前向的形状逐项比对，并在每一阶段断言相等。结果是本周 CNN 的形状链路：8×8 → conv+P → 8×8 → pool → 4×4 → conv+P → 4×4 → pool → 2×2 → 铺平 64 → FC 10。

def out_size(size, k, s, p):
    return (size + 2 * p - k) // s + 1


stages = [("conv", 3, 1, 1), ("pool", 2, 2, 0),
          ("conv", 3, 1, 1), ("pool", 2, 2, 0)]
size = 8
for kind, k, s, p in stages:
    size = out_size(size, k, s, p)
    print(kind, "->", size)          # conv -> 8, pool -> 4, conv -> 4, pool -> 2
print("flatten =", 16 * 2 * 2)       # 64

# 同一组数字，从真实前向读出，而不是从公式推出
h = torch.zeros(1, 1, 8, 8)
with torch.no_grad():
    for layer in CNN().body:
        h = layer(h)
        print(tuple(h.shape[1:]))     # (8,8,8) (8,8,8) (8,4,4) (16,4,4) (16,2,2)

四条核对全部与真实前向一致。当「shape mismatch」报错时，有产出的第一步是拿这套算术手算一遍，而不是改代码——大多数形状错误都能在一分钟内在此定位。

关键术语
  • 步长（stride）——核在相邻位置之间移动的距离；步长 2 会把输出边长减半。
  • 填充（padding）——在边界补零，好让核能对准边缘像素；3×3 核配 padding 1 可保持尺寸不变。
  • 输出尺寸公式（output-size formula）——out = (in + 2p − k)/s + 1，卷积与池化共用。
  • 铺平维度（flatten dimension）——卷积主体末尾的 通道 × 高 × 宽，此处为 64，它成为线性头的输入宽度。

7.4 感受野

一个单元的感受野（receptive field），是它能看到的原始输入范围。它回答的是「你的网络有没有能力关联图像上相距很远的两处」，而一旦涉及池化，它的增长速度会比直觉更快。

7.4.1 递推公式

逐阶段跟踪两个量：感受野 rf 与 jump——即两个相邻输出之间对应的输入像素距离。每个阶段的更新是

rf = rf + (k − 1) × jump　且　jump = jump × s

从 rf = 1、jump = 1 出发。步长为 2 的池化层把 jump 翻倍，这就是它后面那一层感受野增长快一倍的原因。

阶段ks特征图感受野jump
输入——8×811
卷积 1318×831
最大池化224×442
卷积 2314×482
最大池化222×2104

感受野沿 3 → 4 → 8 → 10 递推。承载教训的是「卷积 2」这一行：感受野 8，正好等于整张图的边长。在这份 8×8 数据上，第二层卷积已经能看到全部能看到的东西；再叠多少层也不可能增加平移不变性，因为已经没有未被覆盖的区域——这是数据太小，不是模型太弱。

def receptive_field(stages, size=8):
    rf, jump = 1, 1
    for kind, k, s, p in stages:
        size = (size + 2 * p - k) // s + 1
        rf = rf + (k - 1) * jump
        jump = jump * s
        print(f"{kind:<4} k={k} s={s}  map {size}x{size}  RF={rf}  jump={jump}")

关键术语
  • 感受野（receptive field）——能影响某个单元取值的输入区域。
  • jump——特征图上两个相邻输出所对应的输入空间距离；每个阶段乘以步长。
  • 有效感受野（effective receptive field）——实际有贡献的区域；在感受野边缘处，它比中心处更窄。

7.5 池化

池化通常被讲成「降维」，那只是它三个作用中的一个，而且是最没意思的一个。它还扩大感受野，并换来对小范围平移的容忍——而关键在于，它是一个有实测代价的选择。

7.5.1 三个作用，一个代价

作用它做了什么没有它会怎样
缩小特征图8×8 → 4×4 → 2×2；后续层的算力与显存按面积下降后面每一层都付满额的空间代价
扩大感受野步长 2 的池化让 jump 翻倍，于是下一层卷积看得远一倍叠再多 3×3 卷积也只有 3、5、7……
容忍小范围平移「这一片里有强响应」比「正好在第 3 行第 5 列有强响应」更稳输入动一个像素，输出跟着动

代价是池化丢掉了位置信息。对于需要知道在哪里的任务——分割、检测、关键点定位——这些信息必须被补回来。而选哪种池化函数，也不是一个会互相抵消的口味问题。

7.5.2 池化方式的选择，值 4.1 个点

下面两个架构只有一处不同：池化函数。通道数、核、学习率、轮数完全相同，参数量也一样。这是本周关于「这是设计选择」最清晰的一次实测。

架构池化参数量训练 acc验证 acc测试 acc
CNN 小最大池化18980.9987 ± 0.00090.9704 ± 0.01010.9808 ± 0.0084
CNN 小平均池化18980.9497 ± 0.00890.9289 ± 0.01640.9400 ± 0.0081

最大池化到 0.9808，平均池化到 0.9400。差距是 4.1 个百分点，是好几个标准差，而两个网络的参数量相同。平均池化把「最强的那个响应」抹平了，而手写数字的判别信息恰恰在笔画最集中的地方。选池化函数，就是在选你愿意保留什么——而它可能比在一个错误选择之上做的任何调参都值钱。

关键术语
  • 池化（pooling）——在小窗口上做的、无参数的固定归约，用于缩小特征图并扩大感受野。
  • 最大池化（max pooling）——保留每个窗口里的最大值；保住最强响应，代价是位置细节。
  • 平均池化（average pooling）——保留每个窗口的均值；更平滑，但会稀释单个强响应。
  • 全局平均池化（global average pooling）——把每个通道平均成一个数，常用来替代「铺平 + 全连接」头。

7.6 经典 CNN 结构各自解决了什么

CNN 的设计史，是一串具体的瓶颈，每一个都被一个思想解决。把它读成年表是常识题；把它读成「问题清单」，就是一套你以后会反复用到的设计词汇。

架构它面对的问题它引入的思想
LeNet网络到底能不能读出一个数字？那套模板本身：卷积与池化交替，再接一个小全连接头。体量小，足以应付 8×8 到 32×32 的数字图；本周的模型基本上就是它。
AlexNet真实的高分辨率彩色图像、类别众多；训练太慢且过拟合。往深、往宽走，用 ReLU 取代饱和型激活，用 Dropout 与数据增强压住过拟合——再加上 GPU 让它变得可负担。
VGG随意的卷积核尺寸让架构难以推理与复现。一套统一的配方：只用 3×3 卷积堆叠，块与块之间用池化。用简单、可重复的模式换深度，小核则压住参数开销。
ResNet超过一定深度后，加层反而让训练更差，而不是更好。跳跃连接（skip connection）：让一个块学习围绕恒等的残差，使梯度能穿过很深的堆叠。深度从「自我拆台」变成「可用」。

这里要的是思想，不是实现细节。本周的考核点不是「把 ResNet 写出来」，而是认出这四个架构各自解决了前一个架构造成的瓶颈——当你手上的模型训不动时，要找的正是那个瓶颈。

7.7 数据增强

数据增强（data augmentation）把变换后的训练输入副本喂给模型，它依赖「正确标签能在变换下存活」这一前提。这个前提精确且极易被忽略：该变换必须保持标签（label-preserving）。把数字水平翻转，会把 6 转向 9；垂直翻转会毁掉 9。不保持标签的增强并不增加信息——它在制造贴错标签的样本，同时看起来像个高级的正则化手段。

7.7.1 本实验用什么做增强

增强那一臂对训练批施加每个轴最多 1 个像素的随机平移；测试时输入不做任何改动。训练增强与测试探针用的是同一个函数，因此两者天然可比。

def shift_batch(imgs, dx, dy):
    """对 (n, 1, 8, 8) 批做零填充平移。既作训练增强，也作测试时扰动。"""
    out = torch.roll(imgs, shifts=(dy, dx), dims=(2, 3))
    if dy > 0:   out[:, :, :dy, :] = 0
    elif dy < 0: out[:, :, dy:, :] = 0
    if dx > 0:   out[:, :, :, :dx] = 0
    elif dx < 0: out[:, :, :, dx:] = 0
    return out


# 训练循环里，仅对增强那一臂
if arm == "cnn_aug":

    dy = int(torch.randint(-1, 2, (1,), generator=g))
    xb = shift_batch(xb.view(-1, 1, 8, 8), dx, dy).view(-1, 64)

付出：dx = 0 时 −3 个点（0.9808 → 0.9504）。
教训：增强没有提升上限，它把曲线压平了——用干净精度去换平移鲁棒性。这笔交易划不划算，问的是你的输入，不是模型。如果用户是拿手机拍的（输入会被平移），就买；如果输入已经被裁齐对齐，那你就是在白买。
关键术语
  • 数据增强（data augmentation）——生成标签不变的训练输入变换副本。
  • 保持标签的变换（label-preserving transform）——正确标签能在其上存活的变换；增强有效的前提。
  • 测试时扰动（test-time perturbation）——只在测量时施加的变换，用来探测鲁棒性，而不是用来训练。
  • 鲁棒性 / 干净精度权衡（robustness trade-off）——用未扰动测试集上的精度，换取扰动条件下精度的实测交换。

关键术语
  • 方案（arm）——被检验的一种配置，协议中其余所有因素都保持不变。

  • 均值 ± 标准差——本章所有数字的报告形式；单次运行的值不算结果。
  • 混淆矩阵（confusion matrix）——真类别与预测类别构成的表；对角线统计判对，每个非对角格子都是一次具体的混淆。

7.9 错分分析：从矩阵走到具体样本

「准确率 0.98」不是结论，是起点。错分分析（error analysis）是一门纪律：从一个聚合数字，一路走到模型具体错在哪些样本上，再走到一个关于原因、并且可以检验的假设。这正是课程标准明确要求的交付物：重点看模型到底错在哪类样本上。

7.9.1 方法，五步

打印混淆矩阵，而不只是准确率

0.9807 底下藏着 26 个错误，其中 12 个与数字 8 有关。准确率一个都没提；矩阵才是起点。

点名最差的类对，并给出次数

「8 被当成 1，三次」比「模型在某些类上表现较差」有用一百倍。次数重要，因为一次可能是噪声，三次可能已是模式。

取出具体样本，附上模型的概率

不是「它错了一些 8」，而是「真 8，判 7，置信 0.9829，真类概率 0.0144」。概率能把「犹豫」和「错了还自信」分开，而这两者需要不同的修法。

每条错误配一个可检验的假设

「这个 6 的下半环闭合了」是一个假设，而且可以检验：把下半环闭合的 6 收集起来，看是不是都被判成 8。这一步把一个故事变成了一个实验。

写出下一步，以及怎么判断有没有用

同一个切分、同一个指标、一次只改一处——全课程不变的这条规则。

一份完整错分分析的交付标准 只有一句聚合数字的报告，等于没做这件事。完整的报告必须同时包含：（1）打印出来的混淆矩阵本身；（2）点名的最差类对及其次数；（3）至少三个具体错分案例，各带模型在预测类与真类上的概率；（4）每条错误配一个可检验的假设；（5）下一个实验，以及判断它有没有用的准则。缺任何一条，都是本周报告最常见的失分方式。
关键术语
  • 错分分析（error analysis）——从聚合指标走到具体失败样本及其原因的过程。
  • 类对（class pair）——一个有序的（真类、预测类）对；混淆就是按它来计数的。
  • 置信 vs 真类概率——模型对它那个（错误）答案有多确定，对照正确类别分到了多少概率质量。
  • 可检验假设（testable hypothesis）——把原因写成「再做一次测量就能证伪」的形式。

7.10 GPU 显存管理与绿色计算

显存不足（out of memory, OOM）是本周实验里最常见的卡点，而它几乎从来不是硬件问题，而是批大小（batch size）的问题。正确的回应是先测量，再按一个明确的顺序处置，而不是下单买卡。

7.10.2 显存不足时的处置顺序

从上往下试。越往下，代价越大；最后两步已经不是「调参」，而是换硬件或换方案。

先把批大小减半（免费）

改变的是内存，不是数学。副作用是梯度更吵，用更多步数或更高学习率补偿。先做这一步，别先怀疑硬件。

梯度累积（免费）

不占内存就把等效批大小买回来。下面的实测：4 × 32 配对的权重写法能精确复现真 batch 128。你付出的是时间，不是精度。

混合精度（便宜，但不免费）

torch.amp.autocast 加 GradScaler，激活的存储减半。它改变数值，所以要重新确认指标没有漂。

梯度检查点 / 更小的输入（有代价）

用时间换内存，通常慢 20–30%。缩小输入分辨率会改变任务本身，改之前先想清楚你在测什么。

降模型规模，或承认这个任务本机做不了（最后）

买更大的 GPU 是最后一个选项，不是第一个。本周这个模型即使在批 1024 时峰值也只有 582.0 MB，永远不会 OOM——在申请算力之前，先算清楚你到底需要多少。

7.10.3 梯度累积：把等效 batch 买回来，但要付对价钱

梯度累积（gradient accumulation）把一个大的等效批拆成若干小的微批，累加它们的梯度，再走一步优化器。等效批 = 微批大小 × 累积步数——这里是 4 × 32 = 128。判定标准是每种权重写法能否逐种子复现真 batch 128。

权重写法精确形式与真 batch 128 的一致性
exactw = len(sel) / group_size5 / 5 完全一致
naivew = 1 / accum_steps3 / 5
unscaled不做缩放，也不做归约2 / 5
none不做缩放，梯度直接累加2 / 5

只有 exact 这一种能在五个种子上全部一致。原因很具体，值得说清楚：差异来自每个 epoch 最后一组微批的大小不等（n_train = 1258 无法被 64 × 累积步数整除，在探针里也无法被 32 × 4 整除）。只有按「每个微批在这一组里占的样本比例」——len(sel)/group_size——加权，累加出来的梯度才等于这一组的均值；而 naive 的 1/accum_steps 只在「所有微批一样大」时才等价。

对这条结论的一条诚实边界 naive 与 unscaled 在这里也大致收敛，是因为 Adam 对梯度的整体缩放不敏感——它按二阶矩做归一化，所以把每个梯度统一乘一个常数，几乎被它吃掉。这是优化器的性质，不是「可以不做加权」的许可。如果换成 SGD，这些差异会显著放大。所以正确的结论不是「加权无所谓」，而是「在 Adam 下这个错误被宽容了；换一个优化器就会暴露出来」。 
# 一组 `size` 个样本，被切成若干长度 len(sel) 的微批
if accum_mode == "exact":
    w = len(sel) / size          # 这个微批在组里占的样本比例
elif accum_mode == "naive":
    w = 1.0 / accum_steps        # 只在所有微批等大时才正确
else:                            # none / unscaled
    w = 1.0
(loss * w).backward()
绿色计算：算力是有限资源 同一份数据、同一个准确率，用少 9.07 倍的参数也能达到——而这是本章测出来的，不是喊出来的。参数就是账单：17226 个参数拿到 0.9785，1898 个拿到 0.9808，多出来的 15328 个权重在训练和推理时都要算、要搬、要供电。「用更少的成本达成目标」不是清高，它始于一句追问——这个规模是必要的吗？在申请算力之前先把峰值内存量出来；并且如实报告那些没起作用的优化：本周的增强让干净精度掉了 3 个点，只报平移实验那 29 个点，就是选择性汇报。
关键术语
  • 显存（GPU memory）——训练期间由激活、梯度和参数占用的内存；批大小缩放的就是它。
  • 显存不足（OOM）——申请量超过可用内存时抛出的错误；最常见的实验卡点。
  • 梯度累积（gradient accumulation）——在走一步优化器之前，先跨多个微批累加梯度，以在不占内存的前提下达到更大的等效批。
  • 等效 batch（effective batch）——微批大小 × 累积步数；也就是这次更新实际「看到」的批量。
  • 混合精度（mixed precision）——对大部分激活使用低精度算术，配合损失缩放让梯度保持可用。
  • 绿色计算（green computing）——以达成目标所需的最小算力来做设计，并如实报告没有奏效的优化。

六条要点
  1. 卷积不是「更强的层」，它是用局部性假设换来的参数效率。同一份数据上参数量差 9.07 倍，准确率差 0.0023——小于一个标准差，因此写「未观察到显著差异」。
  2. 先算形状，再写代码。输出尺寸公式 (in + 2p − k)/s + 1 与真实前向在每一阶段都一致；感受野沿 3 → 4 → 8 → 10 递推，第二层卷积就已经覆盖整张 8×8 图。
  3. 池化函数是选择，不是默认。最大对平均在参数量完全相同的情况下值 4.1 个点——好几个标准差。
  4. 增强买鲁棒性、付干净精度：dx = −1 处 +29 个点，dx = 0 处 −3 个点。要不要买，问的是你的输入会不会被平移——这是产品问题，不是模型问题。
  5. 「98%」不是结果。完整的错分分析有四件：混淆矩阵、最差类对及次数、带概率的具体案例、可检验的假设。本实验中剩下 26 个错误，12 个与数字 8 有关，最差类对是 8 → 1（3 次）。
  6. 显存不足时先降 batch，再用梯度累积把等效 batch 买回来；用「微批占组大小的比例」加权时，与真 batch 逐项一致（5/5）。并且如实报告没起作用的优化。

练习 1 · 手算参数量（必做）

  1. 用 k*k*C_in*C_out + C_out，算出 conv(1→8, 3×3) 与 conv(8→16, 3×3) 的参数量。（80 与 1168。）
  2. 加上线性头 64 → 10，给出 CNN 的总参数量。（80 + 1168 + 650 = 1898。）
  3. 算出 64-128-64-10 全连接网的总参数量，并给出它与 CNN 的比值。（17226；17226 / 1898 = 9.07 倍。）
  4. 全连接是 0.9785，CNN 是 0.9808，种子间标准差 0.0084。用一句话写出数据支持得起的结论。（未观察到显著差异；成就是参数量少了 9.07 倍，不是分数。）

练习 2 · 形状链路与感受野（必做）

  1. 8×8 输入依次通过 conv(3×3, s=1, p=1)、MaxPool(2, s=2)、conv(3×3, s=1, p=1)、MaxPool(2, s=2)。写出每一阶段后的特征图尺寸。（8、4、4、2。）
  2. 用 rf = rf + (k − 1) × jump 与 jump = jump × s，算出每一阶段后的感受野。（3、4、8、10。）
  3. 最后一层卷积的感受野是多少？在这份 8×8 数据上意味着什么？（8——它已经覆盖整张图，所以在这里再叠深度也无法增加平移不变性。）

练习 3 · 用代码验证公式（必做，动手改代码）

  1. 写出 out_size(size, k, s, p)，打印上面四个阶段的输出；再建出 CNN，在 model.body 的每一层之后打印 tuple(h.shape[1:])。确认公式与真实前向在每一阶段都一致。
  2. 把第一层卷积改成 padding=0，在运行前先预测四个特征图尺寸以及铺平维度会变成多少，然后运行核对。（6、3、3、1；铺平维度变成 16 × 1 × 1 = 16，线性头必须重建以匹配。）
  3. 把池化从 MaxPool2d 换成 AvgPool2d，其余保持不变。在训练之前，说明你预期哪个方案的测试准确率、以及为什么。（平均池化那一臂的 0.9400——它抹平了最强响应，值 4.1 个点。）

练习 4 · 读懂增强的账本（必做）

  1. 在 dx = −1 处，给出普通 CNN 与增强 CNN 的测试准确率，以及变化量。（0.6481 与 0.9415，约 +29 个点。）
  2. 在 dx = 0 处，给出同样两个数，以及变化量。（0.9808 与 0.9504，约 −3 个点。）
  3. 「增强改善了模型」——这个概括正确吗？用两句话解释，并说出真正决定「要不要用它」的那个问题。（不正确：它没有提升上限，而是把曲线压平了，用干净精度换鲁棒性。决定性的问题是：真实输入是否会被平移。）
  4. 在 dx = 0 处三者中哪一条最低？这说明了鲁棒性的代价是什么？（增强那一臂，0.9504——鲁棒性是用干净精度买的。）

练习 5 · 给出一份可操作的错分分析（必做）

  1. 从混淆矩阵里点名最差类对及其次数，并说出 26 个错误中有多少与数字 8 有关。（8 → 1，3 次；26 个错误里有 12 个与数字 8 有关，46.2%。）
  2. 对「真 8，判 7，置信 0.9829，真类概率 0.0144」这一案例，用一句话写出假设。（下半环被写断，于是这个数字读起来像 7。）
  3. 把这个假设变成一次可以执行的检验。（收集下半环被写断的测试 8，测量它们是否被不成比例地判成 7；或合成这类 8，测它们上的错误率。）
  4. 列出完整的错分分析报告必须包含的五项。（混淆矩阵；最差类对及次数；至少三个带概率的案例；每条配一个可检验假设；下一个实验及其准则。）

练习 6 · 复现，然后写错梯度累积（必做，动手改代码）

  1. 先用真 batch 128 训练一次 CNN，记录五个种子各自的测试准确率；再用 4 × 32 累积、权重 w = len(sel) / group_size 训练一次，逐种子比较。（五个全部一致——5/5。）
  2. 把权重改成 w = 1 / accum_steps 再跑。还有几个种子一致？其余为什么不一致？（3/5；每个 epoch 最后一组微批大小不等，naive 的均值在那一组上是有偏的。）
  3. 现在完全去掉加权（w = 1）再跑。几个一致？（2/5。）
  4. 用三句话解释：为什么写错权重的运行在 Adam 下仍然大致收敛，什么情况下会变。（Adam 按二阶矩归一化，所以梯度被统一缩放基本被它吃掉；换成 SGD 差异会显著放大，所以这份宽容是优化器的性质，不是可以省略加权的许可。）
