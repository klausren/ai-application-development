第 06 章 · 模块 2 · 第 6 周

模型评估、过拟合与正则化

第 5 周结束时，你手里有一个能跑通的训练循环，以及日志末尾的一个数字：验证损失。这一周要问的是工程师真正被雇来回答的那个问题——这个数字是真的吗？80 张训练图配一个 17226 个参数的网络，足以把训练准确率推到完美的 1.000；而它离那个诚实分数有多远，就是本章的全部主题。我们把评测工具搭起来（混淆矩阵、精确率、召回率、F1），把让分数可信的协议固定下来（划分、分层、交叉验证、泄漏），直接从损失曲线上读偏差-方差权衡，再用 PyTorch 实现四种正则化手段。章末是一个六方案、五种子的实测实验——它真正跑在笔记本 CPU 上，而它诚实的结论比「正则化提高了准确率」这句口号**更窄，也更有用**。

6.1 为什么训练集上的分数不算成绩单

第 5 周里，训练损失越低越是目标。这一周，它变成了警报。原因不是哲学问题，是算术问题。

6.1.1 每张图两百一十五个参数

本章全程使用的协议，是让一个 64-128-64-10 的多层感知机——共 17226 个参数——只吃 80 张训练图。也就是每个训练样本大约对应 215 个参数。一台可调数字比样本数还多的机器，有能力把这 80 个点精确记住，而它一定会这么做：损失曲面上的空间足够把每一个点都放到边界的正确一侧，却完全不需要学出一条能迁移到别处的规则。

本章的第一个测量 基线方案的训练准确率是 1.000，而验证准确率停在 0.856 ± 0.024。模型在训练集上不是「差不多对」，是完美；在没见过的数据上，大约每七张错一张。只有第二个数字才算成绩单。

6.1.2 三个划分，以及各自被允许做什么

实践中的混乱，很少来自指标怎么算，而来自在做某个决定的时候，你被允许看哪一份数据。三份数据，三种权限：

划分用途允许做的事禁止做的事
训练集拟合权重只做梯度更新报告任何最终指标——它是被直接优化的对象
验证集模型选择挑超参数、挑停止轮次、挑正则化强度当作最终结论——选的次数多了，它也被拟合了
测试集一次诚实的测量在模型冻结之后，评测一次任何决定，包括「我就再看一个想法」

第三行是最常被破坏的。每一次看测试集，都是一次用「测试集本该封存的信息」做出的超参数决定。看十次之后，测试集就变成了第四份、且被更严重过拟合的验证集。

6.1.3 本周的评测协议

本章后面出现的所有数字，都来自同一套固定协议，这样数字变化就只能来自被检验的那个改动：

冻结的协议
  • 数据。sklearn.datasets.load_digits——8×8 灰度手写数字，10 类，1797 张，随库自带，因此整个实验全程离线，不下载任何东西。像素缩放到 0–1。
  • 划分。70 / 15 / 15，分层，固定种子——约留下 270 张作验证集、270 张作测试集。
  • 训练子集。从训练池里只取 80 张。数据稀缺是刻意设计的：正因为它，过拟合才在 400 轮内而不是 40000 轮内显形。
  • 模型。MLP 64-128-64-10，输出原始 logits，17226 个参数——平均每张训练图约 215 个。
  • 优化。Adam(lr=1e-3)，批大小 32，最多 400 轮。
  • 重复。五个随机种子（42–46）；所有数字都以五种子的均值 ± 标准差报告，绝不用单次运行。
import torch, torch.nn as nn
from sklearn.datasets import load_digits
from sklearn.model_selection import train_test_split


def load_split(seed=42):
    """1797 张数字图缩放到 [0, 1]；分层 70 / 15 / 15。"""
    X, y = load_digits(return_X_y=True)        # 8x8 像素，10 类
    X = X / 16.0                              # 像素范围 0..16 变为 0..1
    Xtr, Xtmp, ytr, ytmp = train_test_split(
        X, y, test_size=0.30, random_state=seed, stratify=y)
    Xva, Xte, yva, yte = train_test_split(
        Xtmp, ytmp, test_size=0.50, random_state=seed, stratify=ytmp)
    return Xtr, Xva, Xte, ytr, yva, yte


class MLP(nn.Module):
    """64-128-64-10 —— 17226 个参数，只喂 80 张训练图。"""
    def __init__(self, p_drop=0.0):
        super().__init__()
        self.body = nn.Sequential(
            nn.Linear(64, 128), nn.ReLU(), nn.Dropout(p_drop),
            nn.Linear(128, 64),  nn.ReLU(), nn.Dropout(p_drop),
            nn.Linear(64, 10))                 # 原始 logits，不加 softmax

    def forward(self, x):
        return self.body(x)

分层在这里比第 5 周更重要。1797 张图分 10 类，若随意切出 80 张训练子集，很可能某类只有 6 张、另一类有 11 张，于是准确率曲线的起伏来自类别构成，而不是来自正则化。分层会保证每个划分——包括那 80 张子集——都保留整个训练池的类别比例。

关键术语
  • 泛化差距——训练表现减去验证表现。这里是 1.000 − 0.856 = 0.145，跨种子报 0.145 ± 0.024。
  • 容量——可调参数的个数，更准确地说，是模型所能表示的函数族有多丰富。
  • 参数/样本比——容量除以训练集大小；本章最有用的一个预警数字。
  • 留出集——训练开始之前就从训练池里物理移除的任何数据。
  • 模型选择——一切通过比较分数做出的决定：架构、学习率、轮数、正则化强度。
  • 分层划分——在每一部分中都保持整体类别比例的划分方式。

6.2 混淆矩阵：四个格子推出所有指标

准确率只有一个数，而一个数无法描述「会犯两种不同错误的分类器」。混淆矩阵把错误分开保存；本章的每一个分类指标，都只是它几个格子上的简单算术。

6.2.1 二分类决策的四个格子

格子含义在缺陷检测线上的对应
真正例（TP）预测为正，实际也为正真有缺陷，被正确拦下
假正例（FP）预测为正，实际为负良品被拒——一次误报
假负例（FN）预测为负，实际为正缺陷流向客户——一次漏检
真负例（TN）预测为负，实际也为负良品被正确放行

6.2.2 手算一遍

一百张图，其中三十张真有缺陷。模型把四十张判为有缺陷；这四十次标记里二十四种，十六次是误报；另外漏掉了六个缺陷。纯粹靠数格子：

量算法取值
准确率——模型整体上有多少次是对的？(24 + 54) / 1000.780
精确率——它一报警，有多准？24 / (24 + 16) = 24 / 400.600
召回率——真缺陷里，抓到了多少？24 / (24 + 6) = 24 / 300.800
F1——两者的调和平均2 · 0.600 · 0.800 / (0.600 + 0.800)0.686

同一个模型，四个数字，而其中只有第四个与第一个属于同一类量。准确率 0.780 与 F1 0.686 之间的差距，全部都是关于犯的是哪一种错的信息。

6.2.3 准确率悖论

如果正样本只占 4%，一个对所有样本都回答「负」的模型能拿到 96% 准确率，同时召回率为 0、毫无价值。准确率本质上是跨类的加权平均；当某一类占了 96% 的权重时，这个平均值描述的就是那一类，别的什么都没说。这也是为什么 6.1 节的泛化差距并不是唯一值得警惕的数字：任何一个作为「招牌」的指标，都要先检查它是否可以通过忽略你在乎的那一类而被抬高。

6.2.4 读十类矩阵

十个数字类别时矩阵是 10 × 10，读法不变：对角线是判对，每个非对角格子都是两个具体类别之间的一次具体混淆。真正有价值的问题从来不是「准确率多少」，而是「哪些格子里有质量，这些对子看起来像不像？」——一个数字被误读成它最像的那个数字，与一个数字被随机误读，是两个完全不同的工程问题。

import numpy as np
from sklearn.metrics import confusion_matrix, classification_report

y_true = yte.numpy()
y_pred = net(Xte).argmax(dim=1).numpy()          # dropout 已经关掉

cm = confusion_matrix(y_true, y_pred)            # 行是真类别，列是预测类别
print(cm)
print("accuracy = %.3f" % (cm.trace() / cm.sum()))

off = cm.copy()
np.fill_diagonal(off, 0)                              # 只留下错误
print("最常见的混淆：", np.dstack(
    np.unravel_index(np.argsort(off.ravel())[::-1][:5], cm.shape))[0])

print(classification_report(y_true, y_pred, digits=3))
三种平均，各一句话 宏平均（macro）对每个类的指标等权平均——它把稀有类看得和常见类一样重要。加权平均（weighted）按类别频率加权，因此在平衡数据上会收敛到准确率。微平均（micro）先把所有决策汇总再算一个指标，在单标签问题上恰好就是准确率。一份只给出三者之一的报告，等于替你做了优先级选择。
关键术语
  • 混淆矩阵——真类别与预测类别构成的表；对角线统计判对的次数。
  • 真正例 / 假正例 / 假负例 / 真负例——四个格子，按（预测、真实）是否一致命名。
  • 准确率——所有决策中判对的比例，被最大的那个类主导。
  • 支持数（support）——某一类真实样本的个数，也就是它在加权平均里的权重。
  • 宏 / 加权 / 微平均——把逐类指标压成一个数的三种方式，隐含三种不同的优先级。
  • 准确率悖论——在类别不平衡的数据上，一个没用的分类器报出很高准确率的失效模式。

6.3 精确率、召回率与 F1：把业务代价写进公式

精确率与召回率不是同一个品质的两个视角，而是同一条决策边界的两种代价。你该保护哪一个，说的是后果，不是数学。

6.3.1 三个公式，各自拒绝隐藏什么

指标公式它回答的问题它忽略的东西
精确率TP / (TP + FP)我标记出来的东西里，有多少是真的？所有我没标记的
召回率TP / (TP + FN)所有真实存在的里，我找到了多少？我制造的每一次误报
F12 · P · R / (P + R) = 2TP / (2TP + FP + FN)当两者都重要时，哪一个数还能站得住？真负例——刻意忽略，因为它不构成一次决策

F1 用的是调和平均而不是算术平均，这个选择正是重点：0.9 与 0.1 的调和平均是 0.18，算术平均是 0.5。一个「什么都抓、每抓一个真缺陷顺手报出一千次误报」的模型，无法靠精确率把自己买回来——F1 会向两者中更差的那个塌缩，而这正是一个指标在两种代价都真实时该有的行为。

6.3.2 在两者之间取舍是一个代价决策

场景假正例的代价假负例的代价该保护谁
垃圾邮件过滤一封重要邮件被埋进垃圾箱一封垃圾邮件进了收件箱通常是精确率
癌症筛查一次不必要的复查一次漏诊几乎总是召回率
工业缺陷检测良品被报废缺陷被出货先召回率，再精确率
视频推荐一次糟糕的推荐一个内容永远没被看到看哪个更伤害参与度
误区：「把 F1 最大化就对了」 当两类错误的代价相当，F1 是个合理的默认值；当它们不相当，F1 就是个坏指标。在筛查场景里，召回率 0.80 配精确率 0.30 可能正是正确的工程选择，而它 0.44 的 F1 在看不懂代价表的人眼里糟糕透顶。先把代价说清楚，再选指标——绝不能反过来。

6.3.3 阈值就是旋钮

输出概率的分类器，靠一个阈值把概率变成决策；移动这个阈值，就是确定性地用一种错误去换另一种：调高，精确率上升、召回率下降；调低，反之。模型本身一点没变。这就是为什么「我们的模型精确率 92%」是一句没说完的话：它缺了工作点，而工作点属于替错误付账的那个人。

from sklearn.metrics import precision_recall_fscore_support

# 逐类的精确率 / 召回率 / F1 以及该类支持数
p, r, f1, sup = precision_recall_fscore_support(
    y_true, y_pred, average=None, zero_division=0)
for c in range(10):
    print(f"class {c}:  P={p[c]:.3f}  R={r[c]:.3f}  F1={f1[c]:.3f}  n={sup[c]}")

# 同一件事的三种压法——它们不可互换
for how in ("macro", "weighted", "micro"):
    P, R, F, _ = precision_recall_fscore_support(
        y_true, y_pred, average=how, zero_division=0)
    print(f"{how:8s} P={P:.3f} R={R:.3f} F1={F:.3f}")
一个值得养成的报告习惯 报告逐类表格，而不只是那几个平均值。在十类问题上，本章协议下宏平均 F1 大约 0.86，完全可以掩盖某一类只有 0.60——而那一类通常才是有意思的发现。平均值是一种概括，而一个不能被拆开的概括不是证据。
关键术语
  • 精确率——正类预测中判对的比例；度量误报的代价。
  • 召回率（灵敏度）——真实正样本中被找出的比例；度量漏检的代价。
  • F1 分数——精确率与召回率的调和平均，被两者中较小的那个拉低。
  • 调和平均——倒数的平均的倒数；与算术平均不同，它无法靠抬高其中一项来变好。
  • 决策阈值——作用在分数或概率上、用来产生类别的那一刀；它是换取精确率与召回率的旋钮。
  • 逐类指标——针对某一类对其余所有类计算的精确率、召回率与 F1，这才是多分类问题被真正评测的方式。

6.4 评估协议：划分、分层、测试集只碰一次

指标是否可信，取决于产出它的协议。两名同学在同一份数据上跑同一个模型，可以诚实地报出 0.91 和 0.84，差别完全活在协议里。

6.4.1 六条规则，按顺序

先划分，再看任何东西

划分发生在第一张图、第一个直方图、第一句「我先看看类别分布」之前。在全量数据上算出统计量、并据此做出任何决定的那一刻，泄漏已经发生了。

分层

传 stratify=y，让每一部分都保持类别比例。类别样本很少时，一个不分层的划分带来的指标变化会大于模型本身带来的变化。

固定并报告种子

传 random_state=，并把它打印进日志。一个无法复现的划分，会让下游所有数字都不可复现。

所有变换只在训练部分上拟合

缩放、填补、特征选择、重采样、目标编码。在全部 1797 行上拟合 scaler 再划分，是学生项目里最常见的泄漏，而且它永远不报错。

在验证集上选择，在测试集上报告——只报一次

架构、学习率、轮数、正则化强度：全部在验证集上决定。测试集在模型冻结之后才打开，它给出的那个数字，就是你要公布的数字。

跨种子报均值 ± 标准差

本章每个方案都在五个种子（42–46）上跑并给出离散度。单次运行是轶事；离散度才是测量精度——6.8 节会展示，正是它决定了你有资格说什么。

6.4.2 协议静默失效的三种方式

失效方式看起来像什么为什么这个数字是错的
反复使用测试集「我们试了十二种配置，最好的测试准确率是 0.91。」测试集参与了十二次决策，所以它已经是验证集；0.91 是十二次抽样的乐观最大值，不是估计量。
用测试分数挑最好轮次「我们报告看起来最好的那一轮的测试分数。」早停本身就是一次超参数选择；在测试集上做它，等于把测试集变成了停止准则——它带来的过拟合多于它消除的。
只报最好的那个种子「五个种子里最高到 0.8926。」五次带噪声运行的最大值是向上偏的。均值是 0.874 ± 0.011；「最高到」是另一个统计量，一个更好看的统计量。
误区：「划分能复现就够了」 同一个划分、换一个权重初始化种子，就是另一个实验——本协议正是证据：同一个增强方案在一个种子上是 0.8074，在另一个种子上是 0.8333；同一个 Dropout 方案在几种子间的跨度是 0.8185 到 0.9000。可复现性必须同时覆盖划分、初始权重和批次顺序，而处理残余波动的诚实做法是把它测出来、报出来——不是用一次幸运的运行把它藏起来。
关键术语
  • 评估协议——一个分数所依附的、固定的划分、拟合、选择与报告流程。
  • 训练 / 验证 / 测试划分——三种角色，以及三套被允许的操作。
  • 复现种子——让划分或初始化可重复的固定随机状态。
  • 乐观偏差——报告多次运行或多组配置中最优值所引入的向上误差。
  • 在验证集上选择——把所有选择都放在测试集从未影响过的数据上做的纪律。

6.5 K 折交叉验证与数据泄漏

一次划分只给出一个数，而在小数据上这个数自带很大的误差条。本章协议的训练子集只有 80 张；把其中几张从训练挪到验证，验证准确率就会变化几个百分点，而模型一点没改。交叉验证是标准答案：用多次划分的平均值，取代对一次的信任。

6.5.1 K 折，以及你应该总是使用的分层变体

把训练池切成 K 份。用其中 K−1 份训练、剩下 1 份评测，轮流进行直到每份都当过验证集，再把 K 个分数平均。每个样本恰好被验证一次、被训练 K−1 次。十个类别时请用 StratifiedKFold：普通的 KFold 可能让某一折里完全没有某个类，此时的指标衡量的不是模型，而是折的分配方式。

from sklearn.model_selection import StratifiedKFold
from sklearn.preprocessing import StandardScaler
from sklearn.pipeline import make_pipeline
from sklearn.linear_model import LogisticRegression

skf = StratifiedKFold(n_splits=5, shuffle=True, random_state=42)
scores = []

for fold, (tr, va) in enumerate(skf.split(Xtr_pool, ytr_pool)):
    pipe = make_pipeline(StandardScaler(), LogisticRegression(max_iter=1000))
    pipe.fit(Xtr_pool[tr], ytr_pool[tr])            # scaler 在折内拟合
    s = pipe.score(Xtr_pool[va], ytr_pool[va])
    scores.append(s)
    print(f"fold {fold}: {s:.4f}")

print(f"CV mean = {np.mean(scores):.4f} +/- {np.std(scores):.4f}")

代价必须诚实说出来：K 折大约是单次训练的 K 倍时间。这是「带方差估计的指标」的价格，也正是交叉验证用于模型选择、而不是用于每一次实验的原因。

6.5.2 泄漏就是任何让验证集看到答案的东西

泄漏它怎么发生为什么你看不见
预处理泄漏在全部数据上拟合缩放器、填补器或特征选择器，然后再划分代码跑得通；只是分数稍微好了一点
重复样本泄漏同一行或近乎相同的行同时出现在训练集和验证集里模型看起来在泛化，其实只是在回忆见过的那一行
测试集泄漏用测试分数去挑配置报出来的数字变好了，而这感觉像是进步
时间泄漏时序数据在划分前被打乱，于是模型用未来训练随机划分是默认行为，而默认感觉是中立的
目标泄漏某个特征由「标签已知之后才能得到的信息」算出该特征看起来完全正当，而且预测力极强——因为它把答案编了进去
分组泄漏来自同一来源的多行（同一张图、同一个传感器、同一个人）落在划分的两侧只有尊重分组时样本才独立；行数会骗人
一个问题的自检 对每一个接触数据的步骤，问一句：这一步在线上推理时，只用当时可得的信息，能不能执行？如果答案是不能，这一步就必须放在折内、只在训练部分上拟合。用 Pipeline 是把这件事变成结构上成立、而不是靠记性的最省事做法。
误区：「交叉验证可以替代测试集」 不能。交叉验证回答的是「这个分数在训练池的不同划分之间有多稳」，这是一个关于模型选择的问题。测试集回答的是「冻结后的模型，在从未被任何决策碰过的数据上表现如何」，这是一个关于报告的问题。用交叉验证去选择，用测试集去陈述，且只陈述一次。
关键术语
  • K 折交叉验证——轮转 K 份划分，使每个样本恰好被验证一次；K 个分数的均值和标准差都要报告。
  • 分层 K 折——在每一折中保持逐类比例的 K 折；分类任务的默认选择。
  • 数据泄漏——任何在训练或选择期间到达模型、而在预测时不可得的信息。
  • 预处理泄漏——在被后续用作验证的数据上拟合了变换。
  • 分组泄漏——相关的行被拆到训练与验证两侧，于是验证分数衡量的是记忆而非泛化。
  • Pipeline——把预处理与模型绑定在一起的构造，使得拟合模型的同时也在正确的子集上拟合了预处理。

6.6 偏差-方差权衡：从曲线读诊断

欠拟合与过拟合不是两个无关的问题，而是同一个旋钮的两端，而这个旋钮有名字：模型容量相对于它所拟合的数据有多大。

6.6.1 一个分解，两种失败模式

训练后模型的期望误差分解成三部分：偏差（模型族中最优函数本身的误差，也就是它太简单）、方差（拟合结果对它恰好看到哪一批训练样本有多敏感）、以及不可约噪声（没有任何办法消除）。增加容量降偏差、升方差；减小容量则相反。由此得到一条实用规则：

规则 欠拟合靠加容量或训练更久解决；过拟合靠加数据或约束模型解决。把这两个动作用反，一定会让情况更糟——而区分它们，恰恰是两条损失曲线存在的意义。

6.6.2 从日志里读出的四种形态

训练损失验证损失诊断正确的动作
高，下降很慢高，且贴近训练损失欠拟合——容量或训练时长不足换更大的模型、加轮次、提高学习率
下降到低位后走平下降到低位后走平拟合良好——两条曲线互相跟随停下；或加数据把两者一起压低
降到接近零先降，然后掉头上升过拟合——模型在背诵正则化：早停、权重衰减、Dropout、加数据
锯齿状，无趋势锯齿状，无趋势不是容量问题——通常是学习率或循环的 bug回到第 5 章，检查 zero_grad()

第三行是最费时间的一行，因为「验证损失掉头上升、而验证准确率纹丝不动」是常态，不是特例——下一小节就是实测证据。

本章立论所依赖的结论 在这个实验里，过拟合唯一可靠的证据是验证损失掉头上升。验证准确率看不到退化，原因是天花板效应：它的上限是 1.0，本身又已经横盘在 0.856 ± 0.024，于是模型对错误答案越来越自信这件事，在一个只统计「是否越过阈值」的指标上完全不会体现。只看准确率的同学会得出结论：跑 400 轮和跑 85 轮等价。损失曲线证明并非如此——上升幅度是 +0.155 ± 0.089，而最佳轮次是 85 ± 17。

这也定义了 6.7 节要用的停止准则：最佳轮次是验证损失最小的那一轮，而不是验证准确率最高的那一轮。在这份数据上两个准则有时会不一致，而损失准则才是那个仍然看得见差别的准则。

关键术语
  • 偏差——模型族中最优函数的误差；偏差高意味着欠拟合。
  • 方差——训练样本一换，拟合出的模型变化多大；方差高意味着过拟合。
  • 不可约误差——任何容量的模型都无法消除的噪声底。
  • 欠拟合——两条损失都高且彼此贴近；模型没有学到本就存在的结构。
  • 过拟合——训练损失接近零而验证损失掉头上升；模型学到的是样本，不是结构。
  • 天花板效应——指标饱和，因而不再能记录进一步的退化。
  • 最佳轮次——验证损失最小的那一轮，被用作停止与报告的时点。

6.7 四种正则化手段

正则化是任何让模型更难把容量花在「背诵」上的约束。下面四种是标准工具箱，它们的区别在于约束什么：训练时长、权重量级、哪些单元可以互相共谋，或者模型被允许看到什么样的输入。

6.7.1 早停——约束训练时长

最简单的正则化不需要改动模型。每个 epoch 记录验证损失，记住最好的权重，当损失连续 patience 轮没有改善时停止——然后恢复最佳权重，而不是保留最后一轮的权重。

best, best_ep, best_state = float("inf"), -1, None

for ep in range(1, epochs + 1):
    net.train()                                  # 打开 dropout
    for i in range(0, len(Xsub), 32):
        xb, yb = Xsub[i:i + 32], ysub[i:i + 32]
        opt.zero_grad()
        loss = criterion(net(xb), yb)
        loss.backward()
        opt.step()

    net.eval()                                   # 每次测量前都要关掉 dropout
    with torch.no_grad():
        v_loss = criterion(net(Xva), yva).item()

    if v_loss < best - 1e-4:                  # 严格改善
        best, best_ep = v_loss, ep
        best_state = {k: v.clone() for k, v in net.state_dict().items()}
    elif patience and ep - best_ep >= patience:
        break                                    # 停止训练，保留最佳权重

net.load_state_dict(best_state)                 # 恢复，不要用最后一轮

在本协议上的实测：patience=20 把运行从 400 轮压缩到 105 ± 17 轮——大约只用掉四分之一的预算——同时把验证损失的上升压到 +0.018 ± 0.016，而基线是 +0.155 ± 0.089。这大约是九倍的下降，而它唯一的来源就是「更早停下」。

6.7.2 权重衰减——约束权重量级

L2 正则化在损失上加一项与权重平方成正比的惩罚，在梯度更新里表现为对所有权重的一股小小的「拉向零」的力。在 PyTorch 里，它只是优化器的一个参数：

# 权重衰减是优化器的参数，不是一个层
opt = torch.optim.Adam(net.parameters(), lr=1e-3, weight_decay=1e-2)

从机理上看，被迫把权重保持得很小的模型，无法围绕每一个训练点刻出一圈尖锐的边界，它被推向更平滑、更小幅的解。实测的印记在曲线上清清楚楚：最佳轮次从基线的 85 ± 17 移到加衰减后的 262 ± 76；在种子 42 的曲线上，验证损失在 0.5794 到 0.6261 的窄带内来回，最后收在 0.5956——它从未掉头，而基线是触底 0.6357 后一路爬到 0.8672。损失上升幅度是 +0.027 ± 0.014，基线是 +0.155 ± 0.089。

强度怎么选 对 Adam 家族，1e-2 是个合理的起点；权衡在本实验里看得见——衰减太强会把模型从「缓慢过拟合」推成「缓慢学习」。请把它理解成一个调节「验证最低点出现得多晚」的旋钮，而不是一个把过拟合关掉的开关。

6.7.3 Dropout——约束谁可以和谁共谋

Dropout 在训练时的每次前向上随机把比例 p 的激活置零，于是任何单元都不能依赖某个特定伙伴的存在。评测时什么都不丢；取而代之的是把输出缩放，使期望激活保持不变。PyTorch 内部已经处理了缩放，这意味着你唯一必须做对的事情，就是切换模式。

net = MLP(p_drop=0.3)                # 每个 ReLU 后面接 nn.Dropout(0.3)

for epoch in range(epochs):
    net.train()                     # dropout 生效——前向是随机的
    train_one_epoch(net, opt, criterion)

    net.eval()                      # dropout 关闭——推理是确定性的
    with torch.no_grad():
        val_metrics = evaluate(net, Xva, yva)
整个模块的头号 bug 来源 忘写 net.eval()（或评测时一直停在 net.train()），意味着每一次验证和测试的测量都是在随机丢掉一部分激活的状态下做的。它不会崩。数字只是偏低，而且更糟的是——每次调用都不一样，于是同学把它诊断成「训练不稳定」，跑去查学习率、架构和数据，而这三者谁都没错。对称的另一个 bug 同样常见：评测后忘了写回 net.train()，下一个 epoch 的 dropout 就是静默关闭的，日志上却仍写着它在生效。在第 5 周那个既没有 dropout 也没有批归一化的 MLP 上，这两个调用什么都不做——这正是为什么这个习惯要在它还不起作用的时候先养成。

Dropout 在 p=0.3 下是最需要仔细读数的方案。它的验证损失上升是 +0.171 ± 0.102——六个方案里最大的，不是最小的——而它的最佳轮次波动极大，是 163 ± 100。它的测试准确率 0.884 ± 0.011 高于基线的 0.878，但差距是 0.006，只有基线自身标准差 0.012 的一半。6.8 节给出这个事实的后果。

6.7.4 数据增强——约束模型的输入

数据增强把变换后的训练输入副本喂给模型，教它「标签在这个变换下不变」。它有效有一个精确且极易被忽略的前提：该变换必须保持标签。把数字水平翻转会把 6 变成更像 9 的东西；垂直翻转会毁掉 9；旋转 180 度则改变了它是哪个数字。不保持标签的增强并不增加信息——它在制造错标签，一边拖慢训练，一边看起来像个高级的正则化手段。

def augment(xb, sigma=0.15):
    """在 8x8 图上加高斯噪声并随机平移 ±1 像素。"""
    xb = xb.view(-1, 1, 8, 8)
    shift = torch.randint(-1, 2, (2,), device=xb.device)   # dx, dy 取 {-1,0,1}
    xb = torch.roll(xb, shifts=(int(shift[0]), int(shift[1])), dims=(2, 3))
    xb = xb + sigma * torch.randn_like(xb)
    return xb.clamp(0.0, 1.0).view(xb.size(0), -1)

实测下来，这个变换在这里是有害的：训练准确率从 1.000 掉到 0.960 ± 0.027，测试准确率从 0.878 ± 0.012 掉到 0.824 ± 0.010。两条曲线一起下移，是欠拟合的特征，而不是正则化成功的特征。6.8 节解释为什么 8 × 8 图像是不该做像素平移的地方。

6.8.3 数据真正支持的四个结论

1 · 正则化压住的是验证损失的上升，不是提高准确率 六个方案的验证准确率全落在 0.716 到 0.858 之间，测试准确率之间的差异全部落在一个标准差以内（测试准确率的标准差在 0.010 到 0.024 之间）。早停与权重衰减真正改变的是验证损失的上升幅度——从 +0.155 ± 0.089 降到 +0.018 ± 0.016 与 +0.027 ± 0.014——以及最低点出现的轮次（85 ± 17 对 262 ± 76）。说「正则化提高了准确率」是对这些数字的误读。
2 · 在 8×8 图像上，增强与组合方案有害——是欠拟合，不是过拟合 数据增强把测试准确率从 0.878 拉到 0.824，把训练准确率从 1.000 压到 0.960；三者叠加的组合方案则崩到测试 0.740、训练准确率 0.875 ± 0.048。这两个差距都超过基线标准差的四倍，而且——这一点是决定性的——两条损失一起下移，这正是欠拟合模型的印记，而不是被良好正则化的模型。机理是具体的：一张 8×8 的数字图就是 64 个像素的笔画；把它平移 ±1 像素，等于让笔画在画面中移动了相当可观的比例、并把「这是哪个数字」模糊掉，于是这个增强制造的是贴错标签的样本，而不是同一个数字的新视角。增强是有力的工具，但它要求那个不变性真的成立——而在这种分辨率下它不成立。
3 · 单次运行的差异可能是噪声 同一处改动、同一份代码，跨种子的结果波动可达 ±3 个百分点——Dropout 方案的测试准确率从 0.8667 到 0.8963，增强方案从 0.8074 到 0.8333。在这个背景下，Dropout 的 0.884 ± 0.011 对基线的 0.878 ± 0.012，差值是 0.006——小于一个标准差。唯一站得住的说法是「未观察到显著差异」，而不是「Dropout 更好」。任何「方案 A 胜过方案 B」形式的结论，都要求 A 的差距越过 B 的离散度，而单个种子无法确立这一点。
4 · 过拟合的唯一可靠证据是验证损失掉头上升 训练准确率从第 61 轮起被钉在 1.000，验证准确率横盘在 0.856 ± 0.024，而验证损失从最低点一路爬到 0.8672。由于准确率指标已经饱和——天花板效应——这个退化在算术上无法出现在它身上。只看准确率，会把「85 轮」和「400 轮」判定为等价；损失曲线则显示出 +0.155 ± 0.089 的上升，以及方案层面 85 ± 17 的最佳轮次。这就是本章把停止准则定为「验证损失最小」的原因。

这个实验建议的报告模板 6.8.3 的每一条主张都是同一个形状：一个数字、一个离散度，以及一句「离散度是否盖住了差异」的判断。「Dropout 拿到 0.884」不是结果。「Dropout 在五个种子上是 0.884 ± 0.011，基线是 0.878 ± 0.012，差值 0.006 小于两个标准差中的任何一个，因此未观察到显著差异」才是结果——而且当别人重跑这份代码时，它依然成立。
关键术语
  • 方案（arm）——被检验的一种配置，协议中其余所有因素都保持不变。
  • 种子重复——在多个随机种子上重复同一方案，使离散度而不是单次运行成为测量结果。
  • 均值 ± 标准差——本章所有数字的报告形式；单次运行的值不算结果。
  • 配对差值——逐种子比较两个方案，比比较两次运行各自的均值更灵敏。
  • 欠拟合——训练与验证指标一起下移；这正是本实验中增强与组合方案的诊断。
  • 主张强度——小于离散度的差异只能支持「未观察到显著差异」这条规则。

练习 5 · 设计你有资格做出的主张（必做）

你想主张「Dropout 在这份数据上提高了测试准确率」。

  1. 用实测值——Dropout 0.884 ± 0.011、基线 0.878 ± 0.012，各五个种子——写出数据所能支持的最强主张。（「未观察到显著差异」：0.006 的差距小于两个标准差中的任何一个。）
  2. 设计一个足以支持更强主张的实验：多少个种子、哪一种划分、哪个指标，以及你会怎么处理测试集。（加到种子数使差值标准误远小于效应量；训练前就固定一个分层划分；决定做出后才打开测试集一次；比较逐种子的配对差值，而非两个均值。）
  3. 说出一个会让比较更灵敏的协议改动，以及一个会让它更不可信的改动。（更灵敏：增加训练数据，降低两个方案的方差。更不可信：挑最好的种子，或反复用测试集测量。）
六条要点
  1. 训练分数完美、验证分数平庸，不是一个「运气不好的好模型」——17226 个参数对着 80 张图，就是一台背诵机器，只有留出的那个数才算成绩单。
  2. 混淆矩阵先行；准确率、精确率、召回率与 F1 都是它四个格子上的算术。准确率会被任何类别不平衡击穿，而 F1 刻意向精确率与召回率中更差的那个塌缩。
  3. 先信协议，再信数字——分层划分、固定种子、预处理在折内拟合、交叉验证用来选择、测试集只打开一次用来陈述。
  4. 过拟合要从验证损失掉头上升读出来，绝不要从准确率上读。当指标已经饱和在 0.856 时，准确率曲线在算术上就无法显示损失曲线所显示的 +0.155 ± 0.089。
  5. 四种正则化手段分别约束训练时长、权重量级、单元间的共适应与输入。实测中，早停（+0.018 ± 0.016）与权重衰减（+0.027 ± 0.014）压住了损失上升；增强与组合方案则因欠拟合而把事情弄坏。
  6. 跨种子报均值 ± 标准差，只主张那些越过离散度的差异。Dropout 的 0.884 ± 0.011 对基线的 0.878 ± 0.012，差 0.006——未观察到显著差异，这是一个结论，不是一次失败。
