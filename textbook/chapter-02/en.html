PyTorch Fundamentals: Tensors and Autograd

In PyTorch, data, parameters, gradients and losses are all tensors — one container, one engine. This chapter teaches the container (shape, dtype, device, requires-grad, grad) and the engine (the computational graph and reverse-mode differentiation), then uses only those two things to learn a straight line by gradient descent. It also covers the one class of bug this course cares about most: the shape error that raises nothing and gives a wrong answer.

2.1 Tensors as the Universal Container

Chapter 1 described the pipeline; this chapter opens the toolbox. Everything you will pass between the stages of that pipeline — a batch of inputs, a weight matrix, a loss, a gradient — is a tensor.

2.1.1 What a Tensor Is

A tensor is an n-dimensional array with three extra capabilities: it carries its own shape and dtype, it can live on a GPU, and it can be differentiated.

0-D — scalar

A single number, e.g. a loss value. Produced by .mean() or .sum(). You call .backward() on one of these.

1-D — vector

A row of features for one sample, or a bias vector. Shape (n,). This shape is the source of half the pitfalls in this chapter.

2-D — matrix

A batch of samples, (n_samples, n_features). The workhorse of every tabular and linear model.

3-D and above

Images (batch, channels, height, width), sequences (batch, time, features). Same rules, more dimensions to get wrong.

2.1.2 Why Not a Python List

Python listtorch.Tensor
SpeedLoops run element by element in the interpreterVectorised kernels in C++/CUDA — one to two orders faster
ShapeNested lists have no shape; nothing checks lengths for youA torch.Size that every operation validates
BroadcastingDoes not exist — you write the loopsBuilt in, with stated rules (and its own failure mode)
DeviceCPU only.to("cuda") moves it to a GPU
GradientsNot supportedAutograd tracks operations automatically

2.1.3 The Relation to NumPy

x = np.ones(3)
t = torch.from_numpy(x)     # shares memory — no copy
t[0] = 9.0
print(x[0])              # 9.0 — the array changed too

t2 = torch.tensor(x)        # copies instead
arr = t2.numpy()            # back to NumPy, for matplotlib
One-liner A tensor is a NumPy array plus two things: it can run on a GPU, and it can be differentiated. The shared-memory behaviour of from_numpy is worth remembering precisely because it is silent.

2.1.4 GPU Tensors

device = "cuda" if torch.cuda.is_available() else "cpu"
X = torch.randn(100, 1).to(device)
w = torch.zeros(1, 1, requires_grad=True, device=device)

# moving data and parameters together is your responsibility
print((X @ w).device)     # cuda:0 — the result stays on the GPU

Two tensors must be on the same device to be combined. Mixing CPU and GPU raises a RuntimeError immediately — one of the few errors in this chapter that is genuinely helpful. Running on CPU is perfectly acceptable in this course; what is not acceptable is not knowing which device you used.

2.2 The Five Attributes

Get any one of these wrong and nothing crashes. The program runs, the loss prints a number, and the number is meaningless. This is why the habit below is worth more than any trick in the chapter.

2.2.1 Reading a Tensor

The habit On any shape error, or whenever a result looks wrong, print first: print(x.shape, x.dtype, x.device). Nine out of ten tensor bugs show up in that one line. This is not debugging; it is a default.

2.2.2 Creating Tensors

import torch

t = torch.tensor([[1., 2.], [3., 4.]])   # from Python data
z = torch.zeros(2, 3)                    # all zeros
o = torch.ones(2, 3)                     # all ones
r = torch.randn(2, 3)                    # standard normal
a = torch.arange(0, 6)                   # 0..5 — int64 by default
l = torch.linspace(0, 1, 5)              # 5 evenly spaced points

print(t.shape, t.dtype, t.device)
# torch.Size([2, 2]) torch.float32 cpu

print(a.dtype)                            # torch.int64
print(torch.arange(6.).dtype)             # torch.float32 — one dot
print(round(r.mean().item(), 2))          # about 0.00
print(round(r.std().item(), 2))           # about 1.00
Trap torch.arange(0, 6) is int64, so requires_grad=True on it raises. In training code write torch.arange(6.): a single decimal point makes it float32. The same trap appears as y = 3.0 * X + 2.0 where 2.0 quietly keeps the tensor floating-point.

2.3 Shape Manipulation and Broadcasting

This section contains the only class of failure in the chapter that produces no error at all. It deserves the most attention, not the least.

2.3.1 Three Families of Shape Operations

FamilyOperationsWhat to know
Change the shapeview, reshape, -1view shares memory and requires contiguity; reshape copies when it must — use it by default. -1 means "infer this dimension"; all others must divide evenly.
Add or remove a dimensionunsqueeze, squeezeunsqueeze(1) turns (n,) into (n,1) — the most common rescue in this course. squeeze only removes dimensions of size 1.
Swap axestranspose, permuteAfter an axis swap the tensor is usually non-contiguous, so view fails. Use .contiguous().view(...) or reshape.
x = torch.arange(6.)           # (6,)
a = x.view(2, 3)               # (2,3) — shares memory with x
x[0] = 99.
print(a[0, 0])                 # 99.0 -> a view, not a copy

t = a.t()                      # (3,2), now non-contiguous
# t.view(6)                    # RuntimeError: view size is not compatible
print(t.reshape(6).shape)         # (6,) — reshape copies, so it works

print(x.reshape(2, -1).shape)       # (2, 3)
print(x.unsqueeze(1).shape)         # (6, 1) — what MSE broadcasting wants

2.3.2 The Broadcasting Rules

Align from the right

Compare the two shapes starting at the rightmost dimension and walk left.

Equal sizes align directly

Dimension sizes that match are paired as they are.

A dimension of 1 stretches

If one of the two is 1, it is copied along that dimension to match the other.

Neither 1 nor equal raises

This is the good kind of error. It stops you before you compute something meaningless.

w = torch.randn(3)         # (3,)
X = torch.randn(4, 3)      # (4,3)
print((X + w).shape)       # (4,3) — w copied onto every row: intuitive

v = torch.randn(3, 1)      # (3,1)
print((v + w).shape)       # (3,3) — silently larger. This is the bug.

print(torch.broadcast_shapes((3, 1), (3,)))
# -> (3, 3): legal by the rules, and not what you meant

w2 = w.reshape(-1, 1)            # write the intent into the shape
print((v + w2).shape)      # (3,1) — what you actually wanted
The rule behind the rule Broadcasting guarantees legality, not intent. The engine will happily produce a shape you never wanted, without a warning. Writing reshape(-1, 1) is partly about correctness and mostly about making the code explain itself.

2.3.3 Silent Wrong vs Loud Error

Sort the failures you meet into these two columns; spend your attention on the left one.

ExpressionResultRaises?Why
X (4,3) + w (3,)(4,3)noRight-aligned; w is copied onto every row — intended
v (3,1) + w (3,)(3,3)no — silent(3,1) spreads down columns, (3,) across rows; an extra dimension appears
v + w.reshape(-1,1)(3,1)noThe intent is written into the shape
X (100,1) @ w (1,1)(100,1)noMatrix multiply does not broadcast; inner dimensions match exactly

2.3.4 The Four Classic Mistakes and Five Checks

Mistake 1

Mixing (n,) with (n,1) and getting a silent (n,n). In a regression loss this changes the scale of the MSE entirely.

Mistake 2

Forgetting a dimension where an outer product was intended, ending up with element-wise multiplication instead.

Mistake 3

Calling view on a transposed tensor — non-contiguity raises.

Mistake 4

Updating a parameter with a mismatched shape, so broadcasting quietly turns w from (n,) into (n,n).

Check 1–3

Write each line's expected shape in a comment before writing the line; add assert y_hat.shape == y.shape; keep (n,) out of the fight by making targets reshape(-1, 1).

Check 4–5

For non-contiguous tensors use reshape or .contiguous().view(...); before training, print the shapes of the data and of every parameter once.

2.4 Computational Graphs and Autograd

Autograd does exactly one thing: it records each forward operation, then walks the recording backwards applying the chain rule. You never differentiate by hand — but you must know who is on the graph.

2.4.1 The Graph Is a By-Product

Every operation involving a tensor with requires_grad=True records how it produced its output. The result is a directed acyclic graph whose leaves are your parameters. After backward() the graph is freed by default; if you need to traverse it twice, pass retain_graph=True.

2.4.2 requires_grad: the Switch

  • Only floating-point tensors accept requires_grad=True. An int64 tensor raises.
  • Data (X, y) does not need it. Parameters (w, b) must have it.
  • Anything computed from such a tensor inherits the flag automatically — that is how the graph grows.

2.4.3 backward, grad, and Accumulation

x = torch.tensor(3.0, requires_grad=True)   # a leaf tensor
y = x ** 2 + 2 * x + 1                      # forward + graph
print(y.requires_grad, y.grad_fn)
# True <AddBackward0> — a non-leaf remembers how it was made

y.backward()                                # walk the graph backwards
print(x.grad)                               # 8.0 = 2*3 + 2

x.grad = None                               # gradients accumulate: clear first
z = (x ** 2).sum()
z.backward()
print(x.grad)                               # 6.0 = 2*3

with torch.no_grad():                       # inference: do not build a graph
    print((x * 2).requires_grad)            # False
print((x * 3).detach().requires_grad)       # False — cut off the graph
The whole truth about accumulation Remove the line x.grad = None and run again: the gradient becomes 8 + 6 = 14. Nothing raises. Inside a training loop this is the direct cause of a loss curve that jumps up and down instead of descending.

2.4.4 The Five Moves of One Update

Forward

Compute the prediction from the current parameters: y_hat = X @ w + b.

Build the graph

Happens automatically because the parameters require grad.

Scalar loss

Compress the error into one number: loss = ((y_hat - y) ** 2).mean().

Backward

loss.backward() fills .grad on every leaf.

Update, then zero

Edit the parameters inside with torch.no_grad():, then zero the gradients immediately. The order is fixed; the no_grad wrapper is not optional.

2.5 Gradient Descent with Tensors

Put the three previous sections together: tensors hold the data, shapes line up, autograd supplies the gradient, and you write the descent step yourself.

2.5.1 The Hand-Written Loop

import torch
torch.manual_seed(42)                  # fixed seed: reproducible

X = torch.randn(100, 1)                # (100, 1)
y = 3.0 * X + 2.0 + 0.1 * torch.randn(100, 1)
w = torch.zeros(1, 1, requires_grad=True)
b = torch.zeros(1, requires_grad=True)
lr, history = 0.1, []

for step in range(200):
    y_hat = X @ w + b                  # forward: (100,1)
    loss = ((y_hat - y) ** 2).mean()   # MSE
    loss.backward()                    # backward: fills w.grad
    with torch.no_grad():              # the update must not be traced
        w -= lr * w.grad
        b -= lr * b.grad
    w.grad.zero_(); b.grad.zero_()     # skip this and gradients accumulate
    history.append(loss.item())

print(round(w.item(), 3), round(b.item(), 3))   # 2.987 2.013

Three things must happen inside the loop, and no two of them are interchangeable: loss.backward(), the update wrapped in with torch.no_grad():, and w.grad.zero_(). Remove any one and training will not converge the way you expect.

2.5.2 Three Learning Rates

ηWhat the loss curve looks likeWhat is actually happening
Too small, 0.001Almost flat; the descent is invisibleEach step is tiny; 200 steps never reach the bottom — easily misread as "the model does not work"
About right, 0.1A clear descent, then a plateauThe default for this lab and the reference for the comparison
Too large, 1.0Rises, oscillates, eventually nanEvery step overshoots the valley and lands further away on the other side
Debugging first move When a loss curve misbehaves, ask two questions in this order: is the loss descending at all, and are the gradients zeroed each step? The learning rate is the third question, not the first.

2.5.3 Where "Converged" Means: Three Numbers, Not One

Linear regression is one of the few models where you know the right answer before training. Use that: it turns your first training run into a check rather than a hope.

w (slope)3.0002.9912.9870.13%

Each number means something different. The truth is what you generated the data with; the closed-form solution is the best possible fit on this particular sample; the trained solution is what 200 steps produced. Your report must state which one it compares against, or the word "error" carries no information.

# closed-form least squares on the same sample
X1 = torch.cat([X, torch.ones_like(X)], dim=1)   # (100, 2)
theta = torch.linalg.lstsq(X1, y).solution
print(theta.flatten().tolist())                    # [w_ols, b_ols]

2.6 Pitfalls and a Debugging Checklist

Rigour: Why the Seed Must Be Fixed Randomness is part of training — initialisation, noise, shuffling — so it must be pinned down. Without a fixed seed, your experiment cannot be re-checked by anyone, including you in three days. A single good run is not a conclusion; a repeatable one is. Every report you write this term carries three things: the seed, the environment version, and one runnable command. And keep the failures in the record: shape errors and debugging traces are evidence of skill, not marks to hide. Never fabricate an output; never prettify a curve. Small cross-device differences are normal — state them rather than quietly keeping the best run.
Checklist
  • Print shapes before anything else. print(x.shape, x.dtype, x.device) on the first look at any new tensor.
  • Predict the shape before running the line. Write it in a comment; if the print disagrees, stop and find out why.
  • Assert the contract. assert y_hat.shape == y.shape costs one line and catches the silent bug.
  • Prefer reshape to view. Use view only when you know the tensor is contiguous.
  • Unify the target's shape. Keep everything (n, 1) and refuse to let (n,) into the fight.
  • Zero the gradients after every update. Not before, not sometimes.
  • Wrap the update in no_grad. Otherwise the update enters the graph and training slows down as it goes.
  • Fix the seed. Or your three learning-rate curves cannot be compared at all.
  • Check the import count. In this lab, a single nn. or optim. in the file is a violation.
  • Read the error aloud. PyTorch error messages state the shapes involved; that is usually the diagnosis.

2.7 Summary and Exercises

Five Takeaways
  1. A tensor is the only container this course uses. On first sight, report four things: shape, dtype, device, requires-grad.
  2. Prefer reshape; add dimensions with unsqueeze(1); view is safe only on contiguous tensors.
  3. Broadcasting aligns from the right and stretches every 1 — it guarantees legality, not intent. (3,) plus (3,1) silently gives (3,3).
  4. Autograd has two rules: only leaves receive .grad, and .grad accumulates.
  5. One update is four moves in a fixed order: backward, update under no_grad, zero the gradients, log the loss.
