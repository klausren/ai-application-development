PyTorch 基础：张量与自动求导

在 PyTorch 里，数据、参数、梯度、损失全都是张量——一个容器，一个引擎。本章先讲容器（形状、类型、设备、是否求导、梯度），再讲引擎（计算图与反向传播），然后只用这两样东西，用梯度下降把一条直线学出来。本章还会重点覆盖本课程最在意的一类 bug：不报错、但答案是错的形状错误。

2.1 张量：深度学习的通用容器

第 1 章讲了流水线，本章打开工具箱。你在流水线各阶段之间传递的一切——一批输入、一个权重矩阵、一个损失、一份梯度——都是张量。

2.1.1 张量是什么

张量是 n 维数组，外加三种能力：它知道自己是什么形状和什么类型，它能住在 GPU 上，它能被求导。

0 维——标量

一个数，例如一个损失值。由 .mean() 或 .sum() 产生。你在它上面调用 .backward()。

1 维——向量

一个样本的特征，或一个偏置向量，形状 (n,)。本章一半的坑都来自这个形状。

2 维——矩阵

一批样本，(样本数, 特征数)。所有表格类模型与线性模型的主力形状。

3 维及以上

图像 (batch, channels, height, width)、序列 (batch, time, features)。规则一样，只是出错的地方更多。

2.1.2 为什么不用 Python list

Python listtorch.Tensor
速度循环由解释器逐元素执行向量化内核（C++/CUDA），快一到两个数量级
形状嵌套列表没有形状概念，长度没人替你检查一个 torch.Size，每个运算都会校验
广播不存在，循环得自己写内建，且有明确规则（也有它自己的失效方式）
设备只能 CPU.to("cuda") 搬进显存
梯度不支持autograd 自动记录运算

2.1.3 与 NumPy 的关系

x = np.ones(3)
t = torch.from_numpy(x)     # 共享内存，不是副本
t[0] = 9.0
print(x[0])              # 9.0 —— 数组也跟着变了

t2 = torch.tensor(x)        # 这个是复制
arr = t2.numpy()            # 交回给 NumPy，例如给 matplotlib 画图
一句话 张量就是 NumPy 数组加两件事：能上 GPU、能求导。from_numpy 的共享内存行为值得记住，恰恰因为它不出声。

2.1.4 GPU 张量

device = "cuda" if torch.cuda.is_available() else "cpu"
X = torch.randn(100, 1).to(device)
w = torch.zeros(1, 1, requires_grad=True, device=device)

# 把数据和参数一起搬过去，是你自己的责任
print((X @ w).device)     # cuda:0 —— 结果留在了 GPU 上

两个张量必须在同一设备上才能参与运算。CPU 与 GPU 混算会立刻抛 RuntimeError——这是本章为数不多「会主动帮你」的报错。只用 CPU 完全没问题；有问题的是不知道自己在用什么设备。

2.2 张量的五个属性

这五个属性里任何一个错了，程序都不会崩。它会跑完，损失会打印一个数，而这个数没有意义。这就是为什么下面这条习惯比本章任何技巧都值钱。

2.2.1 怎么读一个张量

属性在看什么典型值什么时候会咬你
shape每一维的大小torch.Size([100, 1])形状错了不报错，广播会替你「猜」一个结果
dtype元素类型与精度float32、int64int64 不能设 requires_grad，整数除法还会取整
device数据物理上在哪cpu、cuda:0CPU 与 CUDA 混算直接 RuntimeError
requires_grad这个张量要不要参与求导True / False参数忘了设，.grad 永远是 None，训练静默失败
grad累计起来的梯度与自身形状相同的张量它是累加的：不看零，你读到的是一串错数
那个习惯 任何一次形状报错，或者结果看着不对，先打印： print(x.shape, x.dtype, x.device)。 九成的张量 bug 在这一行里就现形了。这不是调试，这是默认动作。

2.2.2 创建张量

import torch

t = torch.tensor([[1., 2.], [3., 4.]])   # 从 Python 数据构造
z = torch.zeros(2, 3)                    # 全 0
o = torch.ones(2, 3)                     # 全 1
r = torch.randn(2, 3)                    # 标准正态随机
a = torch.arange(0, 6)                   # 0..5，默认 int64
l = torch.linspace(0, 1, 5)              # [0,1] 上等距 5 点

print(t.shape, t.dtype, t.device)
# torch.Size([2, 2]) torch.float32 cpu

print(a.dtype)                            # torch.int64
print(torch.arange(6.).dtype)             # torch.float32 —— 一个点号
print(round(r.mean().item(), 2))          # 约 0.00
print(round(r.std().item(), 2))           # 约 1.00
坑 torch.arange(0, 6) 是 int64，在它上面设 requires_grad=True 会直接报错。训练代码里写 torch.arange(6.)：一个小数点就把它变成 float32。同一个坑还有另一种形式——y = 3.0 * X + 2.0，那个 2.0 就是为了让结果保持浮点。

2.3 形状变换与广播

本节包含本章唯一一类「完全不报错」的失败。它应该得到最多注意力，而不是最少。

2.3.1 形状变换的三组动作

动作操作要知道什么
改形状view、reshape、-1view 共享内存且要求连续；reshape 必要时会复制——日常首选。-1 表示「这一维你来算」，其余维必须能整除。
增维与删维unsqueeze、squeezeunsqueeze(1) 把 (n,) 变成 (n,1)，是本课程最常用的救场；squeeze 只能删大小为 1 的维。
换轴transpose、permute换轴之后通常不连续，view 会失败。改用 .contiguous().view(...) 或 reshape。
x = torch.arange(6.)           # (6,)
a = x.view(2, 3)               # (2,3) —— 与 x 共享内存
x[0] = 99.
print(a[0, 0])                 # 99.0 -> 视图不是副本

t = a.t()                      # (3,2)，转置后不连续
# t.view(6)                    # RuntimeError: view size is not compatible
print(t.reshape(6).shape)         # (6,) —— reshape 会复制，所以能用

print(x.reshape(2, -1).shape)       # (2, 3)
print(x.unsqueeze(1).shape)         # (6, 1) —— 正好对上 MSE 的广播

2.3.2 广播规则

从最右一维开始对齐

从两个形状的最右边一维开始比较，逐维向左。

两维相等直接对齐

大小相同的维度直接配对。

其中一维是 1 就复制

如果两者中有一个是 1，就沿这一维复制扩展到另一边的长度。

都不是 1 且不相等就报错

这是好错误。它在你算出一个没有意义的东西之前把你拦住了。

w = torch.randn(3)         # (3,)
X = torch.randn(4, 3)      # (4,3)
print((X + w).shape)       # (4,3) —— w 被复制到每一行：符合直觉

v = torch.randn(3, 1)      # (3,1)
print((v + w).shape)       # (3,3) —— 静默变大。这就是那个 bug。

print(torch.broadcast_shapes((3, 1), (3,)))
# -> (3, 3)：规则说合法，但不是你要的

w2 = w.reshape(-1, 1)            # 把意图写进形状
print((v + w2).shape)      # (3,1) —— 这才是你想要的
规则背后的规则 广播保证的是合法，不是符合意图。引擎会很乐意产出一个你从没想要的形状，且不给你任何警告。写 reshape(-1, 1) 一半是为了正确，一大半是为了让代码自己解释自己。

2.3.3 静默错 vs 报错

把你遇到的失败分进这两列；注意力要花在左边那一列上。

写法结果报错吗为什么
X (4,3) + w (3,)(4,3)不报从最右对齐，w 被复制到每一行——符合直觉
v (3,1) + w (3,)(3,3)不报 —— 静默错(3,1) 沿列复制、(3,) 沿行复制，结果凭空多出一维
v + w.reshape(-1,1)(3,1)不报把意图写进了形状里
X (100,1) @ w (1,1)(100,1)不报矩阵乘法不广播，内维必须严格相等
X (100,1) @ w (3,)—报错内维 1 与 3 不相等：mat1 and mat2 shapes cannot be multiplied
a (2,3).t().view(6)—报错转置后内存不连续：view size is not compatible...
x (4,6).reshape(-1,3)(8,3)不报-1 自动推断；其余维必须能整除

2.3.4 四个高频错误与五条自查

错误 1

把 (n,) 与 (n,1) 混用，静默得到 (n,n)。在回归损失里，这会把 MSE 的量级整个改掉。

错误 2

该做外积的地方忘了补维，结果变成了逐元素相乘。

错误 3

对转置后的张量用 view——非连续，直接报错。

错误 4

更新参数时形状不一致，广播把 w 从 (n,) 悄悄变成 (n,n)。

自查 1–3

写形状相关代码前，先把每行的预期形状写进注释；加断言 assert y_hat.shape == y.shape；把目标统一成 reshape(-1, 1)，别让 (n,) 参战。

自查 4–5

非连续张量用 reshape 或 .contiguous().view(...)；训练开始前，把数据与每个参数的形状各打印一次。

2.4 计算图与自动求导

autograd 只做一件事：把前向的每一步记下来，反向时按链式法则逐段求导。你不需要自己推导，但你必须知道谁在图上。

2.4.1 计算图是前向的副产品

任何涉及 requires_grad=True 张量的运算都会记下自己是怎么算出结果的。整张图是一张有向无环图，叶子就是你的参数。backward() 之后图默认被释放；需要再次遍历就传 retain_graph=True。

2.4.2 requires_grad：开关

  • 只有浮点张量能设 requires_grad=True，int64 张量会报错。
  • 数据（X、y）不需要；参数（w、b）必须有。
  • 凡是从这种张量算出来的结果都自动带上这个标记——图就是这样长出来的。

2.4.3 backward、grad 与累加

x = torch.tensor(3.0, requires_grad=True)   # 叶子张量
y = x ** 2 + 2 * x + 1                      # 前向 + 建图
print(y.requires_grad, y.grad_fn)
# True <AddBackward0> —— 非叶子记录了它是怎么算出来的

y.backward()                                # 反向：沿图回传
print(x.grad)                               # 8.0 = 2*3 + 2

x.grad = None                               # 梯度默认累加，先清零
z = (x ** 2).sum()
z.backward()
print(x.grad)                               # 6.0 = 2*3

with torch.no_grad():                       # 推理：不建图
    print((x * 2).requires_grad)            # False
print((x * 3).detach().requires_grad)       # False —— 从图上摘下
梯度累加的全部真相 把 x.grad = None 那一行注释掉再跑一次：梯度变成 8 + 6 = 14。它不报错。在训练循环里，这就是损失曲线来回震荡而不下降的直接原因。

2.4.4 一次参数更新的五个动作

前向

用当前参数算出预测：y_hat = X @ w + b。

建图

因为参数需要梯度，这一步自动发生。

求损失

把误差压成一个标量：loss = ((y_hat - y) ** 2).mean()。

反向

loss.backward() 沿图回传，填满每个叶子的 .grad。

更新与清零

在 with torch.no_grad(): 里手改参数，然后立刻清零梯度。顺序固定，no_grad 这层包装不是可选项。

2.5 用张量实现梯度下降

把前三节拼起来：张量装数据、形状对齐、autograd 给梯度，而下降那一步由你自己写。

2.5.1 手写的训练循环

import torch
torch.manual_seed(42)                  # 固定种子：结果可复现

X = torch.randn(100, 1)                # (100, 1)
y = 3.0 * X + 2.0 + 0.1 * torch.randn(100, 1)
w = torch.zeros(1, 1, requires_grad=True)
b = torch.zeros(1, requires_grad=True)
lr, history = 0.1, []

for step in range(200):
    y_hat = X @ w + b                  # 前向：(100,1)
    loss = ((y_hat - y) ** 2).mean()   # MSE
    loss.backward()                    # 反向：填 w.grad
    with torch.no_grad():              # 更新不能建图
        w -= lr * w.grad
        b -= lr * b.grad
    w.grad.zero_(); b.grad.zero_()     # 不清零 -> 梯度累加
    history.append(loss.item())

print(round(w.item(), 3), round(b.item(), 3))   # 2.987 2.013

循环里有三件事必须发生，而且它们不能互换位置：loss.backward()、装在 with torch.no_grad(): 里的更新、以及 w.grad.zero_()。少任何一件，训练都不会按你预期收敛。

2.5.2 学习率三档

η损失曲线长什么样实际发生了什么
太小 0.001几乎是平线，看不出下降每步都极小，200 步远没走到谷底——很容易被误判成「模型不行」
合适 0.1先明显下降，然后进入平台本次实验的默认值，也是所有对比的基准
太大 1.0整体上升、来回震荡，最终 nan每一步都跨过谷底，落到对面更远的地方
排查顺序 损失曲线不对劲时，按这个顺序问两个问题：它到底有没有下降趋势？每一步的梯度清零了吗？学习率是第三个问题，不是第一个。

2.5.3 「收敛」是对着谁说的：三个数，不是一个

线性回归是少数几个你在训练之前就知道答案的模型。用它把这个好处兑现：第一次训练就从「盼着它能行」变成「检查它对不对」。

参数数据生成真值闭式最小二乘解梯度下降 200 步相对误差
w（斜率）3.0002.9912.9870.13%
b（截距）2.0002.0142.0130.05%
训练集 MSE0.0100（噪声方差）0.00980.0099不在同一量纲

三个数各有各的含义：真值是你造数据时用的；闭式解是在这批样本上最优的；训练解是 200 步之后你拿到的。报告里必须写清你是在跟哪一个比，否则「误差」这个词不携带任何信息。

# 在同一批样本上求闭式最小二乘解
X1 = torch.cat([X, torch.ones_like(X)], dim=1)   # (100, 2)
theta = torch.linalg.lstsq(X1, y).solution
print(theta.flatten().tolist())                    # [w_ols, b_ols]

2.6 常见误区与排查清单

严谨求实：为什么必须固定随机种子 随机性是训练的一部分——初始化、噪声、打乱顺序都是随机的——所以它必须被固定下来。不固定种子，你的实验就无法被任何人复核，包括三天后的你自己。 一次跑出来的好结果不是结论，能被重复出来的才是。本学期你写的每一份报告都要带三样东西：种子、环境版本、一行可运行的命令。 同时，把错误留在记录里：形状报错和调试过程是能力证据，不是需要藏起来的扣分项。不编造输出，不美化曲线；换设备出现微小差异很正常，如实写明，而不是悄悄只留最好那一次。
检查清单
  • 先印形状，再做别的。 第一次见到任何张量，先 print(x.shape, x.dtype, x.device)。
  • 运行前先预测形状。 把它写进注释；如果打印结果不一致，停下来想清楚。
  • 把契约写成断言。 assert y_hat.shape == y.shape 只花一行，却能挡住那个静默 bug。
  • 优先用 reshape。 只有在确定张量连续时才用 view。
  • 统一目标的形状。 全都保持 (n, 1)，不让 (n,) 参与。
  • 每次更新后清零梯度。 不是更新前，也不是有时候。
  • 把更新包进 no_grad。 否则更新自己进了计算图，越训越慢。
  • 固定种子。 否则三条学习率曲线根本无法对比。
  • 数一下 import。 本次实验里，文件里出现一个 nn. 或 optim. 就是违规。
  • 把报错念出来。 PyTorch 的报错信息里直接写着涉及的两个形状，那通常就是诊断结论。

2.7 小结与练习

五条要点
  1. 张量是本课程唯一的数据容器。拿到它先报四件事：shape、dtype、device、requires_grad。
  2. 形状变换优先 reshape；补维用 unsqueeze(1)；view 只在连续张量上安全。
  3. 广播从最右一维对齐、遇 1 就复制——它保证合法，不保证符合意图。(3,) 与 (3,1) 相加会静默得到 (3,3)。
  4. autograd 只有两条规则：只有叶子张量的 .grad 被填充，而且 .grad 是累加的。
  5. 一次更新是四个动作的固定顺序：backward → 在 no_grad 里更新 → 清零梯度 → 记录损失。

练习 1 · 读一个张量（必做）

  1. 对下面每一个，先写下来再运行：torch.tensor(3.0)、torch.arange(5)、torch.linspace(0, 1, 7)、torch.randn(2, 3).t()、torch.zeros(4).unsqueeze(0) 的 shape、dtype 与 device。
  2. 运行后对比。你猜错了哪一个？这说明 dtype 的默认规则是什么？

练习 2 · 故意制造广播错误（必做）

  1. 有意用 (3,1) 与 (3,) 造出一个 (3,3) 的结果，并用一句话解释引擎为什么允许它。
  2. 再造一个会报错的形状问题，把完整报错信息贴出来。
  3. 写出同样两行、但不可能被误读的版本，并说明你加了什么。

练习 3 · 量化梯度累加（必做）

  1. 跑 2.4.3 的最小 autograd 示例，记下 x.grad。
  2. 把清零那一行注释掉再跑一次，记下新值并解释这个算术。
  3. 把 2.5.1 的循环改成永不清零梯度，跑 200 步，用一句话描述损失曲线，并与正确清零的曲线画在同一张图上对比。

练习 4 · 只用张量做线性回归，并且可复现（必做）

  1. 只用张量和 autograd 实现——不许出现 nn.Module、不许出现 torch.optim。用 grep -nE "nn\.|optim\." 自查文件是否干净。
  2. 记录 w = b = 0 时的基线 MSE 和训练结束时的 MSE。
  3. 把训练得到的参数与真值、闭式最小二乘解分别对比，给出相对误差，并明确写出你用的对照对象是哪一个。
  4. 固定种子，确认重跑脚本能把参数复现到小数点后三位。
  5. 用三个不同的种子各跑一遍这 200 步，把三条损失曲线画在一起。在这个凸问题上，最终参数之间应该只差千分之几。报告这个离散程度，再用五句话解释：为什么在这里——而在从零训练的神经网络上不行——种子对轨迹的影响远大于对终点的影响。

练习 5 · 审计 AI 生成的代码（必做）

  1. 让一个 AI 工具生成「用张量和 autograd 做 PyTorch 线性回归，不要 nn，不要优化器」。
  2. 逐行读，重点找四个缺陷：没有清零梯度、目标用 (n,) 而不是 (n, 1)、更新写在 no_grad 外面、没有固定种子。
  3. 每找到一个缺陷就：引用那句错误写法、说明它会造成什么现象、给出你修正后的版本。
