第 03 章 · 模块一 · 第 3 周

数据准备与管道构建

第 2 章用原始张量搭出了一个模型。本章故意把视线从模型移开，去看它吃进去的东西。结论说得很直接：数据决定上限，模型只是逼近上限。你要用 PyTorch 把六步管道——原始数据、清洗、划分、Dataset、DataLoader、批次——真正建起来，学会识别并规避数据泄漏的四种形态，正确地处理数据增强与类别不平衡而不自欺，最后写出一张说清「结论到哪里就不成立」的数据卡片。

3.1 数据决定上限

每个卡住的项目，第一个问题都一样：该改模型还是改数据？第 2 章已经说明参数是从数据里学出来的，其实已经暗示了答案。本章把它明确下来。

总纲 数据里包含的信息量、以及标注的质量，决定了误差最低能到多少。模型只能逼近这个界限。上限低，换任何结构都救不回来；而一旦划分错了，你连上限是多少都不知道。

3.1.1 三句推论

① 上限是真实存在的

数据覆盖了多少种情况、标注有多准，决定了可达到的误差下界。一个从没被记录过的特征，再大的网络也变不出来。

② 更好的模型只是更靠近它

换结构、调超参，都是沿着同一条上限移动。进展停下来时，下一个有用的动作几乎总是回头检查数据。

③ 度量决定你是否知道

划分错了或泄漏了，得到的数字不只是偏乐观，而是毫无意义。本章后面的每一节都服务于同一个目标：看见真实水平。

3.1.2 数据管道六步

原始数据——多来源、多格式，尚未定义好坏。
清洗——缺失、异常、重复与单位不一致，每类都要有明确的判据。
划分——train / val / test，固定种子，策略有据可依。
Dataset——把数据包装成「样本可索引」的形式：__len__ 与 __getitem__。
DataLoader——批处理、打乱、并行加载与批次拼装。
批次——训练循环真正看到的东西。
顺序不可交换 划分必须发生在任何「会从数据里学习」的步骤之前——标准化、缺失填补、特征选择、数据增强都算。任何在全量数据上算出来的统计量，都已经被验证集和测试集的行污染过了。

3.1.3 以模型为中心 vs 以数据为中心

以模型为中心以数据为中心
起手动作数据原样喂给模型先诊断质量，明确来源与合规
主要手段换模型、调超参修划分、修标签、去重、补覆盖
典型结果提升越来越小且无法解释同一个模型指标更稳更高
卡住时说不清为什么错误能归因到具体的数据问题

两条路线不是对立的，而是有先后：先做数据，再谈模型。顺序反过来，你连「模型到底好不好」都判断不了。

3.2 数据获取、清洗与来源

清洗不是「把数据弄得好看」，而是把已知的问题变成可核查的记录：每个问题都要有一条发现它的判据、一个处理动作，以及一句「这个动作可能弄坏什么」。

3.2.1 四类常见问题

缺失值

先看缺失率排行，再看缺失是否与标签相关。填补用的统计量（中位数、众数）只能来自训练集。

异常值

用 1/99 分位或 IQR 规则判定，而不是「看起来奇怪」。可以截断、变换，也可以保留并加标记。

重复与不一致

按命名的主键去重，统一单位与类别编码。跨集合的重复样本就是直接的数据泄漏。

标签噪声

交叉核对、检查标注一致性、抽样人工复核。噪声比例高时，再多的数据也补不回来。

问题怎么发现处理动作风险
缺失值df.isna().mean() 排序；缺失与标签的交叉统计删除、中位数/众数填补、模型填补用全量统计量填补就是泄漏
异常值分位数、箱线图、IQR 规则截断、对数变换，或保留并加标记异常值可能正是你要预测的目标
重复与不一致主键计数；单位与编码取值集合检查去重、统一单位与类别编码同一实体跨训练与测试即泄漏
标签噪声一致性告警、模型高置信错例、人工抽样重标、剔除，或使用鲁棒损失先量化噪声比例，再决定是否清洗

3.2.2 来源与隐私排在第一位

在写下第一行清洗代码之前，先回答两个问题：这份数据从哪里来、在什么许可下使用？以及它是否包含个人信息？来源不清的数据，结果无法复现，在很多司法辖区也无法合法公开。个人信息必须在进入管道之前就完成去标识化，原始数据绝不能粘贴到公网服务里。尊重数据的来源不是形式要求，而是工程伦理的底线。

3.2.3 用 AI 做探索而不被带偏

让 AI 起草一段探索代码是高效的做法。纪律在于：它给出的每一条统计结论，都必须能被你用一行断言或一张图复现。

import pandas as pd

df = pd.read_csv("data/raw/defects.csv")
print("shape:", df.shape)
print(df["label"].value_counts(normalize=True).round(3))

# AI 常在这里说：「类别分布均衡，可以直接训练。」
# 别信，直接把它定论下来：
share = df["label"].value_counts(normalize=True)
assert share.min() > 0.20, "少数类占比过低，称不上均衡"

# 「没有缺失值。」
assert df.isna().sum().sum() == 0, "存在缺失值"

# 「特征与标签强相关。」-> 画图 + 独立复算
df.groupby("label")["size"].mean().plot(kind="bar")
规则 当 AI 的统计结论与你画的图不一致时，以你自己跑出来的为准。把这次分歧、提问原文和更正后的结论写进 AI_USE.md。这份记录是评价项——它是你核对过的证据，而不是扣分项。

3.3 划分：比例与策略

划分决定了你之后看到的每一个数字是否可信。它是本章里影响最大的一步。

3.3.1 三个集合各自只做一件事

集合比例职责使用频率
训练集约 70%拟合参数，以及所有统计量：标准化、填补、特征选择、数据增强一直用
验证集约 15%选模型、调超参反复用——所以它不是最终成绩
测试集约 15%最终的真实性能估计只用一次
铁律 一旦测试集参与了调参，它就已经悄悄变成了验证集，报出的数字不再可信。数据量小（不足约 1 万条）时，用 5 折交叉验证代替固定验证集。

3.3.2 四种策略——按数据性质选

策略适用失效情形
随机划分样本相互独立、无时序、无重复实体以上三条中有任一条不成立
分层划分类别不平衡，尤其少数类样本很少需要的是「实体级」隔离而不是「类别级」均衡
时间划分存在真实先后关系：时序、流式、日志—
分组划分同一用户/设备/病人/文档有多条记录—

时序数据做随机划分，等于让模型在训练时就看到了未来。同一台设备贡献了几百行时做随机划分，会把近似重复的样本放到线的两侧——这也是泄漏，尽管代码一行都没写错。

3.3.3 PyTorch 里可复现的固定种子划分

import torch
from torch.utils.data import Subset

# torch.Generator 让划分可复现，同时不污染全局随机状态
g = torch.Generator().manual_seed(42)
perm = torch.randperm(len(ds), generator=g)

i1, i2 = int(0.70 * len(ds)), int(0.85 * len(ds))
train_ds = Subset(ds, perm[:i1])
val_ds   = Subset(ds, perm[i1:i2])
test_ds  = Subset(ds, perm[i2:])

print(len(train_ds), len(val_ds), len(test_ds))

类别不平衡时，把排列操作放在每个类别内部再做拼接。这样三个集合都能保住总体类别比例，少数类也不会碰巧从验证集里消失。

3.4 数据泄漏

泄漏指的是：模型在训练时用到了推理阶段拿不到的信息。它给出的分数不只是偏乐观，而是不对应任何真实部署场景。

3.4.1 泄漏的四种形态

形态代码里的样子为什么分数虚高
测试样本混入训练划分之后又把测试集拼回训练数据模型见过它正在被打分的那份考题
重复样本跨集合去重步骤从没执行，同一实体出现在两个集合近似相同的行让「记住答案」变得轻而易举
有序数据随机划分对时序数据用 random_split模型在训练时就把过去和未来插值到了一起
统计量来自全量数据划分之前做标准化或缺失填补验证集与测试集的行参与了模型学到的那个均值

3.4.2 一句判据识别全部四种

判据 这个信息在推理时拿得到吗？拿不到，就不该出现在训练里。对每一列、每一个统计量、每一步预处理都问一遍。

3.4.3 一个错误示范与一个正确示范

from torch.utils.data import random_split

# 错误：统计量在全量数据上拟合，然后才划分
mu = X.mean(0)
X_norm = (X - mu) / X.std(0)
train_ds, val_ds, test_ds = random_split(ds, [0.7, 0.15, 0.15])

# 正确：先划分，统计量只来自训练行
g = torch.Generator().manual_seed(42)
train_ds, val_ds, test_ds = random_split(
    ds, [0.70, 0.15, 0.15], generator=g)

tr = X[train_ds.indices]                 # 只取训练行
mu, sd = tr.mean(0), tr.std(0).clamp_min(1e-8)
X_norm = (X - mu) / sd                   # 同一个变换应用到全部

一个真实案例把代价讲得很清楚：某个项目用一份仍然混着测试样本的数据训练，线下报出 0.99，上线后跌到 0.78。那 21 个百分点不是学到的规律——模型只是见过了考题。

3.5 Dataset 与 DataLoader

划分之后，数据要以「样本可索引」的形式交给训练循环。PyTorch 用两个抽象完成这件事：Dataset 定义「一条样本是什么」，DataLoader 定义「批次怎么来」。

3.5.1 Dataset 的契约

import torch
from torch.utils.data import Dataset

class DefectDataset(Dataset):
    """DataFrame -> PyTorch 数据集：只需要两个方法。"""

    def __init__(self, df, transform=None):
        self.y = torch.tensor(df["label"].values, dtype=torch.long)
        self.x = torch.tensor(
            df.drop(columns=["label"]).values.astype("float32"))
        self.transform = transform       # 只在训练集传入

    def __len__(self):
        return len(self.y)             # 批次数靠它算出来

    def __getitem__(self, i):
        x = self.x[i]                    # 一次只返回一条样本
        if self.transform is not None:
            x = self.transform(x)
        return x, self.y[i]              # (特征, 标签)

ds = DefectDataset(df)
print(len(ds), ds[0][0].shape)     # 12480 torch.Size([12])
两条纪律 绝不要在 __getitem__ 里计算跨样本统计量——那里的一列均值或全局词表是在全量数据上拟合的，是泄漏的温床。同时，transform 只传给训练集：验证与测试必须与线上推理保持一致。

3.5.2 DataLoader 做的四件事

from torch.utils.data import DataLoader

train_loader = DataLoader(train_ds, batch_size=32, shuffle=True,
                          num_workers=4, drop_last=True)
val_loader   = DataLoader(val_ds,   batch_size=64, shuffle=False)
test_loader  = DataLoader(test_ds,  batch_size=64, shuffle=False)

xb, yb = next(iter(train_loader))
print(xb.shape, yb.shape, len(train_loader))   # (32, 12) (32,) 273
参数作用建议初值常见坑
batch_size每个批次的样本数32 / 64太大显存爆且泛化可能变差；太小梯度噪声大、训练慢
shuffle每轮是否打乱顺序训练集 True与 sampler= 互斥；验证/测试开 True 会让排查困难
num_workers并行加载的子进程数2 – 4设太大会拖慢；Notebook 与 Windows 下多进程容易报错
drop_last丢弃不足一批的尾批训练集 True不丢时尾批可能只剩 1 条，BatchNorm 会直接报错
collate_fn自定义批次拼装变长序列时自定义默认要求同形状，NLP 任务里会直接报错
generator固定 shuffle 的随机性torch.Generator不设时两次运行的批次顺序不同，结果无法逐位对齐
第一个调试动作 先打印 xb.shape 与 xb.dtype。批次大小 B、特征数 F 时，xb 必须是 (B, F)。形状不对，多半是 __getitem__ 返回了整列而不是单条样本。

3.6 数据增强与类别不平衡

本节有两条边界。增强只作用于训练集；任何采样步骤都要报告处理前后的类别分布。

3.6.1 增强只属于训练集

图像：翻转、裁剪、颜色抖动、随机擦除。表格数据：小幅高斯噪声、插值、特征扰动。增强不能改变标签语义——否则你就是在批量制造带标注的噪声。

3.6.2 处理不平衡的两条路

import torch
from torch.utils.data import DataLoader, WeightedRandomSampler

# 做法一 —— 重采样：少数类权重更大
y_tr = torch.tensor([ds[i][1] for i in train_ds.indices])
counts = torch.bincount(y_tr)
w = (1.0 / counts.float())[y_tr]
sampler = WeightedRandomSampler(weights=w, num_samples=len(w),
                                replacement=True)
train_loader = DataLoader(train_ds, batch_size=32, sampler=sampler)
# 注意：sampler 与 shuffle=True 互斥

# 做法二 —— 代价敏感损失：不动数据，改「犯错的代价」
import torch.nn as nn
criterion = nn.CrossEntropyLoss(weight=1.0 / counts.float())

3.6.3 不平衡时，accuracy 是错的指标

如果某个类别只占 4%，一个「永远预测多数类」的模型准确率是 0.96，却什么都没学到。此时要改用 per-class recall、F1 或 AUPRC，并报告处理前后的类别分布。任何处理都是取舍：如果少数类的 recall 上去了而多数类崩了，你就是用整体性能换了少数类性能——这件事必须写出来，而不是藏起来。

3.7 常见误区与调试清单

自查清单
  • 先划分。所有会学习的步骤——标准化、填补、特征选择、增强——都在划分之后，且只作用于训练集。
  • 统计量只来自训练集。均值、方差、分位数、词表都在训练行上计算，再应用到 val 与 test。
  • 同一实体只在一个集合里。同一用户、设备、病人或文档的所有记录必须待在一起。
  • 有序数据用时间划分。打乱会让模型看到未来。
  • 测试集不复用。一旦它被用来挑模型或调参，它就已经是验证集。
  • 固定种子。划分与 shuffle 用 torch.Generator，多 worker 时用 worker_init_fn 固定各自种子。
  • 先看批次形状。xb 必须是 (B, F)；不对就去查 __getitem__。
  • 绝不增强 val/test。它们的数字必须与推理时可比。
  • 报告采样前后的分布。否则你引入的偏差就是隐形的。
  • 保持数据卡片同步更新。偏差没有被记录下来的管道，不算做完。

3.8 小结与练习

五条要点
  1. 数据决定上限，模型只是逼近上限。效果不好时，先诊断数据，再考虑换结构。
  2. 清洗是把已知问题变成可核查记录：缺失、异常、重复、标签噪声各有判据、动作与风险。
  3. 划分先于所有「会学习」的步骤；标准化、填补、特征选择背后的统计量只来自训练集。
  4. 泄漏 = 训练时用到了推理时拿不到的信息。用一句判据检验整条管道：这个信息推理时拿得到吗？
  5. Dataset 定义一条样本，DataLoader 定义批次；增强只加训练集；不平衡用 sampler 或代价敏感损失，并改用 per-class 指标复测。

练习 1 · 管道的顺序（必做）

  1. 把以下八个操作排出正确顺序，并标注每个属于「可以跨过划分线」还是「绝不能跨」：计算列中位数、划分 train/val/test、特征零均值标准化、按互信息选出前 20 个特征、图像增强、按主键去重、构建 Dataset、包装成 DataLoader。
  2. 挑两个你标为「绝不能跨」的操作，各写一句：一旦跨线会坏在哪里。

练习 2 · 诊断并清洗（必做）

用自己的数据集（实验提供的 defects.csv 或你的大作业数据）产出一页质量报告。

  1. 对缺失、异常、重复、标签噪声四类问题，各给出你使用的数值判据与它检出的数量。
  2. 写出你采取的动作，以及这个动作的一个风险。
  3. 每条结论配一行断言或一张图；配不上证据的结论，从报告里删掉。

练习 3 · 复现泄漏（必做）

  1. 按 3.3.3 实现固定种子的 70/15/15 划分，打印三个集合的规模与类别比例。
  2. 再把特征均值在全量数据上算出来，在划分之前减掉，重跑一遍。记录两次的验证准确率。
  3. 写五句话：哪个统计量越了线、为什么数字更好看、正确示例里的哪一行挡住了它。

练习 4 · Dataset、DataLoader 与不平衡（必做）

  1. 把清洗后的数据包装成自定义 Dataset，验证 ds[0] 与一个批次的形状和 dtype。
  2. 构建三个 DataLoader，并为 batch_size、shuffle、num_workers 以及打乱随机性的固定方式各给出理由。
  3. 统计各类占比，选择 WeightedRandomSampler 或 CrossEntropyLoss(weight=...)，报告处理前后的占比，以及你改用的 per-class 指标。

练习 5 · 审计 AI 的数据结论（必做）

  1. 让 AI 为你的数据集生成一份探索报告，收集至少四条统计结论。
  2. 把每条结论改写成一行断言或一张图，统计几条成立、几条被证伪。
  3. 把被证伪的写进 AI_USE.md：提问、AI 原话、你的核对、更正后的结论。

练习 6 · 小项目：数据卡片（选做，+5 加分）

自选一个数据集，交付一份包含全部五节的数据卡片——来源与合规、规模与结构、质量与已知问题、增强与不平衡、偏差与使用边界——以及生成它的可运行管道。缺少「偏差与使用边界」一节的数据卡片，视为 0 分。
