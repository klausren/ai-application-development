Chapter 04 · Module 1 · Week 4

Neural Networks and Modelling with nn.Module

Chapter 2 trained a model from raw tensors; Chapter 3 built the pipeline that feeds it. This chapter closes Module 1 by giving that model a shape. You will go from a single neuron to a multi-layer network, discover that non-linearity is the only thing that makes depth useful, learn to write models the way PyTorch expects them to be written, and finish by deciding how big and how deep a network should be — with an ablation table rather than an opinion.

4.1 From a Perceptron to an MLP

A single neuron computes a weighted sum and applies a threshold. That is a linear model with a decision rule attached, and it can draw exactly one straight line.

4.1.1 Three Generations

1 · The perceptron (1958)

One neuron. It solves AND and OR, and it cannot solve XOR — no straight line separates the classes.

2 · The multilayer perceptron

Hidden layers transform the features first; the output layer decides afterwards. The same data becomes separable in the new space.

3 · Modern deep networks

Dozens to hundreds of layers. Architecturally they are still stacked affine maps plus non-linearities, with structure and tricks added on top.

4.1.2 A Single Layer vs a Hidden Layer

Common Misconception make_moons is routinely described as "linearly inseparable", and it is a poor demonstration dataset because of it: measured under a fixed protocol a linear model already reaches about 0.89 on it. Use make_circles or XOR when you need to show what a hidden layer buys you. Always measure linear separability; never assume it from the shape of the scatter plot.

The point is not "more layers". It is non-linearity between layers. Two affine maps with nothing between them compose into a single affine map, so any number of linear layers is still a linear model.

4.1.3 The Forward Pass, Step by Step

Input — a batch x of shape (N, 2): N samples, two features each.
Linear 1 — z1 = x @ W1.T + b1, shape (N, 8): features are lifted into a new space.
Activation — h = ReLU(z1), still (N, 8): element-wise, zero parameters.
Linear 2 — z2 = h @ W2.T + b2, shape (N, 2): these are the logits.
Loss — CrossEntropyLoss(z2, y). Softmax is already inside it; do not add another.
ComponentWeight shapeParamsNote

Reading Rule nn.Linear(in, out) always costs in × out + out parameters. From this chapter on, the first thing you do with any network is count its parameters.

4.2 Activations and Non-linearity

The activation function is the only source of non-linearity in a network. Remove it and, no matter how many layers you stack, the network degenerates into a linear model.

4.2.1 The Family

Sigmoid

σ(z) = 1/(1+e⁻ᶻ), range (0,1), readable as a probability. Its derivative peaks at 0.25, so gradients vanish quickly when deep. Today used mainly at the output for a binary probability.

Tanh

Range (−1,1), zero-centred, so it trains better than sigmoid. It still saturates, so vanishing gradients are not solved. Seen in early RNNs and some Transformer variants.

ReLU

max(0, z). The gradient is exactly 1 on the positive side and it is the cheapest to compute. On the negative side it outputs 0, so units can die. The default for hidden layers.

LeakyReLU

max(0.01z, z). A small negative slope keeps units from dying completely. The cost is one more hyper-parameter, and the gain is not always visible.

FunctionRangeGradientWhere to use it
Sigmoid(0, 1)Max 0.25, decays extremely fast when deepOutput layer for a binary probability; avoid in hidden layers
Tanh(−1, 1)Max 1.0, still saturatesWhen you need a zero-centred output; still not for deep nets
ReLU[0, +∞)Exactly 1 on the positive side, no decayDefault for hidden layers; pair with kaiming initialisation
LeakyReLU(−∞, +∞)Slope 0.01 on the negative sideThe fallback when ReLU leaves many units inactive

4.2.2 The Experiment You Should Run Yourself

One protocol, two datasets, one flag apart. We run it on both because a single dataset can hide the very effect you are trying to measure.

import torch, torch.nn as nn
from sklearn.datasets import make_moons, make_circles
from sklearn.model_selection import train_test_split

def load(kind):
    if kind == "moons":
        X, y = make_moons(n_samples=1000, noise=0.25, random_state=42)
    else:
        X, y = make_circles(n_samples=1000, noise=0.10, factor=0.5,
                            random_state=42)
    Xtr, Xva, ytr, yva = train_test_split(X, y, test_size=0.3,
                                          random_state=42, stratify=y)
    t = lambda a, d: torch.tensor(a, dtype=d)
    return (t(Xtr, torch.float32), t(Xva, torch.float32),
            t(ytr, torch.long),    t(yva, torch.long))

class MLP(nn.Module):
    def __init__(self, use_relu=True):
        super().__init__()
        self.fc1 = nn.Linear(2, 8)
        self.fc2 = nn.Linear(8, 2)
        self.act = nn.ReLU() if use_relu else nn.Identity()

    def forward(self, x):
        return self.fc2(self.act(self.fc1(x)))   # (N,2) -> (N,8) -> (N,2)

def run(data, use_relu, seed=42, epochs=300, lr=1e-2):
    Xtr, Xva, ytr, yva = data
    torch.manual_seed(seed)
    model = MLP(use_relu)
    opt = torch.optim.Adam(model.parameters(), lr=lr)
    crit = nn.CrossEntropyLoss()
    for _ in range(epochs):
        opt.zero_grad()
        loss = crit(model(Xtr), ytr)
        loss.backward(); opt.step()
    model.eval()
    with torch.no_grad():
        acc = (model(Xva).argmax(1) == yva).float().mean().item()
    return acc, loss.item()

for kind in ("moons", "circles"):
    d = load(kind)
    a_on,  l_on  = run(d, True)
    a_off, l_off = run(d, False)
    print(f"{kind:8s} ReLU {a_on:.3f} (loss {l_on:.3f})  "
          f"none {a_off:.3f} (loss {l_off:.3f})")

The Number to Recognise On make_circles the no-activation loss stops at 0.693, which is ln 2 — the loss of guessing between two classes. Two nn.Linear layers with nothing non-linear between them are equivalent to one linear layer, and a linear model cannot separate two concentric rings. The flat curve is not a bug; it is the result.
Why the Dataset Decides On make_moons the same comparison yields 0.953 against 0.890, and the loss curve never flattens at 0.693 — because a linear model already scores 0.890 on that data. Two rows of your table, same 42 parameters, one flag apart, and a gap of about 6 points — against 51 points on circles. If you had only run moons you would have concluded, wrongly, that activations hardly matter. An experiment can only detect an effect the data is able to expose. Choosing data is part of the experiment, not a preliminary to it.

4.2.3 Prove the Composition Numerically

The collapse is not only an argument on paper. Fit the no-activation model, then fold the two layers into one matrix and compare outputs:

torch.manual_seed(42)
m = nn.Sequential(nn.Linear(2, 8), nn.Linear(8, 2))   # no activation

W = m[1].weight @ m[0].weight          # (2,8) @ (8,2) -> (2,2)
b = m[1].weight @ m[0].bias + m[1].bias

x = torch.randn(64, 2)
with torch.no_grad():
    print((m(x) - (x @ W.T + b)).abs().max().item())   # ~2e-7 (float32 round-off)
print(torch.linalg.matrix_rank(W).item())             # 2, not 8

The eight hidden units buy nothing: the composition is a 2×2 map. This is the fastest way to kill the belief that "deeper means more powerful" when the non-linearity is missing.

4.3 Modelling with nn.Module

From this chapter onward your model is a class you can reuse, print, save and move to a device. Following the convention is not formalism: build the layers in the wrong place and your parameters never train — while you believe the model is learning.

4.3.1 Four Rules

1 · Layers in __init__

Create every nn.Linear, nn.ReLU and nn.Dropout in __init__ and assign it to self. Only then is it registered in the module tree and visible to model.parameters().

2 · forward is data flow only

forward describes how tensors are computed, step by step. It never creates a layer, and it never holds hyper-parameter logic or prints.

3 · State the shapes

Comment the shapes: (N, 2) → (N, 8) → (N, 2). The output is logits — do not attach a softmax early.

4 · Make the model inspectable

print(model) should reveal the whole structure; the parameter count should be computable; model.to(device) should move everything in one line.

4.3.2 The Correct Form, and Two Mistakes That Never Train

# A - the correct form (copy this)
class MLP(nn.Module):
    def __init__(self, in_dim=2, hidden=16, n_class=2):
        super().__init__()
        self.net = nn.Sequential(
            nn.Linear(in_dim, hidden),
            nn.ReLU(),
            nn.Dropout(0.2),
            nn.Linear(hidden, n_class),
        )

    def forward(self, x):
        return self.net(x)          # (N,2) -> (N,16) -> (N,2) logits

# B - why these two never train
fc1 = nn.Linear(2, 16)                 # mistake 1: a module-level global

class BadA(nn.Module):
    def forward(self, x):
        return fc1(x)                 # not in model.parameters()

class BadB(nn.Module):
    def forward(self, x):
        layer = nn.Linear(x.shape[1], 2)
        return layer(x)                # mistake 2: fresh random params each call
The Dangerous Part Is the Silence In mistake 1 the optimiser never sees the parameters, and nothing raises an error. In mistake 2 every call uses newly random parameters with nowhere to store gradients. The test is simple: a layer that does not appear in print(model) does not exist.

4.3.3 Common Layers and the Parameter Count

model = nn.Sequential(
    nn.Linear(2, 16),   # 48 parameters = 2*16 + 16
    nn.ReLU(),          # same shape, 0 parameters
    nn.Dropout(0.2),    # active in train() mode only
    nn.Linear(16, 2),   # 34 parameters = 16*2 + 2 -> logits
)

n = sum(p.numel() for p in model.parameters())
print(n)               # 82
model.eval()           # switch to eval before testing: dropout off

4.4 Width, Depth and Capacity

A bigger architecture is not a better one — but "bigger is worse" is not a law either. Both directions have to be measured, and the measurement depends on the data. Three readings, each of which needs the dataset column to mean anything:

  • Rows 2 and 3 — identical parameter counts, one nn.ReLU() apart. On make_circles that is 0.473 versus 0.980; on make_moons it is 0.890 versus 0.953. The 51-point gap on circles against the 6-point gap on moons is the dataset's doing, not the architecture's.
  • Row 4 onward — going from 322 to 4,482 to 67,074 parameters buys nothing at all. Capacity helps until it does not.
  • The last row — 67,074 parameters is about 15× the previous row and 1,600× the 2-8-2 row, yet validation accuracy does not improve on circles and the train/validation gap widens. Not "capacity is harmful", but this much capacity is not where the remaining error is.
Report the Dataset, Not Just the Number A validation accuracy with no dataset beside it is not a result. The same architecture, the same seed and the same optimiser produce a 51-point contrast on one dataset and a 6-point contrast on another. Every ablation row you publish must name its dataset.

4.4.2 Train and Validation Diverge

As capacity grows, training accuracy climbs towards 1.00 while validation accuracy eventually stops improving. The gap between the two curves is overfitting, and it grows with capacity. The gap — not the training number — is what tells you whether the extra parameters did any work.

4.4.3 One Variable at a Time

CONFIGS = [                          # one variable per row
    ("2-8-2     ReLU", [8],      True),
    ("2-8-2     none", [8],      False),
    ("2-64-2    ReLU", [64],     True),
    ("2-64-64-2 ReLU", [64, 64], True),
]

def build(hidden, use_relu, in_dim=2, n_class=2):
    layers, prev = [], in_dim
    for h in hidden:
        layers += [nn.Linear(prev, h)]
        if use_relu:
            layers += [nn.ReLU()]
        prev = h
    layers += [nn.Linear(prev, n_class)]
    return nn.Sequential(*layers)

for name, hidden, use_relu in CONFIGS:
    model = build(hidden, use_relu)
    n = sum(p.numel() for p in model.parameters())
    print(f"{name:18s} {n:7d}")

Note that both the widths and the presence of the ReLU are parameters of build(): change the configuration and the network changes, without touching a single line of training code. That is modularity paying off.

4.5 Parameter Initialisation

Initialisation decides where training starts. It is easy to ignore until it silently costs you half your accuracy.

# nn.Linear's default initialisation is kaiming_uniform, uniform on
# [-1/sqrt(in), 1/sqrt(in)]. One apply() rewrites every submodule.
def init_weights(m):
    if isinstance(m, nn.Linear):
        nn.init.kaiming_normal_(m.weight)
        nn.init.zeros_(m.bias)

torch.manual_seed(42)
model.apply(init_weights)
InitialisationEffectVerdict
Default (kaiming_uniform)Reasonable for most cases; scale depends on fan-inFine to leave alone
kaiming_normal + zero biasMatches ReLU's variance behaviourThe standard pairing for ReLU networks
All zerosEvery hidden unit computes the same thing foreverBroken: the network has one effective unit per layer
All identical constantsSame symmetry problem, slightly less extremeBroken for the same reason
Why Symmetry Breaks With identical initial weights, every hidden unit receives the same gradient and moves identically. They never differentiate, so a layer of 64 units behaves like a layer of one. Randomness at initialisation is not noise to be removed — it is the mechanism that lets units specialise.

The integrated quiz

Three parts, mirroring the three pieces above, completed in class. It is the same structure as the milestone, which is the point: the review checks whether the module holds together, not whether one week was understood in isolation.

Two questions the review will ask. First, do the three pieces agree with each other — does the model consume exactly what the pipeline produces? Second, is the ablation table evidence, or decoration? A table with the correct four columns but no conclusion per row is decoration.

4.7 Pitfalls and a Debugging Checklist

Checklist
  • Not in print(model), not trained. Layers created in forward or stored as globals are invisible to the optimiser.
  • Layers belong in __init__. Assign to self so they are registered in the module tree.
  • Output logits, not probabilities. CrossEntropyLoss contains softmax; adding another one flattens the gradients.
  • Count the parameters. sum(p.numel() for p in model.parameters()) must agree with your hand calculation.
  • model.eval() before testing, model.train() after. Otherwise Dropout keeps dropping units and the metric changes every run.
  • Never initialise to constants. Identical units learn identically and the layer collapses to one effective unit.
  • Change one variable per comparison. Fix the seed, the split, the epochs, the optimiser and the learning rate before you start.
  • Treat a flat loss curve as data. A loss pinned at 0.693 is a finding, not a bug.
  • Report a conclusion, not a number. Every ablation row needs a sentence about what it proves.

4.8 Summary and Exercises

Five Takeaways
  1. One neuron draws one line; a hidden layer transforms features so that linearly inseparable problems become separable — and whether a dataset is linearly separable is a number you measure, not a shape you recognise.
  2. The forward pass is matrix multiplies plus element-wise non-linearity, repeated. Remove the activation and the network is a linear model — the two affine maps compose into one, verifiable numerically to about 1e-7.
  3. The nn.Module convention: layers created in __init__ and registered on self, forward describing data flow only, output logits.
  4. Initialisation sets the starting point: pair ReLU with kaiming; constant initialisation leaves hidden units symmetric and undifferentiated.
  5. Bigger is not automatically better, and it is not automatically worse — it is measurable, per dataset. Only a controlled experiment in which one variable changes at a time tells you which configuration wins, and every reported number needs its dataset attached.
