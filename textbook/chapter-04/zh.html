第 04 章 · 模块一 · 第 4 周

神经网络与 nn.Module 建模

第 2 章用原始张量训练了一个模型，第 3 章为它建好了数据管道。本章给这个模型一个「形状」，为模块一收尾。你要从一个神经元走到多层网络，发现非线性的存在与否决定了「深」这件事是否有意义，学会按 PyTorch 期望的方式写模型，并最终用一张消融对照表而不是凭感觉来决定网络该有多宽、多深。

4.1 从感知机到多层感知机

一个神经元做的是「加权求和 + 阈值判断」，它就是一个附带了判别规则的线性模型，只能画出唯一的一条直线。

4.1.1 三代结构

① 感知机（1958）

只有一个神经元。能解 AND 与 OR，解不了 XOR——没有任何一条直线能把两类分开。

② 多层感知机

隐藏层先做特征变换，输出层再做判断。同一批数据在新空间里变得可分。

③ 现代深度网络

几十到上百层。从结构上看，它仍然是「仿射变换 + 非线性」的堆叠，只是叠加了结构与技巧。

4.1.2 单层 vs 带隐藏层

单层（线性）隐藏层 + 激活
形式y = σ(Wx + b)h = ReLU(W₁x + b₁); y = W₂h + b₂
决策边界一条直线（高维是超平面）可以弯曲——分段线性拼接
能处理只有线性可分的数据线性不可分的数据
make_circles（同心圆环）0.473——与瞎猜无异0.980（2-8-2，300 轮）
make_moons（两个弯月）0.890——本身已接近可分0.953（2-8-2，300 轮）
常见误解 make_moons 常被说成「线性不可分」，正因为如此它是个很差的演示数据集：在固定协议下实测，线性模型在它上面已经有 约 0.89。 要展示隐藏层到底带来了什么，请用 make_circles 或 XOR。线性可分性要测，不能凭散点图形状想当然。

关键不是「层多」，而是层与层之间有非线性。两个仿射变换之间什么都没有，它们会合并成一个仿射变换，所以叠多少层线性层都还是线性模型。

4.1.3 前向传播，逐步走一遍

输入——一批 x，形状 (N, 2)：N 个样本，每个 2 维特征。
线性层 1——z1 = x @ W1.T + b1，形状 (N, 8)：特征被升到新空间。
激活——h = ReLU(z1)，仍是 (N, 8)：逐元素，零参数。
线性层 2——z2 = h @ W2.T + b2，形状 (N, 2)：这就是 logits。
损失——CrossEntropyLoss(z2, y)。softmax 已经在里面了，不要再加一次。
部件权重形状参数量说明
输入 x(4, 2)04 个样本，每个 2 维特征
nn.Linear(2, 4)W (4, 2), b (4,)122 → 4：参数 = 2×4 + 4
nn.ReLU()(4, 4)0逐元素，形状不变、零参数
nn.Linear(4, 2)W (2, 4), b (2,)104 → 2 类 logits：4×2 + 2
合计—22前向 = 两次矩阵乘法 + 一次非线性
读法 nn.Linear(in, out) 的参数量永远是 in × out + out。从本章开始，评估任何一个网络的第一件事就是数它的参数。

4.2 激活函数与非线性

激活函数是网络中「非线性能力」的唯一来源。去掉它，无论叠多少层，网络都会退化为一个线性模型。

4.2.1 四大家族

Sigmoid

σ(z) = 1/(1+e⁻ᶻ)，输出 (0,1)，可以当概率来读。导数最大只有 0.25，深层里梯度衰减极快。现在主要用于输出层的二分类概率。

Tanh

输出 (−1,1)，以 0 为中心，比 sigmoid 好训。但它仍然会饱和，梯度消失问题并没有被解决。常见于早期 RNN 与部分 Transformer 变体。

ReLU

max(0, z)。正区间梯度恒为 1，计算最便宜。负区间输出 0，可能出现「神经元死亡」。隐藏层的默认选项。

LeakyReLU

max(0.01z, z)。负区间留一点斜率，神经元不会彻底死掉。代价是多一个超参数，收益并不总是明显。

函数输出范围梯度特性推荐用法
Sigmoid(0, 1)最大 0.25，深层衰减极快输出层二分类概率；隐藏层避免使用
Tanh(−1, 1)最大 1.0，仍然会饱和需要零中心输出时用；深层仍不推荐
ReLU[0, +∞)正区间恒为 1，不衰减隐藏层默认选择；配 kaiming 初始化
LeakyReLU(−∞, +∞)负区间有小斜率 0.01ReLU 大量神经元不激活时的备选

4.2.2 你应该亲手跑一遍的实验

同一套协议、两个数据集，只差一个开关。之所以两个都跑，是因为单个数据集可以把你正要测量的那个效应本身藏起来。

import torch, torch.nn as nn
from sklearn.datasets import make_moons, make_circles
from sklearn.model_selection import train_test_split

def load(kind):
    if kind == "moons":
        X, y = make_moons(n_samples=1000, noise=0.25, random_state=42)
    else:
        X, y = make_circles(n_samples=1000, noise=0.10, factor=0.5,
                            random_state=42)
    Xtr, Xva, ytr, yva = train_test_split(X, y, test_size=0.3,
                                          random_state=42, stratify=y)
    t = lambda a, d: torch.tensor(a, dtype=d)
    return (t(Xtr, torch.float32), t(Xva, torch.float32),
            t(ytr, torch.long),    t(yva, torch.long))

class MLP(nn.Module):
    def __init__(self, use_relu=True):
        super().__init__()
        self.fc1 = nn.Linear(2, 8)
        self.fc2 = nn.Linear(8, 2)
        self.act = nn.ReLU() if use_relu else nn.Identity()

    def forward(self, x):
        return self.fc2(self.act(self.fc1(x)))   # (N,2) -> (N,8) -> (N,2)

def run(data, use_relu, seed=42, epochs=300, lr=1e-2):
    Xtr, Xva, ytr, yva = data
    torch.manual_seed(seed)
    model = MLP(use_relu)
    opt = torch.optim.Adam(model.parameters(), lr=lr)
    crit = nn.CrossEntropyLoss()
    for _ in range(epochs):
        opt.zero_grad()
        loss = crit(model(Xtr), ytr)
        loss.backward(); opt.step()
    model.eval()
    with torch.no_grad():
        acc = (model(Xva).argmax(1) == yva).float().mean().item()
    return acc, loss.item()

for kind in ("moons", "circles"):
    d = load(kind)
    a_on,  l_on  = run(d, True)
    a_off, l_off = run(d, False)
    print(f"{kind:8s} ReLU {a_on:.3f} (loss {l_on:.3f})  "
          f"none {a_off:.3f} (loss {l_off:.3f})")

在这套协议下实测得的数：

数据集2-8-2 · ReLU2-8-2 · 无激活无激活的最终损失
make_moons0.9530.8900.322
make_circles0.9800.4730.693
要记住的那个数字 在 make_circles 上，无激活的损失停在 0.693，也就是 ln 2——二分类瞎猜的损失。两个 nn.Linear 之间没有非线性，等价于一个线性层， 而线性模型分不开两个同心圆环。那条平线不是 bug，它就是结论。
为什么由数据集决定 在 make_moons 上，同一个对照得到 0.953 与 0.890，损失曲线也从来不会在 0.693 处变平——因为线性模型在那个数据上本身就有 0.890。 同一张表里的两行，同样的 42 个参数，只差一个开关，差距只有约 6 个百分点——而 circles 上是 51 个百分点。如果你只跑了 moons，你会得出一个错误结论：激活函数无关紧要。 一个实验只能检测出数据有能力暴露的效应。选数据是实验的一部分，不是实验之前的预备动作。

4.2.3 把「塌缩」用数值证出来

这种塌缩不只是纸上的论证。把无激活模型拟合好，再把两层折成一个矩阵，比较两者输出：

torch.manual_seed(42)
m = nn.Sequential(nn.Linear(2, 8), nn.Linear(8, 2))   # 无激活

W = m[1].weight @ m[0].weight          # (2,8) @ (8,2) -> (2,2)
b = m[1].weight @ m[0].bias + m[1].bias

x = torch.randn(64, 2)
with torch.no_grad():
    print((m(x) - (x @ W.T + b)).abs().max().item())   # ~2e-7（float32 舍入误差）
print(torch.linalg.matrix_rank(W).item())             # 2，不是 8

那 8 个隐藏单元一个都没换来：复合结果只是一个 2×2 的映射。当非线性缺席时，这是击碎「越深越强」这个信念最快的办法。

4.3 nn.Module 规范建模

从本章开始，你的模型不再是一串散装代码，而是一个可以被复用、打印、保存、搬到设备的类。遵守规范不是形式主义：层建在错误的位置，参数就不会被训练——而你还以为模型在学。

4.3.1 四条纪律

① 层在 __init__ 里建

所有 nn.Linear、nn.ReLU、nn.Dropout 都在 __init__ 里创建并赋给 self。只有这样它才被注册进模块树，model.parameters() 才拿得到它。

② forward 只写数据流

forward 只描述张量如何一步步算过去。它绝不新建层，也不放超参数逻辑或打印语句。

③ 形状要说得清

把形状注释写出来：(N, 2) → (N, 8) → (N, 2)。输出是 logits，不要提前接 softmax。

④ 让模型可检查

print(model) 应该能看出完整结构；参数量应该算得出来；model.to(device) 应该能一行搬到设备上。

4.3.2 规范写法与两种「训练不动」的错法

# A —— 规范写法（照这个写）
class MLP(nn.Module):
    def __init__(self, in_dim=2, hidden=16, n_class=2):
        super().__init__()
        self.net = nn.Sequential(
            nn.Linear(in_dim, hidden),
            nn.ReLU(),
            nn.Dropout(0.2),
            nn.Linear(hidden, n_class),
        )

    def forward(self, x):
        return self.net(x)          # (N,2) -> (N,16) -> (N,2) logits

# B —— 这两种写法永远训不动
fc1 = nn.Linear(2, 16)                 # 错法 1：模块级全局变量

class BadA(nn.Module):
    def forward(self, x):
        return fc1(x)                 # 不在 model.parameters() 里

class BadB(nn.Module):
    def forward(self, x):
        layer = nn.Linear(x.shape[1], 2)
        return layer(x)                # 错法 2：每次调用都是新的随机参数
危险的地方在于「不报错」 错法 1 的参数永远不会被优化器看到，而程序不会抛任何异常。错法 2 每一步都在用新的随机参数，梯度无处可存。判据很简单：在 print(model) 里看不到的层，就等于没建。

4.3.3 常用层与参数量

model = nn.Sequential(
    nn.Linear(2, 16),   # 48 个参数 = 2*16 + 16
    nn.ReLU(),          # 形状不变，0 参数
    nn.Dropout(0.2),    # 只在 train() 模式下生效
    nn.Linear(16, 2),   # 34 个参数 = 16*2 + 2 -> logits
)

n = sum(p.numel() for p in model.parameters())
print(n)               # 82
model.eval()           # 评估前切到 eval：关掉 dropout

4.4 宽度、深度与模型容量

结构不是越复杂越好——但「越大越差」也不是定律。两个方向都必须量出来，而且量出来的结果取决于数据。下面是同一套协议下（1,000 个样本、7:3 分层划分、seed=42、Adam lr=1e-2、300 轮）在两个数据集上的同一张表。

4.4.1 消融对照表

配置参数量验证准确率 · circles验证准确率 · moons结论
2 → 2（线性，第 2 章基线）60.4730.890没有隐藏层，只能画一条直线
2-8-2 · 无激活420.4730.890有隐藏层但没有激活，仍然是那条直线

2-64-2 · ReLU3220.9900.960加宽有效，但收益已经开始变缓
2-64-64-2 · ReLU4,4820.9870.960再加一层已经换不来收益——circles 上反而略降

三条读法，每一条都必须带着「哪个数据集」这一列才有意义：

  • 第 2、3 行——参数量完全相同，只差一个 nn.ReLU()。在 make_circles 上是 0.473 对 0.980；在 make_moons 上是 0.890 对 0.953。circles 上 51 个百分点的落差、moons 上 6 个百分点的落差，是数据集决定的，不是结构决定的。
  • 第 4 行往后——从 322 涨到 4,482 再涨到 67,074 个参数，什么都没换来。容量有用，直到它不再有用。
  • 最后一行——67,074 个参数大约是上一行的 15 倍、2-8-2 那一行的 1,600 倍，但 circles 上的验证准确率没有提升，训练/验证缺口反而最大。这不是「容量有害」，而是这么多容量并不是剩余误差所在的地方。
报数字，也要报数据集 一个不带数据集的验证准确率不构成结果。同一个结构、同一个种子、同一个优化器，在一个数据集上做出 51 个百分点的反差，在另一个数据集上做出 6 个百分点的反差。 你发表的每一行消融数据都必须写明它跑在哪个数据集上。

4.4.2 训练与验证开始分叉

随着容量增大，训练准确率一路爬向 1.00，而验证准确率最终不再提升。两条曲线之间的缺口就是过拟合，并且随容量一起变大。判断额外参数有没有干活，看的是这个缺口，而不是训练集上的那个数字。

4.4.3 一次只改一个变量

CONFIGS = [                          # 每一行只改一个变量
    ("2-8-2     ReLU", [8],      True),
    ("2-8-2     none", [8],      False),
    ("2-64-2    ReLU", [64],     True),
    ("2-64-64-2 ReLU", [64, 64], True),
]

def build(hidden, use_relu, in_dim=2, n_class=2):
    layers, prev = [], in_dim
    for h in hidden:
        layers += [nn.Linear(prev, h)]
        if use_relu:
            layers += [nn.ReLU()]
        prev = h
    layers += [nn.Linear(prev, n_class)]
    return nn.Sequential(*layers)

for name, hidden, use_relu in CONFIGS:
    model = build(hidden, use_relu)
    n = sum(p.numel() for p in model.parameters())
    print(f"{name:18s} {n:7d}")

注意隐藏层宽度和「有没有 ReLU」都是 build() 的参数：配置一变，网络就变，而训练代码一行都不用改。这就是「模块化」最直接的好处。

4.5 参数初始化

初始化决定训练从哪里出发。它很容易被忽略，直到你悄悄损失掉一半准确率。

# nn.Linear 的默认初始化是 kaiming_uniform，即在
# [-1/sqrt(in), 1/sqrt(in)] 上的均匀分布。一次 apply 就能全部改写。
def init_weights(m):
    if isinstance(m, nn.Linear):
        nn.init.kaiming_normal_(m.weight)
        nn.init.zeros_(m.bias)

torch.manual_seed(42)
model.apply(init_weights)
初始化方式效果结论
默认（kaiming_uniform）多数情况下够用；尺度依赖 fan-in可以不动
kaiming_normal + 零偏置与 ReLU 的方差特性匹配ReLU 网络的标准搭配
全部初始化为 0所有隐藏单元永远算一样的东西坏的：每层实际上只有一个有效单元
全部初始化为同一常数同样的对称问题，只是没那么极端同样坏的
对称性为什么会被打破不了 如果初始权重完全相同，每个隐藏单元收到的梯度也完全相同，于是它们始终同步移动、永远不分化，一层 64 个单元就表现得像 1 个。初始化里的随机性不是要被消除的噪声，而是让单元能够分工的机制。

4.6 模块一里程碑：三件事凑齐一套

模块一在这里收官，而里程碑刻意是「整个模块」而不是「只有模型」。没有数据的模型是演示，没有模型的数据是表格。

① 问题定义单 （自 W1 起）

目标用户、你要解决的问题、你真正拿得到的数据、一个成功指标与一个失败判据。你必须能用一句话说清自己在做什么。

② 数据管道 （自 W3 起）

清洗、划分与 Dataset/DataLoader 代码。划分比例写在配置里，泄漏自查做过，换台机器用同一份脚本能重建数据集。

③ 模型与对照实验 （今天，W4）

用 nn.Module 定义的 MLP，参数量算得出来，输出是 logits，并用一张消融对照表说明「为什么是这个配置」。

综合小测

当堂完成，三部分与上面三件交付一一对应。结构与里程碑完全一致，这正是重点：评审看的是这个模块能不能拼成一体，而不是某一周有没有单独学懂。

4.7 常见误区与调试清单

自查清单
  • print(model) 里看不到的层，等于没建。在 forward 里创建、或存成全局变量的层，优化器根本看不到。
  • 层属于 __init__。赋给 self 才会被注册进模块树。
  • 输出 logits，不是概率。CrossEntropyLoss 里已含 softmax；再加一次会把梯度压平。
  • 把参数量算出来。sum(p.numel() for p in model.parameters()) 必须与手算一致。
  • 评估前 model.eval()，之后 model.train()。否则 Dropout 仍在丢弃，指标偏低且每次不同。
  • 绝不初始化为常数。完全相同的单元会学出完全相同的参数，一层塌缩成一个有效单元。
  • 每次对照只改一个变量。开始之前先把种子、划分、轮数、优化器、学习率全部固定。
  • 把平直的损失曲线当成数据。损失钉在 0.693 是一个发现，不是 bug。
  • 交结论，不是数字。消融表每一行都要有一句「它证明了什么」。

4.8 小结与练习

五条要点
  1. 一个神经元只画一条直线；隐藏层做特征变换，让线性不可分的问题变得可分——而一个数据集是否线性可分，是你量出来的数字，不是你看散点图认出来的形状。
  2. 前向传播 = 矩阵乘法 + 逐元素非线性，重复若干次。去掉激活，网络退化为线性模型——两个仿射变换会合并成一次，可以用数值验证到约 1e-7。
  3. nn.Module 规范：层在 __init__ 创建并注册到 self，forward 只描述数据流，输出 logits。
  4. 初始化决定起点：ReLU 配 kaiming；常数初始化会让隐藏单元永远对称、永远不分化。
  5. 结构不是越大越好，也不是越大越差——它是可测量的，而且逐数据集不同。只有一次只改一个变量的对照实验能告诉你哪个配置胜出，而每一个报出来的数字都必须附上它的数据集。

练习 3 · 把模型搞坏三次（必做）

下面每个「坏模型」，先预测会发生什么，再实际运行并记录真正的结果。

  1. 把层存成模块级全局变量并在 forward 里使用。检查 len(list(model.parameters()))。
  2. 在 forward 里每次调用都新建层。训练 50 轮后与正确版本的损失对比。
  3. 正确模型 + 在 CrossEntropyLoss 之前多加一个 nn.Softmax(dim=1)。对比正确版本第一轮的损失，并解释差异。
