Training Loop, Loss and Optimizer

⏱ Weekly 180-min integrated session · this plan covers the Lecture Part, 90 min (L1–L5) 📚 Chapter 5.1–5.5 🎯 Module 2 · Core Deep Learning (Week 5–8) — first week of the module 🧩 Lesson Plan ID: LP-W5-A 🖼 Deck: 29 pages (this part covers p1–p20) 🌐 English

1. Learning Objectives

Knowledge

  • Choose the right loss for a task: CrossEntropyLoss for multi-class, BCEWithLogitsLoss for binary and multi-label, MSELoss for regression
  • State why a loss with WithLogits in its name — or CrossEntropyLoss — must be fed raw logits, never probabilities
  • Explain what each optimizer does to the gradient before the step: SGD (the current gradient), momentum (an accumulated direction), Adam (a per-parameter adaptive step)
  • Describe how the learning rate appears in a loss curve — explosion, oscillation, crawl — and what a healthy curve looks like
  • Name the five steps of a training loop and the exact call for each
  • Explain how an optimizer's state relates to VRAM, and why doubling the batch size usually means raising the learning rate

Skills

  • Write the five-step training loop from memory, in the correct order
  • Recognise and repair the two silent bugs: softmax applied twice, and a missing optimizer.zero_grad()
  • Read a (train_loss, val_loss, val_acc) log and name the failure mode it shows
  • Set up a controlled comparison where one variable changes and every other variable — including the initial weights — is pinned
Attitudes Internalise that tuning is experimental design, not luck. A hyper-parameter claim without a control run is an opinion. The professional habit this week is: change one thing, keep a log, and let the curve — not your memory — decide which configuration wins.

4. Key Activity Design

Activity 1 · Write the Five Steps Before You See Them (L5, p17)

Before revealing the flow diagram, give the class 90 seconds to write the five steps and their calls on paper. Then show p17 and have students correct their own sheet. In every cohort most of the room omits step 1. That omission is the lesson: optimizer.zero_grad() is the step with no visible output, so it is the step people forget — and forgetting it makes gradients accumulate across batches.

Activity 2 · Spot the Double Softmax (L2, p6–p7)

Put the two-line snippet on screen and ask the room to predict which loss will be printed. Run it: 2.2865 versus 2.3002. "Almost the same" is the correct first reaction — then let it train and show the accuracy curves separating. The punchline: a mistake that raises no exception is more expensive than one that does.

Activity 3 · Name the Optimizer From the Update Rule (L3, p10)

Read column two of the comparison table aloud — "one step along the current gradient", "accumulate past gradients into inertia", "adaptive per-parameter step" — and ask students to name the optimizer and predict what happens to each when the learning rate goes to 1e-1. The predicted answer (plain SGD survives; momentum and Adam do not) is exactly what the lab then measures.

Activity 4 · Predict the Curve Before You See It (L4, p15)

Show only the axes of the learning-rate diagnostic chart — ten epochs, loss from 0 to 2.8 — and have students sketch three curves by hand: lr=1e-1, 1e-3, 1e-5. Then reveal the real chart. Sketching first makes the three shapes memorable and turns the chart into a diagnostic tool instead of an illustration.

Activity 5 · The Gradient That Would Not Reset (L5, p18)

Run three steps without zero_grad() and print the summed gradient each time: 11.78, 23.58, 35.39 — a straight line upward. Ask what the optimizer will do with a gradient roughly three times too large. Then add the one line and re-run. This is the most useful three minutes of the session, because the bug reappears in real project code every term.
