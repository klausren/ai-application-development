1. Learning Objectives

Knowledge

  • State why a two-layer network without a hidden activation is mathematically a linear model
  • Recognise 0.693 (= ln 2) as the loss of a binary classifier at chance and say what it implies
  • Explain why a dataset must be chosen so that the effect under test is visible: a linear model already reaches ≈0.89 on make_moons, so the activation effect there is far smaller than on make_circles
  • State the four rules of nn.Module and the symptom of breaking each one
  • Explain why an ablation table needs one variable changed per row
  • Explain what the gap between train and validation accuracy measures

Skills

  • Build an nn.Module subclass parameterised by depth, width and activation
  • Run the same experiment under two settings differing by one boolean
  • Produce a four-column ablation table with a conclusion per row
  • Make every reported number reproducible with one command and a recorded seed
  • Push the Module 1 milestone M4 (problem sheet + pipeline + model) before the lab ends
Attitudes Write conclusions, not numbers. A table row without a sentence explaining what it proves is not a result. Treat an AI-suggested architecture as a hypothesis to be tested — testing it and finding it wrong is a successful outcome, and it belongs in the log.

4. Key Activity Design

Activity 1 · Freeze the Board (Lab A, p22)

Write the frozen settings on the board at the start of the lab and leave them there for the whole session: make_moons(1000, noise=0.25), 7:3 split, random_state=42, set_seed(42), Adam lr=1e-2, 300 epochs. Every ablation row must use exactly these. Students who change one of them to "improve" a result have invalidated the comparison, and the board is the evidence.

Activity 2 · The Flat Line Is the Result (Lab B, p23–p24)

On make_circles the no-activation loss sits at 0.693 for the whole run. Students assume their code is broken and start debugging — stop them and ask what a blind coin flip would score on two classes: -ln(1/2) = 0.693. The "bug" is the finding. Then put the moons rows next to it, where the same code gives 0.890 without the activation and 0.953 with it — about 6 points against 51 — and ask the harder question: which of the two results would you have reported if you had only run moons? That is the whole point of the lab in one minute.

Activity 2b · Prove It Algebraically, Then Numerically (Lab B, p24)

For the no-activation model, multiply the two weight matrices on the board: W2(W1x + b1) + b2 = (W2W1)x + (W2b1 + b2). Then have students verify it in code — compute W = model[1].weight @ model[0].weight and compare model(x) against x @ W.T + b. The maximum difference comes out around 1e-7 (float32 round-off), and the effective weight matrix has rank 2. Two layers, one affine map, proven rather than asserted.

Activity 3 · Predict the Width Curve (Lab C, p24)

Before running the width sweep, each student draws on paper what they expect validation accuracy to look like as width grows from 4 to 128. Afterwards they overlay the real numbers. Most expect a straight rise; the real curve bends. The gap between their sketch and the measurement is the lesson about diminishing returns — and it is personal, not told.

Activity 4 · One Command or It Did Not Happen (Lab E, p24–p25)

Require python run_ablation.py to regenerate every number in the table before the report is accepted. If a number in the report cannot be produced by that one command, it is removed from the report. This is the smallest possible lesson in reproducibility, but it is the one that carries into every later week.

Activity 5 · Assemble the Milestone Out Loud (Lab F, p25–p26)

Each student names their three milestone pieces to a neighbour — the problem sheet, the data pipeline, and the model — and states which one is weakest. Naming the weak piece is what makes the milestone review honest, and it gives the instructor a precise place to help in the last ten minutes of Module 1.
