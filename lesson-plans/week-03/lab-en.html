1. Learning Objectives

Knowledge

  • Explain why the split must happen before scaling, imputation, feature selection and augmentation
  • State the single question that detects every kind of leakage
  • Name the two methods a custom Dataset must implement and what each returns
  • Name the four jobs of a DataLoader and why shuffle is True for train only
  • Explain why accuracy is the wrong metric when a class holds 4% of the data
  • State what a Data Card must contain, including its bias-and-limits section

Skills

  • Turn every exploration claim into one assert or one plot, and reconcile it with your own output
  • Split with a fixed torch.Generator and report sizes and class ratios for train/val/test
  • Implement __len__ and __getitem__ and verify the shape and dtype of a batch
  • Configure DataLoader with reasons, and confine augmentation to the training split
  • Treat imbalance and re-measure with per-class metrics
  • Push the capstone milestone M3 (src/data/ + runnable pipeline) before the lab ends
Attitudes Treat the Data Card as part of the deliverable, not as paperwork: if a reader cannot tell where the data came from and where your conclusions stop being valid, the pipeline is not finished. Use only data with a lawful, authorised source; de-identify personal data and never upload it to public tools.

4. Key Activity Design

Activity 1 · Refuse the Vague Criterion (Lab A, p25)

The first time a student writes "this column looks wrong", stop the room. Ask for the number that made them say it: a missing rate above 2%, a value outside the 1/99 percentiles, a duplicate count on a named key. This single intervention improves the whole cohort's Data Cards, because a criterion that cannot be written as a number cannot be audited.

Activity 2 · The AI Said It Was Balanced (Lab A, p25)

Project a plausible AI claim — "classes are balanced, you can train as is" — and have students run value_counts(normalize=True) and then write the assert that settles it. When a claim turns out false, it goes into AI_USE.md with the corrected conclusion. The target is not mistrust of AI; it is a repeatable way to check it.

Activity 3 · Break the Shape on Purpose (Lab C, p25)

Have students delete the [i] index in __getitem__ so it returns a whole column, then print the batch shape. Seeing (11, 32) instead of (32, 11) makes the shape rule memorable. Restore it, then state the rule out loud: for batch size B and F features, xb is (B, F).

Activity 4 · Two Leaks, One Line (Lab B–C, p25)

Instructor writes one line on the board: mu = df.drop(columns="label").mean(), then subtracts it from every row before the split is applied. Ask which set that mean was computed over. Students will say "all of them" — and that is the leak. The fix belongs in a comment they can point to: statistics come from the training split only.

Activity 5 · Fresh-clone reproducibility test (Lab F, p26–p27)

Have students clone their own repo into a new directory and run python src/train.py there. Absolute paths, an unpinned dependency and a hardcoded filename surface within seconds — far more convincingly than any checklist.
