1. 教学目标

知识目标

  • 建立文本到张量（text-to-tensor）的链路。把一个段落走完分词 Tokenisation、词表 Vocabulary、编码 Encoding、填充 Padding 四步，并说出每一步的典型错误
  • 解释为什么词表必须只从训练集统计，以及用全量数据建表会带来什么样的数据泄漏；本周模型实际只见到均值 1592 个词，而全语料词表是 3142
  • 说清词嵌入 Embedding 是什么、padding_idx=0 冻结了什么，以及为什么第 0、1 号位置要留给 <pad> 与 <unk>
  • 理解 RNN/LSTM 的门控机制。解释梯度消失与爆炸（vanishing & exploding gradients）在朴素 RNN 上破坏了什么，以及遗忘门、输入门、输出门如何把“记住什么”变成可学的量
  • 说清填充 Padding 与掩码 Masking：为什么需要定长张量、为什么本周 95.58% 的测试文档达不到 max_len = 96、以及不掩码的池化为什么会读到填充向量
  • 完成一个端到端的文本分类。把一次 6 分类实验整体读懂：五臂对照表、训练曲线、混淆矩阵与错分分析

能力目标

  • 会写 tokenise、build_vocab 与 encode_batch，并把每个样本的真实长度 lens 一直留到池化那一行为止
  • 会搭出模型 Embedding(64, padding_idx=0) → LSTM(96, batch_first=True) → Linear(6)，并读出参数量（种子 42 为 166,278）
  • 会用 (h * mask).sum(1) / mask.sum(1) 算掩码均值，并用 pack_padded_sequence 打包一个 batch 取最后一个真词的隐状态
  • 会把五个池化臂读成“5 个种子的均值 ± 标准差”，并报出最好与最差之间的差（0.2620）
  • 会读混淆矩阵，点名最差类对及其次数，并贴出至少 3 段错分原文
  • 会给指标排序：准确率与宏 F1（macro F1）同时报，并认出一个低于随机的模型（宏 F1 0.0711 对 1/6 ≈ 0.1667 的随机基线）
素质目标 · 思政 以用户为中心：文本分类的错误代价并不对称，指标选择要贴合业务。本周这条不是口号，而是当堂实测：last_step 臂的准确率是 0.2407，看上去“只是弱”；它的宏 F1 是 0.0711，低于 6 分类随机基线 1/6 ≈ 0.1667。各类召回率从 0.1750（W1）到 0.6643（W6），差 3.80 倍——只有宏 F1 能让这个差距可见。一份只报准确率的报告，会放过一个几乎不再识别最小类别的模型。

4.1 Part 1 · 从一段文本到一个张量：四步链路，每步一个典型错误（p3–p7，KT15）

LSTM 不认识字。它认识的是一个 (batch, seq_len) 的整数张量。本周 80% 的错误不发生在模型里，而发生在构造这个张量的那四步里——而每一步的失败，最后都会以“准确率不高”的形式出现，而不是在你写错的那一行。

步骤做什么典型错误本周证据
① 分词把字符串切成 token 序列。英文：小写 + 正则 [a-z][a-z'-]*，让 don't、state-of-the-art 保持完整直接按空白切分、然后祈祷。对中文来说这几乎必错按空白切分的 OOV 率为 0.9973，字符级为 0.0254——差 39 倍
② 词表把 token 映射成整数 id。min_freq=2 过滤只出现一次的词，上限 6000用全量数据建词表——那是把测试集信息漏进训练本周模型只见到均值 1592 个词（只从训练集统计）；全语料词表是 3142
③ 编码每个 token 换成 id：<pad>=0、<unk>=1，真词从 2 开始忘了 padding_idx=0，于是填充向量会吃到梯度、跟着漂nn.Embedding(vocab, 64, padding_idx=0) 让填充向量冻结；这个约定正是后面掩码要对齐的东西
④ 填充把同一个 batch 里的样本补零到等长补完零，然后把这些填充位置当成正常的词来读语料长度为中位 35、95 分位 87、最长 285 词；95.58% 的测试文档达不到 max_len = 96

语料是本课程第 1–6 周自己的材料：来自 lesson-plans/week-XX/lecture-en.html、lab-en.html、textbook/chapter-XX/en.html 与 labs/week-XX/lab-handout.md 的英文段落。许可为 CC BY-NC-SA 4.0，用 python scripts/build_text_corpus.py 离线重建，指纹 SHA-256 为 87e41aac89ef59903abca15eea4250e68eb9d29537c1cd78d251ad497a16b4b1。

4.2 Part 2 · 填充与掩码：那个安静的 bug（p8–p12，KT15）

两个模型，除最后一行的写法外逐字节相同，却讲完了整个故事。上半在 LSTM 之后取 out[:, -1, :]——那是第 96 个位置，在短文档上就是填充向量，不是句子。下半用 pack_padded_sequence 让循环在真词结束处停下，取最后一个真词的隐状态。参数量相同（166,278）、数据相同、轮数相同——唯一的差别就是“怎么把 (B, 96, 96) 压成 (B, 96)”。

按长度分桶，伤害就露出来了：伤害最重的地方，正好是填充占比最大的地方，并且随文档变长而消失。长度分界线上还有一条更硬的证据：last_step 种子 42 下，长度 ≥ 96 的文档（n = 5）准确率 0.4000，长度 < 96 的文档（n = 108）准确率 0.2315——长度够的文档没有填充位置，[-1] 就真的指向句末。这排除了“只是任务太难”的解释。一次 max_len 扫描又封掉了另一个借口：packed 在 48 / 96 / 192 上分别是 0.4572 / 0.4454 / 0.4454（波动在一个标准差以内），而 last_step 始终停在 0.2891 / 0.2389 / 0.2478。调 max_len 不是杠杆；选错池化方式，调什么长度都白搭。

掩码是正确性，不是优化 两个求均值的臂做的是同一件“对时间维求平均”的事，代码几乎逐字相同，差别只有一个布尔参数。不掩码 0.3929 对掩码 0.5027，是 +11.0 个点，标准差从 ±0.0684 收窄到 ±0.0449。注意哪一个桶涨得最多——最短的那一桶——因为那里填充向量在均值里占的比例最大。一个“写了就等于没写”的错误，是最贵的那种：程序不会崩，数字悄悄掉一半。

正则化救不回来——这是本周最重要的诚实结论 把第 6 周最有效的两样东西（Dropout 0.3 + 权重衰减 1e-3）加到本周最好的一臂上。测试准确率 0.5027 → 0.4672，下降 3.6 个百分点；宏 F1 从 0.4774 降到 0.4433，下降 3.4 个点；而且标准差反而从 ±0.0449 扩大 到 ±0.0595。第 6 周这两招是有效的，因为那里的数据够、模型大。同一个技术手段，在“容量瓶颈”和“数据瓶颈”下的正确答案是相反的。本周的瓶颈是 523 个训练段落，不是模型容量——所以要先诊断出瓶颈，再决定用不用正则化，而不是反过来。

最后一条证据是召回模式。把六个类按大小排序，召回率就几乎单调地排好了：W1 0.1750、W2 0.1867、W3 0.4235、W4 0.4778、W5 0.4211、W6 0.6643。有两处小逆序：W2（n=75）略高于 W1（n=80），W5（n=95）略低于 W4（n=90）。W6 的召回是 W1 的 3.80 倍。这是“模型在学先验，而不是在学内容”的直接证据——也正是“加正则化”没有用的原因：欠的是样本，不是约束。

The same data becomes separable in the new space." （2）通用工程句子，哪一周都成立——真 W1、判 W2，26 词："Hyper-parameters, data paths, batch size and split ratios live in a file or a single dictionary — not scattered through the code and not in your memory." （3）术语跨周复用——真 W6、判 W4，22 词（17,226 这个数字在第 4 周也讲过）："Explain how a training set of 80 samples against 17,226 parameters produces overfitting on purpose, and why that is the point of the lab." 14 篇里没有一篇是“模型看错了”——它们是任务定义的边界。正确的做法是把这个发现写进报告，而不是继续调参。

错分分析的交付标准有四条可检查项，对应官方课后任务（“说明为什么模型在某些类别上表现更差”）：① 打印矩阵并写出三个总数（565 / 240 / 0.4248），以及对角线上最大的一格（W6，93）；② 准确率与宏 F1 同时报并解释差距；③ 至少 3 段错分原文并附模型置信度；④ 写出一条能被下一步推翻的可检验假设，然后去跑它、把结果写回报告——不管涨没涨。

5. 思政与 AI 赋能

【思政】以用户为中心：指标选择是一种责任

  • 错误的代价并不对称，所以指标要贴合业务；当同一个模型换一个指标就得出相反结论时，这句口号就变成了可检查的东西
  • 准确率会放过一个坏模型：last_step 报 0.2407，看上去“只是弱”，而它的宏 F1 0.0711 低于 6 分类随机基线 0.1667——代价落在少数类用户身上，他们几乎从不被正确识别
  • 类别大小决定了谁被牺牲：W1（n = 80）召回 0.1750，W6（n = 140）召回 0.6643，差 3.80 倍，且总体随类别大小上升（Spearman ρ = 0.77）。只有宏 F1 能让这件事被看见；用加权 F1 或准确率，这个差距会被平均数抹平
  • 回看第 6 周：那里“最大化准确率”是对的（数据平衡、代价对称）；本周它是错的，因为它奖励模型去猜大类的先验。选指标之前先问：这一次，谁的错误更贵？

【AI 赋能】AI 生成整条管道，你去抓它的错

  • 第 1 步：让 AI 为一个变长输入的 6 分类文本任务写出完整的 PyTorch LSTM 前向传播，并说明它怎么处理填充——要求它给可运行代码而不是散文，而且先不要看老师给的参考实现
  • 第 2 步：拿一张检查清单，逐条在 AI 的代码里找错——没有传 lens（于是它只能取 [-1]）；词表建在全量数据上（数据泄漏）；漏了 padding_idx=0；池化用的是裸 mean 而不是掩码均值（裸均值就是本周第 4 名）
  • 第 3 步：用一张三列表记录修正前后的结果差异——AI 原代码怎么写 / 你改成了什么 / 修正前后准确率差多少。第三列是硬要求：“我发现了 bug”不算数，要有数字
  • 第三列的参考量级：裸均值 → 掩码均值是 +11.0 个点（0.3929 → 0.5027）；[-1] → packed 是 +18.4 个点（0.2407 → 0.4248）
  • 必须核查的典型 AI 回答：忽略长度时它常常直接写 out[:, -1, :]，也可能用全量数据建词表——这两点恰好就是本周的核心错误
