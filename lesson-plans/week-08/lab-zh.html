1. 教学目标

知识目标

  • 说出实验协议中被固定的各项设置，并解释每一项为什么必须固定
  • 解释为什么词表只能从训练集统计，以及不这样做会泄漏什么（模型只见到均值 1592 个词，而全语料词表是 3142）
  • 解释为什么 95.58% 的测试文档达不到 max_len = 96，以及 out[:, -1, :] 在短文档上取到的是什么
  • 解释为什么在其他一切都不变时，仅池化方式的选择就值 26.2 个点（0.5027 对 0.2407）
  • 解释为什么掩码是正确性而非优化（裸均值 → 掩码均值 +11.0 个点）
  • 解释为什么 last_step 的宏 F1 0.0711 低于 6 分类随机基线 1/6 ≈ 0.1667，而它的准确率 0.2407 看上去“只是弱”

能力目标

  • 会写 tokenise、build_vocab 与 encode，并把每个样本的真实长度 lens 一直留到池化那一行
  • 会用 nn.Embedding(padding_idx=0) → nn.LSTM(batch_first=True) → nn.Linear(6) 搭出模型，并数出参数量（种子 42 为 166,278）
  • 会用 (h * mask).sum(1) / mask.sum(1) 算掩码均值，并在第二个臂里用 pack_padded_sequence 打包
  • 会训练、画出训练与验证曲线，并把四臂池化对照表填成“5 个种子的均值 ± 标准差”
  • 会打印混淆矩阵、点名最差类对及其次数，并给出至少 3 段错分原文及其模型置信度
  • 会向 AI 索取整条管道的代码，定位其中的填充/掩码错误，并把修正前后的准确率差记进三列表
素质目标 · 思政 如实报告不成功的实验，也如实报告那个改变了结论的指标。本实验里有两个不那么舒服的事实要留在报告中：最好的一臂也只到 0.5027；而同一个模型报出的宏 F1 是 0.0711——低于随机——它的准确率 0.2407 看上去却“只是一般”。以用户为中心的习惯，就是把两个数字都报出来并解释差距，因为一份只报准确率的报告，会把一个几乎不再识别最小类别的模型送上线。

5. 代码骨架

把四个管道函数与模型补进去。形状链路是 (B, 96) 的 id → (B, 96, 64) 的嵌入 → (B, 96, 96) 的 LSTM 输出 → 掩码均值 (B, 96) → (B, 6) 的 logits。下面两个池化臂就是本实验的全部要点。

import re, collections, torch, torch.nn as nn
from torch.nn.utils.rnn import pack_padded_sequence

TOKEN = re.compile(r"[a-z][a-z'-]*")

def tokenise(text):                        # 小写 + 正则；keep don't whole
    return TOKEN.findall(text.lower())

def build_vocab(texts, min_freq=2, cap=6000):
    freq = collections.Counter()
    for t in texts:                        # texts = TRAIN split only
        freq.update(tokenise(t))
    words = [w for w, c in freq.most_common() if c >= min_freq][:cap]
    return {"<pad>": 0, "<unk>": 1,
            **{w: i + 2 for i, w in enumerate(words)}}

def encode(text, vocab, max_len=96):
    ids = [vocab.get(w, 1) for w in tokenise(text)][:max_len]
    ids += [0] * (max_len - len(ids))      # pad to a fixed length
    return torch.tensor(ids)

class TextLSTM(nn.Module):
    def __init__(self, vocab_size, hidden=96, n_classes=6):
        super().__init__()
        self.emb  = nn.Embedding(vocab_size, 64, padding_idx=0)  # pad 永远不更新
        self.lstm = nn.LSTM(64, hidden, batch_first=True)
        self.fc   = nn.Linear(hidden, n_classes)

    def forward(self, x, lens):
        e = self.emb(x)                      # (B, 96, 64)
        out, _ = self.lstm(e)                # (B, 96, 96)
        mask = (x != 0).unsqueeze(-1)        # (B, 96, 1)  1 = real token
        h = (out * mask).sum(1) / mask.sum(1).clamp(min=1)   # 掩码均值
        return self.fc(h)                    # (B, 6)

# 打包臂：同一个模型，只改最后三行
def forward_packed(self, x, lens):
    e = self.emb(x)
    order = torch.argsort(lens, descending=True)
    inv   = torch.argsort(order)
    packed = pack_padded_sequence(e[order], lens[order].cpu(),
                                  batch_first=True, enforce_sorted=True)
    out, (h, _) = self.lstm(packed)
    return self.fc(h[-1][inv])               # h[-1] = 每个样本最后一个真词

两个臂的唯一区别，就是“怎么把 (B, 96, 96) 变成 (B, 96)”：对真实位置求掩码均值，或取打包后的末隐状态。去掉掩码（裸均值臂）值 −11.0 个点；不打包直接取 out[:, -1, :] 值 −26.2 个点。四臂都跑一遍，把表填满。

6. AI 协同操作规程

先问、再找错、后测量——并把数字写下来

  1. 问：提示 AI 为一个变长输入的 6 分类文本任务写出完整的 PyTorch LSTM 前向传播，并说明它怎么处理填充。要求它给可运行代码，不要散文。先不要看老师给的参考实现——先让 AI 出初稿。
  2. 找错（这是评分点）：拿清单逐条在 AI 的代码里找。① 有没有传 lens 进去？没有，它就只能取 [-1]。② 词表是在全量数据上建的吗？那就是数据泄漏。③ 用了 padding_idx=0 吗？没有，填充向量就会吃到梯度。④ 池化是掩码均值，还是裸 mean？裸均值就是本周第 4 名。
  3. 测量：把修正后的代码与 AI 原代码都跑一遍，记录准确率差。参考量级：裸均值 → 掩码均值是 +11.0 个点（0.3929 → 0.5027）；[-1] → packed 是 +18.4 个点（0.2407 → 0.4248）。
  4. 留痕：把记录留在报告里——提问、AI 的代码、你的修改、实测结果、结论。一条建议可以“在一般情况下成立”却在“这个任务上无效”；被考核的是第三列那个数字。
必须核查的典型 AI 说法 “直接取最后一个隐状态 out[:, -1, :] 就行”忽略了 95.58% 的文档短于 max_len，那个位置其实是填充向量——实测代价是 26.2 个点。“词表可以用全量数据建”是数据泄漏，它会让报出的测试准确率虚高，也过不了真实部署。“掩码是可选的优化”是错的，裸均值比掩码均值低 11.0 个点。每条结论都来自学生自己的实测，不是来自 AI 的原文。
