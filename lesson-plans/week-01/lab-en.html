  • Create a conda environment independently and install the dependency list
  • Run notebooks in Jupyter/Colab and verify GPU availability
  • Initialize a project with Git and push to GitHub (with commit-message conventions)
  • Run the first Iris classifier and compare model results
Attitudes Build the professional habit of "one isolated environment per project"; experience troubleshooting (error diagnosis) as the daily skill of an AI engineer; complete the first versioned GitHub delivery and form the "commit when done" engineering habit.

4. Key Activity Design

Activity 1 · Troubleshooting clinic (between Lab A/B)

Project 3 typical errors onto the screen: ① a version conflict (numpy 2.x vs. old code); ② running python before activating the conda env; ③ a pip network timeout. Students diagnose in pairs for 3 minutes first; the instructor then gives the standard troubleshooting path and encourages class-wide peer help.

Activity 2 · Model-comparison challenge (Lab D)

After the Iris baseline, an extra challenge: train both LogisticRegression and SVC, record accuracies; then try 3 random_state values and observe the fluctuation. The fastest 3 students present their results table on stage — steering the discussion toward "model choice and randomness".

5. Lab Steps & Deliverables

  1. Environment setup: create the ai-app conda env (Python 3.11), install numpy pandas matplotlib seaborn scikit-learn torch jupyter, and export environment.yml.
  2. Notebook verification: create a notebook, verify import numpy, pandas, sklearn, torch succeed; open the same file in Google Colab and run torch.cuda.is_available().
  3. Git commit: local git init → add → commit → new GitHub repo → push. Commit-message convention: feat: week1 lab environment setup; configure .gitignore to exclude __pycache__ and .ipynb_checkpoints.
  4. First model: run the Iris classifier; compare LogisticRegression vs. SVC accuracy; record results for 3 random_state values and write conclusions in the notebook.
  5. Reflection questions (append to the notebook): name 3 products around you and classify them as ML/DL/GenAI; explain what random_state means for reproducibility; state which lifecycle stage "training the model" belongs to and its time share.
Deliverable (counts toward Lab participation 20%) ① environment.yml; ② the completed notebook (with reflection questions); ③ the GitHub repo link.
Deadline: next Monday 23:59. Late penalty: −10% per day.
