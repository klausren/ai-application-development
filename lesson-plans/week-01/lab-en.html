1. Learning Objectives

Knowledge

  • Explain what an isolated environment protects you from, and what goes into environment.yml
  • State the three things an environment self-check must prove: version, device, memory
  • Explain why a fixed seed makes two runs comparable, and which random sources must all be fixed
  • State the three components of the reproducibility standard: seed, config, version
  • State what a valid AI collaboration trace must contain

Skills

  • Create a conda environment, install PyTorch, and verify the device in one script
  • Run the same script twice with and without a seed, and prove the difference from the raw output
  • Export and commit the environment so a classmate can rebuild it
  • Create a Git record repository with a documented layout and naming convention
  • Push the M1 milestone: three topic proposals, PROJECT_PLAN.md and DEVLOG.md v0
Attitudes Treat the workbench as part of the deliverable. "It works on my machine" is a statement about your machine, not about your result. From today, every number you report must be reachable by one command in a README — and any AI assistance must be visible in the record, including where the AI was wrong.

4. Key Activity Design

Activity 1 · Read the Error Before You Fix It (Lab A, p22)

When import torch fails, students may not reinstall anything for the first two minutes — they must first answer three questions out loud: which interpreter is this shell using, which environment is active, and where is the package installed. This builds the reflex that a failing import is a path problem until proven otherwise.

Activity 2 · Predict the Second Run (Lab B, p24)

Before running, each student writes down whether they expect run1, run2 and no-seed to match. Then run it. The number of students surprised by run2 is exactly the number who have never checked whether their own results were reproducible.

Activity 3 · The Missing Random Source (Lab C, p24)

If a student's two runs differ, the class diagnoses it together rather than the instructor fixing it. Candidates in order of likelihood: the seed is set after data creation, numpy was never seeded, or a DataLoader with shuffling and workers was used. The diagnosis list matters more than the fix.

Activity 4 · Fresh Clone Check (Lab D, p25)

Each student clones their own repository into a different directory and rebuilds the environment from environment.yml while following only their own README. Absolute paths, missing files and a README that never mentions how to run anything surface immediately — far more convincingly than any checklist.

Activity 5 · Three Proposals, Not One Idea Tripled (Lab E, p26)

Students pair up and read each other's three proposals; each pair must name one proposal that is probably unimplementable and why. That is not a criticism — it is the point of writing three. The instructor then confirms each student's chosen topic and the cut list in the last five minutes.
