1. Learning Objectives

Knowledge

  • State the fixed items of the experiment protocol and explain why each one is fixed
  • Reconcile the parameter count of the CNN (1,898) against the dense control (17,226) layer by layer
  • Explain why the CNN and the 9.07x larger dense net differ by only 0.0023 in test accuracy, and why that is written up as not observed
  • Explain why 4.1 points of test accuracy hang on the pooling function alone
  • Explain why augmentation trades 3.0 points of clean accuracy for 29 points of translation robustness
  • Explain why the digit 8 carries 12 of the 26 errors in the confusion matrix

Skills

  • Build a CNN with nn.Conv2d, nn.MaxPool2d and nn.Linear, and assert the shape of every layer against the formula before training
  • Count the parameters with a small script instead of estimating them
  • Train the CNN, plot the training and validation curves, and read the five-architecture ledger as mean ± standard deviation
  • Print the confusion matrix, name the worst class pair with its count, and present 3 or more misclassified cases with their probabilities
  • Measure peak memory against batch size and reproduce the effective batch with gradient accumulation
  • Ask an AI for memory optimisations, test each one, and label it valid or invalid
Attitudes · Civic Education Report an experiment that did not work, and report the optimisation that did not help. In this lab augmentation lowers the clean test score on purpose (0.9808 to 0.9504) and one AI memory suggestion will not survive measurement. Both stay in the report and get explained. This is also the green-computing habit in practice: the 1,898-parameter CNN matches the 17,226-parameter dense net, so compute the parameter budget before adding parameters, and measure the memory peak before asking for hardware.

5. Code Skeleton

Fill in the three layer types; the shape chain is 8×8 → conv+P → 8×8 → pool → 4×4 → conv+P → 4×4 → pool → 2×2 → flatten 64 → FC 10. The assertions must pass before any training starts.

import torch, torch.nn as nn, torch.nn.functional as F

class CNN(nn.Module):
    def __init__(self, channels=(8, 16), n_classes=10):
        super().__init__()
        c1, c2 = channels
        self.conv1 = nn.Conv2d(1,  c1, kernel_size=3, stride=1, padding=1)  # 1x8x8 -> c1x8x8
        self.conv2 = nn.Conv2d(c1, c2, kernel_size=3, stride=1, padding=1)  # c1x4x4 -> c2x4x4
        self.pool  = nn.MaxPool2d(2)                                        # stride 2, halves the map
        self.fc    = nn.Linear(c2 * 2 * 2, n_classes)                       # flatten 16*2*2 = 64

    def forward(self, x):                      # x: (B, 1, 8, 8)
        x = self.pool(F.relu(self.conv1(x)))   # (B, 8, 4, 4)
        x = self.pool(F.relu(self.conv2(x)))   # (B, 16, 2, 2)
        x = x.flatten(1)                       # (B, 64)
        return self.fc(x)                      # (B, 10)

# 1) shapes: assert the formula against the real forward
def out_size(size, k, s, p):
    return (size + 2 * p - k) // s + 1
assert out_size(8, 3, 1, 1) == 8   # conv + padding keeps the size
assert out_size(8, 2, 2, 0) == 4   # pooling halves it

# 2) parameters: count them, do not estimate
n_conv = sum(p.numel() for p in CNN().parameters())
# conv1 = 3*3*1*8 + 8 = 80 ; conv2 = 3*3*8*16 + 16 = 1168 ; fc = 64*10 + 10 = 650
assert n_conv == 80 + 1168 + 650 == 1898

The dense control reuses an MLP from Week 4: nn.Linear(64, 128) → nn.Linear(128, 64) → nn.Linear(64, 10), 17,226 parameters. The augmentation arm applies a random ±1 pixel shift to the training batch only; the test batch is never shifted. The average-pooling variant is the same class with nn.AvgPool2d(2) in place of nn.MaxPool2d(2), byte-for-byte identical otherwise.

6. AI Collaboration Protocol

Ask, test, label — in that order

  1. Ask: prompt the AI for ways to reduce GPU memory for this week's model. Expect a list such as "halve the batch", "use gradient accumulation", "use mixed precision with torch.amp.autocast and GradScaler", "shrink the input".
  2. Test: run each suggestion on this machine and measure it. Halving the batch changes memory only; gradient accumulation with the share-of-group weighting reproduces the true batch-128 run at 5/5 and costs time, not accuracy; mixed precision changes the numerics, so the metric must be re-checked.
  3. Label: mark each suggestion valid or invalid, with the measured evidence and the cost beside it. A suggestion can be valid in general and still be invalid for this task — measured this week, this model never runs out of memory (the peak at batch 1024 is 582.0 MB), so "shrink the input to 16×16" is a cost with no benefit here.
  4. Record: keep the trace in the report — the prompt, the suggestions, the measurement, the verdict. Deleting an AI suggestion on the basis of your own measurement is the skill being assessed.
Typical AI claims to check "Gradient accumulation always saves memory" is only true when the accumulated gradient is weighted correctly; with the none and unscaled weightings the result no longer matches the true batch (2/5 seeds). "Always use mixed precision" trades numerics for memory and must be verified against the metric. Both claims are labelled from the student's own measurement, not from the AI text.

How to read the measured arms · three honest conclusions 1. The CNN matches a 9.07x larger dense net: 0.9808 against 0.9785 is a 0.0023 gap against a 0.0084 standard deviation, so the only defensible sentence is no significant difference was observed. 2. The pooling function is a design choice: max 0.9808 against average 0.9400 is a 4.1-point gap on identical parameter counts. 3. Augmentation is a trade, not a win: it buys 29 points of translation robustness (0.6481 to 0.9415 at dx = -1) and pays 3.0 points of clean accuracy (0.9808 to 0.9504 at dx = 0).
