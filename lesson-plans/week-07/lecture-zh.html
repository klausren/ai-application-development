1. 教学目标

知识目标

  • 理解卷积 Convolution与池化 Pooling：说清局部连接与权值共享 Weight Sharing，并说明卷积层相对全连接层的优势以及它为此付出的代价
  • 会逐层读出一个网络的参数量，并在同一份 digits 数据上把 17,226 个参数与 1,898 个参数对清楚
  • 会用输出尺寸公式 out = (in + 2p - k)/s + 1 计算 nn.Conv2d 与 nn.MaxPool2d 的输出，并沿着特征图 8×8 → 8×8 → 4×4 → 4×4 → 2×2 走一遍
  • 描述经典 CNN 结构（LeNet / AlexNet / VGG / ResNet 的思想）以及它们所服务的图像分类任务
  • 说清每种数据增强 Data Augmentation 策略的机理与代价，并能把五架构对照表读成「5 个种子的均值 ± 标准差」
  • 说清 GPU 显存、梯度累积与混合精度，足以在实验里处理显存不足（OOM）

能力目标

  • 能用 nn.Conv2d、nn.MaxPool2d 与 nn.Linear 搭出 CNN，并在训练前把每一层的形状与公式对齐（用断言，不靠感觉）
  • 能按递推 rf = rf + (k - 1) × jump 算出感受野 Receptive Field，并判断一个任务到底需要几层
  • 能训练 CNN 完成图像分类，记录训练曲线与混淆矩阵 Confusion Matrix，并写出点名最差类对的错分分析 Error Analysis
  • 能按正确顺序处置 OOM：先降 batch，再用梯度累积买回等效 batch，最后才考虑硬件
  • 能向 AI 询问显存优化方案，在本机逐条实测，并标注哪条有效、哪条无效
素质目标 · 思政 绿色计算：算力是有限资源，职业习惯是用更少的成本达成目标。本周这条不是口号，而是当堂实测：17,226 个参数拿到 0.9785，1,898 个参数拿到 0.9808——少 9.07 倍参数，测试准确率相差 0.0023，小于一个标准差（0.0084）。多出来的 15,328 个参数，在训练和推理里都要算、要传、要供电。在把模型做大之前，先问一句：这个规模是必要的吗？

4. 讲授内容详解

4.1 Part 1 · 卷积：从全连接到权值共享（p3–p7，KT13）

卷积就是一次滑动点积：取一块、逐元素相乘、求和，在每个位置重复一遍。由此得到三个性质——局部连接、权值共享，以及与图宽无关的参数量。课堂先手写朴素版 conv2d_naive，再用断言把它与 nn.Conv2d 对齐，而不是「相信它对」（p5）。

层 Layer形状 Shape参数 Params累计 Running
输入 Input1×8×800
全连接 64→12864→1288,3208,320
全连接 128→64128→648,25616,576
全连接 64→1064→1065017,226
卷积 1→8，3×38×8×83·3·1·8 + 8 = 8080
卷积 8→16，3×316×4×43·3·8·16 + 16 = 1,1681,248
线性 64→1064→1064·10 + 10 = 6501,898

上半是本周对照用的全连接网，下半是两层卷积加一个线性头。17,226 → 1,898，少 9.07 倍；两者的测试准确率是 0.9785 与 0.9808——差 0.0023，小于一个标准差（0.0084）。要写「未观察到显著差异」，不写「卷积更好」。卷积真正买到的，是平移容忍：把测试图右移一列，全连接掉到 0.5089，卷积还有 0.6504。

它付出的代价 局部性是假设，不是真理。如果你的有用模式是全局的（比如整张图的亮度分布），这个假设就是错的，卷积网会比全连接更差。感受野也是有限的：这里的最后一层卷积已经看到整张 8×8，再叠深度也不会增加平移不变性。池化会丢位置信息，而有些任务恰恰需要位置。

形状链路：8×8 → conv+P → 8×8 → pool → 4×4 → conv+P → 4×4 → pool → 2×2 → flatten 64 → FC 10。感受野递推得到 3 → 4 → 8 → 10。关键一行是「卷积 2」：感受野 8，正好等于整张图。在本周这个 8×8 数据上，第二层卷积已经能看到全图，网络再叠也拿不到更多平移不变性——这不是模型不好，是数据太小。

增强的账本：买 +29 个点，付 −3 个点 dx = −1 时，CNN 是 0.6481、增强 CNN 是 0.9415——买到了 +29 个点的鲁棒性。dx = 0 时，CNN 是 0.9808、增强 CNN 是 0.9504——付掉了 3.0 个点的干净精度，而且增强那条在 dx = 0 时是三条里最低的。增强没有提升上限，它把曲线压平了。它的训练准确率也不再冲上 1.000（第 115 轮 0.9292），过拟合被压住。要不要买，取决于一个产品问题：你的模型会遇到平移过的输入吗？如果用户是拿手机拍的——会，那就买；如果输入已被裁齐对齐——不会，那你只是白买。

「98%」不是一个结果，是一个不完整的句子。混淆矩阵才是把「98%」翻译成「它在哪两类之间犹豫」的那张表。行＝真实标签，列＝模型判断；对角是正确，非对角是错误。

测试预测总数 1,350（5 个种子合计），正确 1,324（0.9807），非对角错误 26 个。这 26 个错误里有 12 个与数字 8 有关（占非对角错误的 46.2%）。最差的类对是 8 → 1，出现 3 次。数字 0 是满分（135/135）；数字 8 最差（124/130，召回 0.9538）。

把错分的那个数字本身画出来 两个真实的 seed-42 测试样本：真 8，被判成 7，置信 0.9829——下半环被写断，上部只剩一撇，人眼看也像 7；真类概率只有 0.0144。以及真 6，被判成 8，置信 0.8852——这个 6 的下半环是闭合的，而 6 的下半环不该闭合；真类概率 0.0271。这才是错分分析：不是「模型还不够好」，而是「它在一个下半环闭合的 6 上会把 8 叫出来」——后者是可以修的。完整的交付标准有五条：打印混淆矩阵；点名最差的类对并给出次数；至少 3 个具体错分样本并附模型概率；每条错误配一个可检验的假设；写出下一步以及如何判断有没有用。

4.5 Part 5 · 显存与绿色计算（p22–p26，KT14）

显存不足（OOM）是本周实验最常见的卡点，但它几乎从来不是硬件问题——是 batch size 的问题。课堂用独立子进程测峰值，而不是靠猜。

batch size32641282565121,024
超出基线的峰值内存（MB）83.691.3104.3129.7176.5275.5

基线（只导入 torch、不训练）是 306.5 MB。输入用最近邻上采样到 32×32，使激活体量达到真实视觉模型的量级。从 batch 32 到 1,024，增量从 83.6 涨到 275.5 MB（3.3 倍），因此峰值内存随 batch size 近似线性增长。batch = 1,024 时峰值 582.0 MB。macOS 上 ru_maxrss 单位是字节（Linux 是 KB），脚本内已用 /1024**2 处理。降低 batch 是唯一一个「不改变数学、只改变内存」的旋钮——所以它是第一件要做的事。

累积梯度的权重写法与「真 batch 128 单次前向」的逐位一致率
exact：w = 本微批样本数 / 组内样本数5 / 5 完全一致
naive：w = 1 / 累积步数3 / 5
none：不做缩放，梯度直接累加2 / 5
unscaled：不做缩放且不归约2 / 5

差异来自每个 epoch 最后一组的微批大小不等（n_train = 1258 不能被 64 × 累积步数整除）。只有按「组内实际样本占比」加权才逐位等价。配套一句诚实说明：Adam 对整体梯度缩放不敏感，所以 naive 也能大致收敛；若换 SGD，差异会显著放大。

OOM 的处置顺序 1 · 免费：先把 batch size 减半（不改变数学，只改变内存；副作用是梯度更吵）。2 · 免费：梯度累积——4×32 用对权重时与真 batch 128 逐项一致（5/5），代价是时间，不是精度。3 · 便宜：混合精度（torch.amp.autocast + GradScaler）；它改变数值，所以要重新确认指标没漂。4 · 有代价：梯度检查点或更小的输入，通常慢 20–30%；缩小输入会改变任务本身。5 · 最后：降模型规模，或者承认这个任务本机做不了——加显存是最后一条，不是第一条。本周实测这个模型永远不会 OOM，batch 1,024 的峰值也只有 582.0 MB。
绿色计算 同一份数据、同一个准确率、参数量差 9.07 倍——这是实测，不是口号。17,226 参数的全连接网拿 0.9785，1,898 参数的卷积网拿 0.9808。用更少的成本达成目标，先问一句：这个规模是必要的吗？在申请算力之前先把峰值量出来，因为大多数「我需要更大的机子」其实是「我把输入搞太大了」。

5. 思政与 AI 赋能

【思政】绿色计算

  • 算力是有限资源，要学会用更少的成本达成目标
  • 实测依据：17,226 参数拿 0.9785，1,898 参数拿 0.9808——多出来的 15,328 个参数在训练和推理里都要算、要传、要供电，却没有换到可测量的准确率
  • 先把峰值量出来（基线 306.5 MB；batch 1,024 时 582.0 MB），再决定要不要加硬件
  • 无效的优化要如实写：增强让干净精度掉了 3.0 个点，只报平移那 29 个点就是选择性汇报

【AI 赋能】显存优化，逐条实测

  • 第 1 步：向 AI 询问「怎么降低本周模型的显存占用」
  • 第 2 步：把每条建议在本机实测——降 batch、梯度累积、混合精度
  • 第 3 步：逐条标注有效或无效，并把代价（时间、数值、任务改变）写在旁边
  • 必须核查的典型 AI 回答：「一定要用混合精度」「梯度累积总能省显存」——后者只有在权重写对时才成立
  • 交付物：实测后留下的建议清单，每条附一行证据；同时列出没有生效的那几条
