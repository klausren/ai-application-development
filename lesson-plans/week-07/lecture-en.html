1. Learning Objectives

Knowledge

  • Understand convolution and pooling: explain local connectivity and weight sharing, and state the advantage a convolutional layer has over a fully connected layer and the price it pays for it
  • Read the parameter count of a network layer by layer, and reconcile 17,226 parameters against 1,898 on the same digits data
  • Apply the output-size formula out = (in + 2p - k)/s + 1 to nn.Conv2d and nn.MaxPool2d, and trace a feature map from 8×8 to 8×8, 4×4, 4×4, 2×2
  • Describe the classic CNN structures (the ideas of LeNet / AlexNet / VGG / ResNet) and the vision classification task they serve
  • State the mechanism and the cost of each Data Augmentation strategy, and read a five-architecture table as mean ± standard deviation over five seeds
  • Explain GPU memory use, gradient accumulation and mixed precision well enough to handle an out-of-memory (OOM) error in a lab

Skills

  • Build a CNN with nn.Conv2d, nn.MaxPool2d and nn.Linear, and assert every layer shape against the formula before training
  • Compute a receptive field by the recurrence rf = rf + (k - 1) × jump and decide how many layers a task actually needs
  • Train a CNN for image classification, record the training curves and the confusion matrix, and write an error analysis that names the worst class pair
  • Diagnose OOM in the right order: halve the batch, then buy the effective batch back with gradient accumulation, before touching the hardware
  • Ask an AI for GPU-memory optimisations, test each suggestion on the machine, and label which ones worked and which ones did not
Attitudes · Civic Education Green computing: compute is a finite resource, and the professional habit is to reach the goal at a lower cost. This week the class measures it rather than asserting it — 17,226 parameters reach 0.9785 and 1,898 parameters reach 0.9808, a 9.07x parameter saving for a test-accuracy difference of 0.0023 that is smaller than one standard deviation (0.0084). The extra 15,328 parameters still have to be computed, moved and powered, in training and at inference. Before scaling a model up, ask whether the size was necessary.

4.1 Part 1 · Convolution: from dense layers to weight sharing (p3-p7, KT13)

A convolution is one sliding dot product: take a patch, multiply element-wise, and sum, repeated at every position. Three properties follow — local connectivity, weight sharing, and a parameter count that does not grow with image width. The class first writes the naive conv2d_naive and then asserts it against nn.Conv2d rather than trusting it (p5).

LayerShapeParamsRunning
Input1×8×800
Dense 64→12864→1288,3208,320
Dense 128→64128→648,25616,576
Dense 64→1064→1065017,226
Conv 1→8, 3×38×8×83·3·1·8 + 8 = 8080
Conv 8→16, 3×316×4×43·3·8·16 + 16 = 1,1681,248
Linear 64→1064→1064·10 + 10 = 6501,898

Top block is the dense control; bottom block is two conv layers plus a linear head. 17,226 → 1,898 is 9.07x fewer parameters, and the two test accuracies are 0.9785 and 0.9808 — a 0.0023 gap, smaller than one standard deviation (0.0084). Write no significant difference was observed, not "the CNN is better". The real thing the CNN buys is translation tolerance: shift the test images by one column and the dense net is at 0.5089 while the CNN is at 0.6504.

What it costs Locality is an assumption, not a fact. If the useful pattern is global (say, the overall brightness distribution), the assumption is wrong and the conv net is worse than dense. The receptive field is finite: the last conv here already sees the whole 8×8, so extra depth adds nothing on this data. Pooling throws away position, and some tasks need position.

4.2 Part 2 · The arithmetic of shapes (p8-p12, KT13)

The shape chain is 8×8 → conv+P → 8×8 → pool → 4×4 → conv+P → 4×4 → pool → 2×2 → flatten 64 → FC 10. The receptive field recurrence gives 3 → 4 → 8 → 10. The row that matters is Conv 2: receptive field 8, exactly the whole image. On 8×8 data the second conv already sees everything, so no amount of extra depth adds translation invariance — that is the data being small, not the model being weak.

The pooling choice is worth 4.1 points Apart from the pooling function the two architectures are byte-for-byte identical: same channels, same kernels, same learning rate and epochs. Average pooling is 4.1 points below max pooling (0.9400 against 0.9808), which is five times the standard deviation — not noise. Max pooling keeps the strongest response, and for handwritten digits the discriminative information is exactly where the stroke is densest. Choosing a pooling function is choosing what to keep.

The augmentation ledger: +29 bought, −3 paid At dx = -1 the CNN is 0.6481 and the augmented CNN is 0.9415 — +29 points of robustness. At dx = 0 the CNN is 0.9808 and the augmented CNN is 0.9504 — −3 points of clean accuracy, and the augmented curve is the lowest of the three at dx = 0. Augmentation did not raise the ceiling; it flattened the curve. Its training accuracy no longer runs to 1.000 (0.9292 at epoch 115), so overfitting is held back. Whether to buy depends on one product question: will the model meet translated inputs? If users photograph the thing, yes; if inputs are already cropped and aligned, you are buying nothing.

4.4 Part 4 · Where it fails (p18-p21)

"98%" is not a result, it is an unfinished sentence. The confusion matrix is the table that turns it into "which two classes it hesitates between". Row = true label, column = prediction; diagonal is correct, off-diagonal is wrong.

Total 1,350 test predictions over 5 seeds; correct 1,324 (0.9807); off-diagonal errors 26. 12 of those 26 involve the digit 8 (46.2% of all errors). The worst class pair is 8 → 1, three times. Digit 0 is perfect (135/135); digit 8 is worst (124/130, recall 0.9538).

Draw the misclassified digit itself Two real seed-42 test samples: true 8, predicted 7, confidence 0.9829 — the lower loop is broken and only the upper stroke survives, so it reads like a 7; true-class probability 0.0144. And true 6, predicted 8, confidence 0.8852 — this 6 has a closed lower loop, which a 6 should not; true-class probability 0.0271. This is error analysis: not "the model is not good enough" but "it calls 8 on a 6 whose lower loop closes", which is fixable. The complete deliverable has five items: the printed confusion matrix, the worst class pair with its count, at least 3 concrete cases with probabilities, a testable hypothesis per case, and the next step with its success criterion.

4.5 Part 5 · Memory and green computing (p22-p26, KT14)

Out-of-memory is the most common blocker in this week's lab, and it is almost never a hardware problem — it is a batch-size problem. The class measures the peak of an independent subprocess instead of guessing.

batch size32641282565121,024
Peak memory over baseline (MB)83.691.3104.3129.7176.5275.5

Baseline (torch imported, nothing running) is 306.5 MB. The input is nearest-neighbour upsampled to 32×32 to give the activation volume the order of a real vision model. From batch 32 to 1,024 the increment grows 83.6 → 275.5 MB (3.3x), so peak memory grows approximately linearly with batch size. At batch 1,024 the peak is 582.0 MB. On macOS the ru_maxrss unit is bytes, not kilobytes; the script already divides by 1024². Dropping the batch is the only knob that changes memory without changing the maths — so it is the first thing to try.

Weighting of the accumulated gradientBit-for-bit match with the true batch-128 run
exact: w = (size of this micro-batch) / (group size)5 / 5 seeds identical
naive: w = 1 / accumulation steps3 / 5
none: no scaling, gradients added directly2 / 5
unscaled: no scaling and no reduction2 / 5

The mismatch comes from the fact that the last group of each epoch has an unequal micro-batch size (n_train = 1258 is not divisible by 64 × accumulation). Only weighting each micro-batch by its real share of the group is bit-for-bit equivalent. An honest note alongside it: Adam is largely insensitive to a uniform scaling of the gradient, so naive still roughly converges; with SGD the difference would be far larger.

What to do when you run out of memory — in this order 1. Free: halve the batch size (changes memory, not maths; side effect is noisier gradients). 2. Free: gradient accumulation — 4×32 with the share-of-group weighting reproduces true batch 128 exactly (5/5); you pay in time, not accuracy. 3. Cheap: mixed precision (torch.amp.autocast + GradScaler); it changes the numerics, so re-confirm the metric. 4. Costs: gradient checkpointing or a smaller input, typically 20-30% slower; shrinking the input changes the task itself. 5. Last: shrink the model, or admit the task does not fit — buying a GPU is last, not first. Measured this week, this model never OOMs; the peak at batch 1,024 is only 582.0 MB.
Green computing Same data, same accuracy, 9.07x fewer parameters — this is measured, not a slogan. The 17,226-parameter dense net reaches 0.9785 and the 1,898-parameter CNN reaches 0.9808. Reaching the goal with less starts with one question: was this size necessary? Measure the peak before requesting compute, because most "I need a bigger machine" is really "I made the input too big".

5. Civic Education & AI Empowerment

[Civic Education] Green computing

  • Compute is a finite resource; reach the goal at a lower cost
  • The measured basis: 17,226 parameters at 0.9785 against 1,898 parameters at 0.9808 — the 15,328 extra parameters are computed, moved and powered in training and at inference for no measured accuracy gain
  • Measure the peak (306.5 MB baseline; 582.0 MB at batch 1,024) before asking for hardware
  • Report the optimisation that did not work, not only the one that did — augmentation cost 3 points of clean accuracy

[AI Empowerment] Memory optimisation, tested

  • Step 1: ask the AI for ways to reduce GPU memory for this week's model
  • Step 2: test each suggestion on the machine — halve the batch, gradient accumulation, mixed precision
  • Step 3: label each suggestion valid or invalid, with the measured evidence and its cost (time, numerics, or task change) beside it
  • Typical AI answers that must be checked: "always use mixed precision" and "gradient accumulation always saves memory" — the second is only true when the weighting is right
  • Deliverable: the shortened list of suggestions that survived measurement, each with one line of evidence, plus the ones that did not work
