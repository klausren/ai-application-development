1. Learning Objectives

Knowledge

  • State the four moves of one parameter update and why the order matters
  • Explain why .grad must be zeroed and what a loss curve looks like when it is not
  • Explain what a baseline loss proves before any training happens
  • Distinguish the generating truth, the closed-form least-squares solution, and the trained solution
  • Explain why shapes must be checked even when no error is raised

Skills

  • Generate a seeded synthetic dataset and compute the baseline MSE at w = b = 0
  • Train linear regression with tensors and autograd — no nn.Module, no torch.optim
  • Produce loss curves for three learning rates on one figure and read each one correctly
  • Compute the closed-form OLS solution and report relative errors against it
  • Log shape failures with verbatim error text and create one AI collaboration trace
  • Push the M2 capstone milestone: topic confirmed, DATA.md v0, data loads
Attitudes Keep the failures in the record — shape errors and debugging are evidence of skill, not marks to hide. A report that contains only the successful run says nothing about whether you did the work. Never fabricate output and never prettify a curve; small differences across devices are normal and must simply be stated.

4. Key Activity Design

Activity 1 · Print the Shapes Before the Loss (Lab A, p23)

Before any training, every student must print X.shape, y.shape, w.shape and b.shape and assert that X @ w + b has shape (100, 1). Students who typed torch.randn(100) for y see the mismatch here instead of thirty minutes later — and it would never have raised an error.

Activity 2 · The Forbidden Libraries (Lab B, p24)

Halfway through, students run grep -nE "nn\.|optim\." lab1_linear_regression.py on their own file. Any hit is a violation for this lab. The purpose is not pedantry: writing the update line yourself is the only way to feel what an optimiser does for you — and what it does that you did not ask for.

Activity 3 · Predict the Curve Before You Run (Lab C, p19)

Each student writes down, for lr = 0.001, 0.1 and 1.0, whether they expect convergence, stalling, or divergence. Comparing predictions with the plotted result turns a mechanical exercise into a calibration exercise — and makes the "lr too large" story personal before it is told.

Activity 4 · Which Error Did You Just Compute? (Lab D, p20)

Before filling the table, ask the class to argue about the denominator: relative error against the truth, against OLS, or against the previous step? All three are defensible, and the only wrong answer is leaving it unstated. This is the difference between a number and a result.

Activity 5 · Reproduce Someone Else's Curve (Lab E, p25)

Students swap repositories with a neighbour and try to reproduce the other person's loss curve from the README alone. A missing seed, an unpinned version, or a hardcoded path shows up immediately. Then each student writes down what their own README was missing.
