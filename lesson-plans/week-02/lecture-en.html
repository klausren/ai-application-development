PyTorch Fundamentals: Tensors and Autograd

1. Learning Objectives

Knowledge

  • Name the five tensor attributes — shape, dtype, device, requires_grad, grad — and say what breaks when each is wrong
  • State the broadcasting rules and explain why they guarantee legality but not intent
  • Explain what a computational graph is, when it is built, and when it is released
  • State the two rules of autograd: only leaves receive .grad, and .grad accumulates
  • Explain why a fixed seed is what turns one good run into a repeatable result

Skills

  • Report shape, dtype and device for any tensor on sight, and predict the shape of a result before running it
  • Choose correctly between view, reshape, unsqueeze, squeeze and permute for a given shape problem
  • Reproduce a shape or broadcast failure deliberately, read the message, and fix it
  • Implement one parameter update with backward(), a no_grad() update and a gradient reset
  • Write a training loop that learns y = 3x + 2 using tensors and autograd alone
Attitudes This week's professionalism theme is rigour: a conclusion requires reproducibility. Randomness is part of training, so it must be pinned down; a shape error that raises is a good error, and a wrong answer that does not raise is the one that costs you a week. Read the message before reaching for a fix, and record the failures as carefully as the successes.

4. Key Activity Design

Activity 1 · Report Four Things (L1–L2, p4)

Show a tensor on the projector — torch.randn(4, 3), then torch.arange(6), then torch.randn(4,3).to("cuda") — and require four answers before any operation: shape, dtype, device, needs-grad. The arange case is the trap: int64 cannot require grad, and dividing by it truncates.

Activity 2 · Read the Error Aloud (L3, p9–p10)

Nobody may fix anything for the first two minutes. Run torch.randn(3,1) + torch.randn(3) — which does not raise — and then torch.randn(4,3) + torch.randn(4,2) — which does. The class must explain why the silent one is the more dangerous of the two. Seeing one error clearly beats memorising ten rules.

Activity 3 · Why Is My Gradient 14? (L4, p14)

Run the minimal autograd example, then comment out x.grad = None and run again. The printed gradient goes from 8 to 14. Ask what "14" would have meant inside a training loop — and connect it directly to the oscillating loss curve that appears later on p19.

Activity 4 · Five Moves, One Order (L4–L5, p15–p16)

Put the five steps on the board in a deliberately wrong order — forward, backward, zero, update, loss — and have the class reorder them. Then ask what happens if the update is written outside with torch.no_grad():. Answer: the update itself enters the graph, and training gets slower every step.

Activity 5 · Read Three Curves (L5, p19)

Show the three-curve chart before explaining it. Each student writes one sentence per curve: monotone descent, oscillation, or divergence. Only afterwards are the causes named (zeroing, accumulation, learning rate). The point: a loss curve is a diagnostic before it is a result.
